## 📸 快速開始 - 截圖捕獲

### 方法 1: PowerShell 自動化腳本（推薦）

```powershell
# 手動模式 - 逐步捕獲（最詳細）
.\tools\capture-emulator-screenshots.ps1

# 自動模式 - 快速捕獲（基本場景）
.\tools\capture-emulator-screenshots.ps1 -AutoTest

# 指定場景
.\tools\capture-emulator-screenshots.ps1 -Scenario "composition"
```

**輸出**:
- 📁 `screenshots/emulator-testing/session_[timestamp]/`
- 📊 `index.html` - 互動式 HTML 報告
- 📝 `VISUAL_COMPARISON.md` - 對比文檔

### 方法 2: 手動 ADB 命令

```bash
# 捕獲單張截圖
adb exec-out screencap -p > screenshot.png

# 捕獲並自動命名
$timestamp = Get-Date -Format "yyyyMMdd_HHmmss"
adb exec-out screencap -p > "screenshot_$timestamp.png"
```

### 方法 3: Android Studio Device File Explorer

1. 開啟 Android Studio
2. View → Tool Windows → Device File Explorer
3. 導航到 `/sdcard/Pictures/Screenshots`
4. 右鍵 → Save As

## 🔍 視覺驗證清單

### 📐 構圖分析功能

#### 1.1 無主體場景
**測試步驟**:
1. 確保畫面中無人臉
2. 捕獲截圖

**預期結果**:
- [ ] 顯示「未偵測到主體」或類似提示
- [ ] 格線正常顯示（如果已啟用）
- [ ] 無構圖引導框
- [ ] UI 元素完整

**參考截圖**: 無（需自行捕獲）

---

#### 1.2 良好構圖 - 單一人臉
**測試步驟**:
1. 將人臉置於上三分線附近
2. 確保頭部空間適當（5-15%）
3. 主體居中
4. 捕獲截圖

**預期結果**:
- [ ] **綠色構圖引導框** 顯示在人臉周圍
- [ ] 引導框位置：眼睛在框的上三分處
- [ ] 引導框大小：適當包含整個頭部
- [ ] 提示訊息：「構圖良好」或無提示
- [ ] 無方向指示器（或指示器為綠色/靜止狀態）

**參考截圖**:
```
others/v2.4.6-Testing/optimized/後鏡頭Screenshot_20251213-170034.jpg
```

**對比重點**:
- 引導框顏色應為綠色
- 引導框位置應接近實機位置
- 文字提示應為中文

---

#### 1.3 需調整構圖 - 眼睛位置過低
**測試步驟**:
1. 將人臉置於畫面中心或偏下
2. 捕獲截圖

**預期結果**:
- [ ] **黃色構圖引導框** 顯示
- [ ] 提示訊息：「請向上移動相機」或類似
- [ ] **向上箭頭** 方向指示器
- [ ] 引導框應移至理想位置（預覽效果）

**視覺檢查**:
```
┌─────────────────┐
│                 │  ← 理想位置（上三分線）
│   [黃色框]      │
│                 │
│     👤          │  ← 當前位置（過低）
│                 │
│      ⬆️         │  ← 方向指示器
└─────────────────┘
```

---

#### 1.4 需調整構圖 - 眼睛位置過高
**測試步驟**:
1. 將人臉置於畫面上方
2. 捕獲截圖

**預期結果**:
- [ ] **黃色構圖引導框**
- [ ] 提示訊息：「請向下移動相機」
- [ ] **向下箭頭** 方向指示器

---

#### 1.5 需調整構圖 - 頭部空間不足
**測試步驟**:
1. 將人臉貼近畫面上緣（< 5% 空間）
2. 捕獲截圖

**預期結果**:
- [ ] **黃色構圖引導框**
- [ ] 提示訊息：「頭部空間過少，請向下移動相機」
- [ ] **向下箭頭** 方向指示器

**參考截圖**:
```
others/v2.4.6-Testing/optimized/後鏡頭Screenshot_20251213-170145.jpg
```
（檢查是否有頭部空間警告）

---

#### 1.6 多人臉場景
**測試步驟**:
1. 確保畫面中有 2+ 人臉
2. 捕獲截圖

**預期結果**:
- [ ] 所有人臉皆有偵測框（淡色）
- [ ] 最大人臉有主要構圖引導框
- [ ] 多主體提示（如果實現）
- [ ] 構圖分析針對主要人臉

### 🎨 Overlay 元素

#### 2.1 三分法格線
**測試步驟**:
1. 開啟格線顯示
2. 捕獲截圖

**預期結果**:
- [ ] 兩條垂直線（33%, 67%）
- [ ] 兩條水平線（33%, 67%）
- [ ] 線條顏色：白色半透明或設定的顏色
- [ ] 線條粗細：1-2px
- [ ] 四個交點清晰可見

**視覺檢查**:
```
┌─────┬─────┬─────┐
│     │     │     │  ← 上三分線
├─────┼─────┼─────┤
│     │     │     │
├─────┼─────┼─────┤
│     │     │     │  ← 下三分線
└─────┴─────┴─────┘
  ↑33% ↑67%
```

---

#### 2.2 構圖提示文字
**測試步驟**:
1. 創造需要調整的構圖
2. 確認提示顯示
3. 捕獲截圖

**預期結果**:
- [ ] 提示文字為**繁體中文**
- [ ] 文字大小：易讀（建議 14-16sp）
- [ ] 文字顏色：白色或高對比色
- [ ] 背景：半透明黑色確保可讀性
- [ ] 位置：不遮擋主體（通常在頂部或底部）
- [ ] 提示內容專業且清晰

**預期提示範例**:
- ✅ "請向上移動相機，將眼睛對齊上三分線"
- ✅ "頭部空間過少，請向下移動相機"
- ✅ "主體偏左，請向右移動相機"
- ❌ "Move up" （不應出現英文）
- ❌ "調整位置" （過於模糊）

---

#### 2.3 方向指示器
**測試步驟**:
1. 創造偏離構圖
2. 觀察方向指示器
3. 捕獲截圖

**預期結果**:
- [ ] 箭頭方向正確（上/下/左/右）
- [ ] 箭頭顏色：黃色或警告色
- [ ] 箭頭大小：清晰可見但不突兀
- [ ] 箭頭位置：接近需調整的區域
- [ ] 箭頭動畫：平滑（如果有動畫）

**方向對應**:
- 主體過低 → 向上箭頭 ⬆️
- 主體過高 → 向下箭頭 ⬇️
- 主體偏左 → 向右箭頭 ➡️
- 主體偏右 → 向左箭頭 ⬅️

---

#### 2.4 水平儀指示器
**測試步驟**:
1. 傾斜模擬器（或使用感測器模擬）
2. 捕獲截圖

**預期結果**:
- [ ] 水平線顯示
- [ ] 傾斜角度數值（例如：5°）
- [ ] 顏色變化：
  - 綠色 = 水平（< 2°）
  - 黃色 = 輕微傾斜（2-5°）
  - 紅色 = 嚴重傾斜（> 5°）
- [ ] 位置：通常在頂部中央或底部

**預期結果**:
- [ ] **預覽畫面已鏡像**（符合自拍習慣）
- [ ] 人臉偵測正常運作
- [ ] 偵測框位置正確（鏡像後）
- [ ] 構圖引導框位置正確（座標已轉換）

- [ ] 所有 Overlay 元素正常顯示

others/v2.4.6-Testing/optimized/前鏡頭_20251213-170234.jpg

**關鍵檢查點**:

---

#### 3.2 後鏡頭模式
**測試步驟**:
1. 切換到後鏡頭
2. 捕獲截圖

**預期結果**:
- [ ] 預覽畫面**非鏡像**（真實世界視角）
- [ ] 人臉偵測正常
- [ ] 構圖分析正確
- [ ] 切換流暢（< 1 秒）
- [ ] 無閃爍或黑屏

---

#### 3.3 前後切換穩定性
**測試步驟**:
1. 快速切換前後鏡頭 5 次
2. 每次切換後捕獲截圖

**預期結果**:
- [ ] 無崩潰
- [ ] 無 ANR（Application Not Responding）
- [ ] Overlay 狀態正確保留
- [ ] 偵測框不會殘留
- [ ] 記憶體使用穩定

## 📋 測試流程

### 完整視覺驗證流程（30 分鐘）

1. **準備** (5 分鐘)
   ```bash
   # 啟動模擬器
   emulator -avd <emulator_name>

   # 安裝應用
   ./gradlew.bat installEmulatorDebug
   ```

2. **執行截圖腳本** (15 分鐘)
   ```powershell
   .\tools\capture-emulator-screenshots.ps1
   ```
   - 按照提示逐步操作
   - 每個場景仔細檢查
   - 捕獲所有要求的截圖

3. **查看 HTML 報告** (5 分鐘)
   - 自動開啟 `index.html`
   - 瀏覽所有截圖
   - 確認分類正確

4. **對比實機截圖** (5 分鐘)
   - 開啟 `VISUAL_COMPARISON.md`
   - 逐項對比檢查清單
   - 標記差異項目

5. **記錄問題** (5 分鐘)
   - 在 `VISUAL_COMPARISON.md` 記錄發現的問題
   - 對嚴重問題添加優先級標記
   - 必要時附加額外截圖
