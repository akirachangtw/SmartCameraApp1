### 3. DetectionOverlay.kt (v1.0.0 → v1.1.0)

**核心修復：完全重寫 `transformRect()` 函數**

#### 原始版本的問題：
```kotlin
// 舊版：只做簡單的縮放，沒有旋轉處理
private fun transformRect(
    mlKitRect: RectF,
    imageSize: Size,
    previewSize: Size
): Rect {
    val scaleX = previewSize.width / imageSize.width
    val scaleY = previewSize.height / imageSize.height

    return Rect(
        left = mlKitRect.left * scaleX,
        top = mlKitRect.top * scaleY,
        right = mlKitRect.right * scaleX,
        bottom = mlKitRect.bottom * scaleY
    )
}
```

#### 新版本的完整實作：

**步驟 1：判斷有效影像尺寸（處理旋轉維度交換）**
```kotlin
val needsSwap = rotationDegrees == 90 || rotationDegrees == 270
val effectiveImageWidth = if (needsSwap) imageSize.height else imageSize.width
val effectiveImageHeight = if (needsSwap) imageSize.width else imageSize.height
```

**步驟 2：計算 FIT_CENTER 縮放比例（保持 aspect ratio）**
```kotlin
val imageAspectRatio = effectiveImageWidth / effectiveImageHeight
val previewAspectRatio = previewSize.width / previewSize.height

val scale = if (imageAspectRatio > previewAspectRatio) {
    // 影像較寬，以寬度為限制
    previewSize.width / effectiveImageWidth
} else {
    // 影像較高，以高度為限制
    previewSize.height / effectiveImageHeight
}
```

**步驟 3：計算置中偏移（用於 letterboxing/pillarboxing）**
```kotlin
val scaledWidth = effectiveImageWidth * scale
val scaledHeight = effectiveImageHeight * scale
val offsetX = (previewSize.width - scaledWidth) / 2f
val offsetY = (previewSize.height - scaledHeight) / 2f
```

**步驟 4：根據旋轉角度轉換座標**

**0° (無旋轉)：**
```kotlin
Rect(
    left = mlKitRect.left * scale + offsetX,
    top = mlKitRect.top * scale + offsetY,
    right = mlKitRect.right * scale + offsetX,
    bottom = mlKitRect.bottom * scale + offsetY
)
```

**90° (順時針旋轉)：**
```kotlin
// 轉換公式：(x, y) → (height - y, x)
Rect(
    left = (imageSize.width - mlKitRect.bottom) * scale + offsetX,
    top = mlKitRect.left * scale + offsetY,
    right = (imageSize.width - mlKitRect.top) * scale + offsetX,
    bottom = mlKitRect.right * scale + offsetY
)
```

**180° (翻轉)：**
```kotlin
// 轉換公式：(x, y) → (width - x, height - y)
Rect(
    left = (imageSize.width - mlKitRect.right) * scale + offsetX,
    top = (imageSize.height - mlKitRect.bottom) * scale + offsetY,
    right = (imageSize.width - mlKitRect.left) * scale + offsetX,
    bottom = (imageSize.height - mlKitRect.top) * scale + offsetY
)
```

**270° (逆時針旋轉)：**
```kotlin
// 轉換公式：(x, y) → (y, width - x)
Rect(
    left = mlKitRect.top * scale + offsetX,
    top = (imageSize.height - mlKitRect.right) * scale + offsetY,
    right = mlKitRect.bottom * scale + offsetX,
    bottom = (imageSize.height - mlKitRect.left) * scale + offsetY
)
```

**除錯日誌**：
```kotlin
Log.d(

    "Transform: MLKit[${mlKitRect.left}, ${mlKitRect.top}, ${mlKitRect.right}, ${mlKitRect.bottom}] " +
```

## 技術細節

### 座標轉換演算法

#### 問題描述：
ML Kit 提供的邊界框座標是基於**分析影像**的座標系統，而這個影像可能：
1. 已經被旋轉（0°, 90°, 180°, 270°）
2. 尺寸與螢幕預覽不同（例如 480x640 vs 1080x2400）
3. aspect ratio 與預覽不同

#### 解決方案架構：

```
ML Kit 影像座標 (480x640, 90° 旋轉)
        ↓
[步驟 1] 判斷有效尺寸 (需要交換？)
        ↓
[步驟 2] 計算 FIT_CENTER 縮放比例
        ↓
[步驟 3] 計算置中偏移量
        ↓
[步驟 4] 根據旋轉角度轉換座標
        ↓
螢幕預覽座標 (1080x2400, 0° 顯示)
```

#### 數學公式：

**有效尺寸計算**：
```
if (rotation == 90° || rotation == 270°):
    effectiveWidth = imageHeight
    effectiveHeight = imageWidth
else:
    effectiveWidth = imageWidth
    effectiveHeight = imageHeight
```

**縮放比例計算**：
```
imageAspectRatio = effectiveWidth / effectiveHeight
previewAspectRatio = previewWidth / previewHeight

if (imageAspectRatio > previewAspectRatio):
    scale = previewWidth / effectiveWidth  (寬度為限制)
else:
    scale = previewHeight / effectiveHeight (高度為限制)
```

**偏移量計算**：
```
scaledWidth = effectiveWidth × scale
scaledHeight = effectiveHeight × scale
offsetX = (previewWidth - scaledWidth) / 2
offsetY = (previewHeight - scaledHeight) / 2
```

**旋轉變換矩陣**：

| 旋轉角度 | 轉換公式 | 說明 |
|---------|---------|------|
| 0° | (x, y) → (x, y) | 無旋轉，直接縮放 |
| 90° | (x, y) → (h - y, x) | 順時針 90° |
| 180° | (x, y) → (w - x, h - y) | 翻轉 180° |
| 270° | (x, y) → (y, w - x) | 逆時針 90° |

其中 w = imageWidth, h = imageHeight

## 已知限制

### 環境限制
1. **極暗環境**：偵測可能失敗（視覺 AI 的正常限制）
2. **強烈背光**：可能造成間歇性偵測失敗
3. **快速移動**：非常快速的移動可能造成追蹤中斷

### 技術限制
1. **信心度波動**：邊界條件（昏暗、進出畫面）可能閃爍
2. **最小人臉大小**：< 15% 畫面的人臉不會被偵測
3. **旋轉角度**：僅支援 0°, 90°, 180°, 270° 四個標準角度
