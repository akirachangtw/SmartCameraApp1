### 根因分析（已確認）

**觀測 Logcat**（Sony 16:9 模式）：
```
D/RenderScriptYuvConverter: NV21 fast path: chromaHeight=360, chromaWidth=640, vRowStride=1280
```
- `vRowStride=1280` → ImageAnalysis 實際收到 **1280×720** NV21 buffer（非我們期望的 640×360）
- `chromaHeight=360 = 720/2`, `chromaWidth=640 = 1280/2` → 確認是 1280×720 NV21 格式

**原因**：Sony HQ616R2713 HAL 在 16:9 模式下，ImageAnalysis stream 的最小可用解析度是 **1280×720**（沒有提供 640×360）。

現有 `analysisSelector`（commit `c1646fd`）的問題：
```kotlin
// 同時設定 AspectRatioStrategy(16:9) + ResolutionStrategy(640×480)
// CameraX 行為：AspectRatioStrategy 優先 → 先篩出所有 16:9 解析度
// Sony 的 16:9 ImageAnalysis 最小 = 1280×720（沒有 640×360 可用）
// ResolutionStrategy(640×480, CLOSEST_LOWER_THEN_HIGHER) → no lower found → fallback to 1280×720
```
→ `AspectRatioStrategy(16:9)` 篩選後，Sony 只剩 1280×720，`ResolutionStrategy` cap 無效。

**4:3 成功原因**：Sony 有原生 640×480 (4:3) ImageAnalysis stream → cap 生效 → FPS > 20。

### 補充：THROTTLE_INTERVAL_MS（SmartCameraAnalyzer.kt line 93）
```kotlin
private val THROTTLE_INTERVAL_MS = if (Build.MODEL == "Pixel 9a") 500L else 100L
```
Sony = 100ms throttle。若 1280×720 ML Kit 處理時間 > 100ms，分析 FPS 就 < 10。
即使處理時間 = 60ms，相機 session 整體 FPS（preview）也可能因 HAL 處理 1280×720 ImageAnalysis 而下降。

## 4. 最新交付成果 (Latest Deliverable)

### 4A. 目前 `analysisSelector` 程式碼（LiveCameraSource.kt ~line 1049-1069）

```kotlin
// v2.12.0: Dedicated analysisSelector for ImageAnalysis — capped at ≤640×480
// Rationale: commonSelector lets HAL pick any resolution (e.g. Sony selects 1920×1080
//   for 16:9 → FPS drops below 20). ML Kit analysis does not need high resolution.
//   Separating selectors: Preview+Capture keep full quality; Analysis stays small.
val analysisSelector = androidx.camera.core.resolutionselector.ResolutionSelector.Builder()
    .setAspectRatioStrategy(
        androidx.camera.core.resolutionselector.AspectRatioStrategy(
            targetAspectRatio,
            androidx.camera.core.resolutionselector.AspectRatioStrategy.FALLBACK_RULE_AUTO
        )
    )
    .setResolutionStrategy(
        androidx.camera.core.resolutionselector.ResolutionStrategy(
            android.util.Size(640, 480),
            androidx.camera.core.resolutionselector.ResolutionStrategy.FALLBACK_RULE_CLOSEST_LOWER_THEN_HIGHER
        )
    )
    .build()
    .also {
        Log.i(TAG, "[v2.12.0] analysisSelector: ${currentAspectRatioMode.displayName} → capped ≤640×480")
    }
```

**問題所在**：有 `setAspectRatioStrategy(16:9)` → Sony 只看 16:9 resolutions → minimum = 1280×720 → cap 失效。

## 5. 下一步行動 (Next Steps)

### 目標：修復 Sony 16:9 FPS < 20（v2.12.0-02）

**修改檔案**：唯一需要改 `LiveCameraSource.kt`

**修法**：移除 `analysisSelector` 的 `setAspectRatioStrategy()` 約束，只保留 `ResolutionStrategy`：

```kotlin
// v2.12.0-02: Remove AspectRatioStrategy from analysisSelector
// Root cause: Sony HAL has no 16:9 ImageAnalysis resolution < 1280×720.
//   AspectRatioStrategy(16:9) filters to 16:9-only resolutions → Sony minimum = 1280×720 → cap fails.
// Fix: Remove AR constraint. ResolutionStrategy(640×480) alone → HAL picks 640×480 (4:3 physical)
//   for both 4:3 and 16:9 modes. ViewPort cropRect handles the 16:9 crop region.
// Impact: ML Kit analyzes 640×480 frame in 16:9 mode (slightly larger FOV than cropRect).
//   imageProxy.width=640, imageProxy.height=480 for all modes → coordinate mapping uses these.
val analysisSelector = androidx.camera.core.resolutionselector.ResolutionSelector.Builder()
    .setResolutionStrategy(
        androidx.camera.core.resolutionselector.ResolutionStrategy(
            android.util.Size(640, 480),
            androidx.camera.core.resolutionselector.ResolutionStrategy.FALLBACK_RULE_CLOSEST_LOWER_THEN_HIGHER
        )
    )
    .build()
    .also {
        Log.i(TAG, "[v2.12.0] analysisSelector: AR-free, capped ≤640×480 (both modes)")
    }
```

**修改位置**：`LiveCameraSource.kt` 的 `analysisSelector` builder block（約 line 1053-1069），刪除 `.setAspectRatioStrategy(...)` 那 7 行，只保留 `.setResolutionStrategy(...)` 部分。

### ⚠️ 座標系風險說明

移除 `AspectRatioStrategy` 後，16:9 模式的 ImageAnalysis 物理解析度 = 640×480（4:3）。
- `imageProxy.cropRect` 會反映 ViewPort 的 16:9 裁切區域（e.g. `Rect(0, 60, 640, 420)`）
- 但 `DetectionResult.imageWidth = 640`, `imageHeight = 480`（全尺寸，非 cropRect）
- ML Kit 分析整個 640×480（含上下各 60px letterbox）
- **如果** 人臉剛好在 letterbox 區域，座標會有輕微偏移

**預期影響**：低。ViewPort FIT + WYSIWYG 架構下，letterbox 區域為黑邊，不太可能有有效人臉。實機測試確認即可。
