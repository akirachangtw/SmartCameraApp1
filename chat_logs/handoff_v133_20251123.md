## 三、關鍵技術理解

### 3.1 ML Kit 座標系統

**重要概念**:
```
InputImage.fromMediaImage(mediaImage, rotationDegrees)
    ↓
內部旋轉影像到正確方向
    ↓
inputImage.width/height = 旋轉後的尺寸 (IMPORTANT!)
    ↓
ML Kit 偵測
    ↓
bounding box 座標已在旋轉後的空間中
```

**關鍵理解**:
1. `InputImage` 內部已處理旋轉
2. `inputImage.width` 和 `inputImage.height` 是**旋轉後的尺寸**
3. 返回的邊界框座標也在**旋轉後的空間**中
4. **不需要再次旋轉或交換維度！**

### 3.2 座標轉換公式

**正確的轉換步驟** (v1.3.3):
```
1. 直接使用 imageSize (已旋轉後的尺寸)
2. 計算 FIT_CENTER 縮放因子
3. 計算居中偏移
4. 應用 scale + offset
5. 箝制座標到螢幕範圍
```

**錯誤的做法** (v1.3.1, v1.3.2):
- ❌ 手動應用旋轉矩陣 (v1.3.1)
- ❌ 根據旋轉角度交換維度 (v1.3.2)

### 3.3 為何 v1.3.2 直向模式問題更嚴重

**直向 (90°)**:
```
ML Kit: 640x480 (橫向影像)
v1.3.2 交換: 480x640 (直向)
    ↓
錯誤的長寬比 (0.75 vs 正確的 1.33)
    ↓
使用寬度縮放 (應該用高度)
    ↓
過大的 offsetY (482px)
    ↓
座標 y > 1080px → 框超出螢幕下方
```

**橫向 (0°)**:
```
ML Kit: 640x480
v1.3.2 未交換: 640x480
    ↓
正確的長寬比
    ↓
offsetY = 795px (仍偏大，但可接受)
    ↓
部分框可見
```
