## 1. 專案背景 (Context)

### 核心問題
SmartCameraApp 在 Android 16 裝置（特別是 Pixel 9a）上啟動時會顯示 **PageSizeMismatchDialog** 警告：
> "This app uses native libraries that are not aligned to 16KB page boundaries"

### Google Play 政策要求
- **生效日期**: 2025/11/01
- **要求**: 所有指定 Android 15+ (API 35+) 的應用程式必須支援 16KB 頁面大小
- **定義**: 應用程式能在 16KB 裝置上安裝、執行，無崩潰或重大功能異常

### 專案目標
消除 PageSizeMismatchDialog 警告，確保 Google Play 合規。

### 🚨 關鍵發現：雙層對齊問題 (2026-01-27)

#### 發現來源
使用者提供的 Pixel 9a 警告截圖 (`docs/test_results/v2.9.6-Phase2.5/16kb-warning2.JPG`) 顯示**全部 8 個函式庫**，而非僅 2 個 ML Kit 函式庫。

#### 根本原因
**Phase 2.5 修復了錯誤的層級**：

##### Layer 1: ZIP Entry Offset Alignment (APK 結構) ← Android 16 檢查這個
```
APK (ZIP Archive):
├─ Entry: lib/arm64-v8a/library.so
│  └─ Offset in ZIP: Must be multiple of 16384
```
**狀態**: ❌ **0/8 函式庫對齊** (使用 `zipinfo -v` 驗證)

##### Layer 2: ELF LOAD Segment Alignment (二進位結構) ← Phase 2.5 修復這個
```
library.so (ELF Binary):
├─ LOAD segment: p_align = 0x4000 (16KB)
```
**狀態**: ✅ **6/8 函式庫對齊** (使用 `llvm-readelf -l` 驗證)

#### AGP 8.10.1 自動對齊失效
- **官方聲稱**: AGP 8.5.1+ 自動將原生函式庫對齊至 16KB
- **實測結果**: 0/8 函式庫 ZIP 對齊
- **可能原因**: AAR 傳遞依賴 (ML Kit, CameraX) 繞過 AGP 處理

1. ✅ **CameraX 函式庫 ELF 對齊**

   - libimage_processing_util_jni.so: 4KB → 16KB

2. ✅ **附帶函式庫 ELF 對齊**
   - libc++_shared.so: 4KB → 16KB
   - libdatastore_shared_counter.so: 4KB → 16KB
   - libandroidx.graphics.path.so: 4KB → 16KB
   - libopencv_java4.so: 已為 16KB

3. ✅ **App 功能完全正常**
   - OpenCV 4.13.0 載入成功
   - CameraViewModel 完整初始化
   - 相機預覽、AI 人臉偵測、構圖引導全部正常
   - 無崩潰或異常

4. ✅ **Google Play 合規**
   - 透過 `android:pageSizeCompat="enabled"` 確保向後相容
   - 符合「支援 16KB 裝置」要求
   - 可正常提交更新

### 未解決的問題

1. ❌ **ZIP 偏移量對齊** (0/8)
   - 所有函式庫的 ZIP 條目偏移量未對齊 16KB
   - 這是 Android 16 實際檢查的項目

2. ❌ **ML Kit 函式庫 ELF 對齊** (2/8 仍為 4KB)
   - libface_detector_v2_jni.so (ML Kit 16.1.5)
   - libmlkitcommonpipeline.so (ML Kit 17.0.1)

3. ❌ **PageSizeMismatchDialog 仍出現**
   - 實體 Pixel 9a 啟動時仍顯示警告
   - 使用者可關閉，不影響功能

## 5. 下一步行動 (Next Steps)

### Phase 2.6: ZIP 對齊修復 (建議執行)

**參考文件**: `docs/plan/v2.9.6_Phase2.6_ZIP_Alignment_Plan.md` (Gemini 提供)

#### 目標
將**所有 8 個函式庫**的 ZIP 條目偏移量對齊至 16KB，達成 **8/8 完全修復**。

#### 實作方案

**選項 A: zipalign 後處理** (推薦)

```bash
# Step 1: Build APK
./gradlew clean assembleDeviceDebug

# Step 2: Apply zipalign with 16KB alignment
zipalign -p -f -z 16 \
  app/build/outputs/apk/device/debug/app-device-debug.apk \
  app/build/outputs/apk/device/debug/app-device-debug-aligned.apk

# Step 3: Replace original APK
mv app/build/outputs/apk/device/debug/app-device-debug-aligned.apk \
   app/build/outputs/apk/device/debug/app-device-debug.apk

# Step 4: Verify ZIP alignment
zipinfo -v app/build/outputs/apk/device/debug/app-device-debug.apk | \
  grep "lib/arm64-v8a.*\.so" -A 3 | \
  grep "offset" > tmp/zip_offsets_phase2.6.txt

# Step 5: Check all offsets divisible by 16384
python -c "
import re
with open('tmp/zip_offsets_phase2.6.txt') as f:
    content = f.read()
    offsets = re.findall(r'offset.*?:\s+(\d+)', content)
    for i, offset in enumerate(offsets):
        offset_int = int(offset)
        aligned = 'YES' if offset_int % 16384 == 0 else 'NO'
        print(f'Lib {i+1}: {offset_int:>12,}  16KB: {aligned}  (mod {offset_int % 16384})')
"
# Expected: All show "YES" with mod 0
```

**選項 B: Gradle 自動化** (如可實現)

```kotlin
// app/build.gradle.kts
android {
    // ... existing configuration

    applicationVariants.all { variant ->
        variant.outputs.all { output ->
            variant.packageApplicationProvider.get().doLast {
                val apkFile = output.outputFile
                if (apkFile.exists()) {
                    exec {
                        commandLine(
                            "zipalign",
                            "-p", "-f", "-z", "16",
                            apkFile.absolutePath,
                            "${apkFile.parent}/aligned-${apkFile.name}"
                        )
                    }
                    delete(apkFile)
                    file("${apkFile.parent}/aligned-${apkFile.name}")
                        .renameTo(apkFile)
                }
            }
        }
    }
}
```
