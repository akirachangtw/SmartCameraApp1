## 二、Logcat 日誌分析

### 2.1 直向模式日誌 (90° 旋轉)

```
Processing image: 640x480, rotation: 90°
Transform: MLKit[125, 270, 311, 379] -> Screen[281, 1090, 699, 1335]
(img=480x640, rotation=90°, scale=2.250, offset=[0,482])
```

**問題發現**:
- ML Kit 報告: `640x480` (已旋轉後的尺寸)
- transformRect 使用: `480x640` (進行了維度交換！)
- **雙重交換錯誤**: ML Kit 已經將 90° 旋轉處理好，返回 640x480（橫向影像），但程式碼又交換成 480x640（直向），導致錯誤的長寬比

**後果**:
- 錯誤的 aspect ratio 計算
- offsetY = 482px（過大的偏移）
- 螢幕座標 y=1090px **超出 1080px 螢幕高度！**
- 大部分框被渲染到螢幕下方不可見區域

### 2.2 橫向模式日誌 (0° 旋轉)

```
Processing image: 640x480, rotation: 0°
Transform: MLKit[199, -21, 508, 287] -> Screen[335, 762, 857, 1281]
(img=640x480, rotation=0°, scale=1.688, offset=[0,797])
```

**問題發現**:
- ML Kit 報告: `640x480`
- transformRect 使用: `640x480` (未交換，正確)
- **但偏移仍過大**: offsetY = 797px
- 螢幕座標底部 y=1281px 仍超出螢幕範圍

### 2.3 根本原因確認

**v1.3.2 的錯誤邏輯**:
```kotlin
val needsSwap = rotationDegrees == 90 || rotationDegrees == 270
val effectiveImageWidth = if (needsSwap) imageSize.height else imageSize.width
val effectiveImageHeight = if (needsSwap) imageSize.width else imageSize.height
```

**問題**:
1. `imageSize` 參數已經是 `inputImage.width` 和 `inputImage.height`（來自 MLKitDetector.kt:102-103）
2. `InputImage.fromMediaImage()` **內部已經處理旋轉**，返回的尺寸是**旋轉後的尺寸**
3. 程式碼又進行一次維度交換 → **雙重交換** → 錯誤的長寬比 → 巨大的偏移量

#### 修改 1: 移除維度交換邏輯

**原始碼 (v1.3.2, 錯誤)**:
```kotlin
// Step 1: Determine effective image dimensions
// ML Kit returns coordinates in the rotated space, but imageSize reflects the ORIGINAL dimensions
// For 90°/270° rotations, the coordinate space has swapped dimensions
val needsSwap = rotationDegrees == 90 || rotationDegrees == 270
val effectiveImageWidth = if (needsSwap) imageSize.height else imageSize.width
val effectiveImageHeight = if (needsSwap) imageSize.width else imageSize.height
```

**修正後 (v1.3.3, 正確)**:
```kotlin
// Step 1: Use image dimensions directly
// IMPORTANT: imageSize parameter already contains the ROTATED dimensions from InputImage
// MLKitDetector passes inputImage.width/height which are already post-rotation
// We should NOT swap dimensions again!
val effectiveImageWidth = imageSize.width
val effectiveImageHeight = imageSize.height
```

#### 修改 2: 加入邊界檢查與座標箝制

**新增程式碼**:
```kotlin
// Step 5: Check if coordinates are within screen bounds
val isOutOfBounds = transformed.left < 0f || transformed.top < 0f ||
        transformed.right > previewSize.width || transformed.bottom > previewSize.height

if (isOutOfBounds) {
    Log.w(
        "DetectionOverlay",
        "⚠️ Box OUT OF BOUNDS: MLKit[...] -> Screen[...] " +
                "Preview=${previewSize.width.toInt()}x${previewSize.height.toInt()}, ..."
    )
} else {
    Log.d("DetectionOverlay", "Transform: MLKit[...] -> Screen[...]")
}

// Step 6: Clamp coordinates to screen bounds to prevent rendering issues
val clampedRect = Rect(
    left = transformed.left.coerceIn(0f, previewSize.width),
    top = transformed.top.coerceIn(0f, previewSize.height),
    right = transformed.right.coerceIn(0f, previewSize.width),
    bottom = transformed.bottom.coerceIn(0f, previewSize.height)
)

return clampedRect
```

**目的**:
1. 記錄超出範圍的框 (幫助除錯)
2. 將座標箝制在螢幕範圍內 (確保可見性)

## 四、技術分析深入解釋

### 4.1 ML Kit InputImage 行為理解

**InputImage.fromMediaImage() 內部處理**:
```
原始相機感測器: 640x480 (橫向感測器)
裝置方向: 直向 (90° 旋轉)
    ↓
InputImage.fromMediaImage(image, rotationDegrees=90°)
    ↓ 內部旋轉影像
旋轉後影像: 640x480 (仍為橫向，因為旋轉了 90°)
    ↓ ML Kit 偵測
座標系統: 640x480 空間 (橫向)
```

**重點**: ML Kit 返回的 `inputImage.width` 和 `inputImage.height` **已經是旋轉後的尺寸**！

### 4.2 v1.3.2 vs v1.3.3 計算對比

**場景: 直向模式 (90° 旋轉)**

| 步驟 | v1.3.2 (錯誤) | v1.3.3 (正確) |
|------|---------------|---------------|
| ML Kit 影像尺寸 | 640x480 | 640x480 |
| 程式使用尺寸 | 480x640 (交換!) | 640x480 (直接使用) |
| 長寬比 | 0.75 (480/640) | 1.33 (640/480) |
| 螢幕尺寸 | 1080x2400 | 1080x2400 |
| 螢幕長寬比 | 0.45 | 0.45 |
| 縮放依據 | 寬度 (錯誤) | 高度 (正確) |
| 縮放因子 | 1080/480=2.25 | 2400/480=5.0 |
| 縮放後尺寸 | 1080x1440 | 3200x2400 |
| offsetY | (2400-1440)/2=480 | (2400-2400)/2=0 |
| 座標範圍 | y: 480~1920 | y: 0~2400 |
| **結果** | ❌ 超出螢幕 | ✅ 正確 |

**場景: 橫向模式 (0° 旋轉)**

| 步驟 | v1.3.2 (部分錯誤) | v1.3.3 (正確) |
|------|-------------------|---------------|
| ML Kit 影像尺寸 | 640x480 | 640x480 |
| 程式使用尺寸 | 640x480 (未交換) | 640x480 (直接使用) |
| 長寬比 | 1.33 | 1.33 |
| 縮放因子 | 1080/640=1.69 | 1080/640=1.69 |
| 縮放後尺寸 | 1080x810 | 1080x810 |
| offsetY | (2400-810)/2=795 | (2400-810)/2=795 |
| **結果** | ⚠️ 偏移過大 | ✅ 相同但正確 |

### 4.3 為何直向模式錯誤更嚴重

**直向 (90°)**:
- v1.3.2 進行維度交換 → 完全錯誤的長寬比
- offsetY = 480px → 大部分框超出螢幕下方

**橫向 (0°)**:
- v1.3.2 未進行交換 → 長寬比正確
- 但 offsetY = 795px 仍然偏大（因螢幕高度 2400px 遠大於影像高度 810px）
- 部分框仍會超出範圍

## 七、關鍵學習點

### 7.1 ML Kit 座標系統理解

**重要概念**:
1. `InputImage.fromMediaImage(image, rotationDegrees)` 會內部旋轉影像
2. `inputImage.width` 和 `inputImage.height` 是**旋轉後的尺寸**
3. 返回的 bounding box 座標也在**旋轉後的空間**中
4. **不要再次進行任何旋轉或維度交換！**

### 7.2 除錯方法

**有效的診斷步驟**:
1. **對比日誌與預期** - 發現 img=480x640 與 ML Kit 報告的 640x480 不符
2. **追蹤資料來源** - 確認 imageSize 來自 inputImage.width/height
3. **理解 API 行為** - 研究 InputImage 如何處理旋轉
4. **計算驗證** - 手動計算 offset 發現 480px 過大，導致座標超出 1080px

### 7.3 測試的重要性

**v1.3.2 測試揭露的問題**:
- 截圖顯示偵測計數與可見框數不符
- Logcat 顯示座標值超出螢幕範圍
- 兩者結合確定問題為「框被渲染到螢幕外」

**沒有測試就無法發現**:
- v1.3.2 的修復看似合理（移除雙重旋轉）
- 但仍存在維度交換問題
- 只有實際測試才能發現

## 十、結論

v1.3.3 成功修復了 v1.3.2 的維度交換問題。根本原因是對 ML Kit InputImage 行為的理解仍不完整：雖然 v1.3.2 移除了旋轉矩陣轉換，但仍錯誤地進行了維度交換。

**核心理解**:
- ML Kit 的 `inputImage.width/height` 已經是旋轉後的尺寸
- 不需要任何維度操作，直接使用即可
- 只需進行簡單的 scale + offset 轉換

**修復效果**:
- 移除維度交換 → 正確的長寬比 → 合理的偏移量
- 加入邊界箝制 → 確保所有框可見
- 增強日誌 → 更容易發現未來問題

**預期結果**: 所有邊界框應正確顯示在螢幕範圍內，偵測計數與可見框數一致。
