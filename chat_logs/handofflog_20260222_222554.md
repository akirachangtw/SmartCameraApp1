### 修改後程式碼（v2.11.4-03 目標版本）

**將上方 try/catch 區段（第 740-751 行）替換為：**

```kotlin
        // v2.11.4-03: Set CONTROL_AE_LOCK=true + CONTROL_AF_MODE=OFF via Camera2CameraControl.
        // CONTROL_AE_LOCK=true: freezes ISO + exposure time (v2.11.4-02).
        // CONTROL_AF_MODE=OFF: disables AF algorithm, holds lens at current focused position.
        // FocusMeteringAction one-shot AF would degrade FOCUSED_LOCKED→PASSIVE_SCAN after ~3s;
        // setting AF_MODE=OFF after metering success permanently holds the focal distance.
        // AF_STATE will show INACTIVE (0) in logcat — this is correct behavior for MODE=OFF.
        try {
            @OptIn(ExperimentalCamera2Interop::class)
            Camera2CameraControl.from(cameraControl)
                .addCaptureRequestOptions(
                    CaptureRequestOptions.Builder()
                        .setCaptureRequestOption(CaptureRequest.CONTROL_AE_LOCK, true)
                        .setCaptureRequestOption(
                            CaptureRequest.CONTROL_AF_MODE,
                            CaptureRequest.CONTROL_AF_MODE_OFF
                        )
                        .build()
                )
            Log.i(TAG, "[v2.11.4-03] CONTROL_AE_LOCK=true + CONTROL_AF_MODE=OFF applied (true AE+AF lock)")
        } catch (e: Exception) {
            Log.w(TAG, "[v2.11.4-03] Failed to apply AE/AF lock options: ${e.message}")
        }
```

### 技術背景：為何 CONTROL_AF_MODE=OFF 而非 AUTO？

| 選項 | 效果 | 退化？ |
|------|------|--------|
| `CONTROL_AF_MODE_AUTO`（使用者方案一） | 一次性對焦，HAL ~3s 後仍恢復 PASSIVE | ✅ 仍退化 |
| `CONTROL_AF_MODE_OFF`（**推薦**） | 完全關閉 AF 算法，鏡頭永久停在已對焦距離 | ❌ 不退化 |

`CONTROL_AF_MODE=OFF` 必須在 CameraX metering 成功後設定（即 FocusMeteringAction callback success 之後），此時鏡頭已收斂到正確焦距，切換 OFF 即永久固定。
