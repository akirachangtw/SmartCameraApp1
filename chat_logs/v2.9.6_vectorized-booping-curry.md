**預覽流程 (正確)**:
```

    ↓
transformBitmap(90°)
    ↓

```

### What: 要解決什麼問題

2. 照片缺少 EXIF Orientation 資訊
3. 預覽畫面在橫向旋轉時不正確

### Why: 為什麼發生

### Scope: 影響範圍
- 所有拍照功能
- 所有非 Landscape Left 的拍照方向
- 預覽畫面的橫向顯示

2. ⚠️ 涉及預覽畫面旋轉計算
3. ⚠️ 修改可能影響前鏡頭的鏡像邏輯
4. ⚠️ EXIF 寫入需要考慮 Android 版本相容性

## L2 可行性檢視

### 修復方案

#### 方案 A: 在 takePicture() 應用旋轉（推薦）

**修改**: `LiveCameraSource.takePicture()`

```kotlin
override suspend fun takePicture(): Result<Bitmap> = suspendCancellableCoroutine { continuation ->
    imageCapture.takePicture(
        ContextCompat.getMainExecutor(context),
        object : ImageCapture.OnImageCapturedCallback() {
            override fun onCaptureSuccess(image: ImageProxy) {
                val rotationDegrees = image.imageInfo.rotationDegrees
                val rawBitmap = image.toBitmap()

                // 應用旋轉轉換
                val rotatedBitmap = if (rotationDegrees != 0) {
                    rotateBitmap(rawBitmap, rotationDegrees)
                } else {
                    rawBitmap
                }

                image.close()
                continuation.resume(Result.success(rotatedBitmap))
            }
        }
    )
}

private fun rotateBitmap(bitmap: Bitmap, degrees: Int): Bitmap {
    val matrix = Matrix()
    matrix.postRotate(degrees.toFloat())
    return Bitmap.createBitmap(bitmap, 0, 0, bitmap.width, bitmap.height, matrix, true)
}
```

**優點**:
- 最小改動
- 不影響現有預覽邏輯
- 不需要修改 EXIF（因為 Bitmap 已經正確旋轉）

**缺點**:
- 額外的 Bitmap 記憶體分配
- 旋轉運算的 CPU 開銷

#### 方案 B: 使用 ExifInterface 寫入 Orientation

**修改**: `CameraRepositoryImpl.saveBitmapToMediaStore()`

```kotlin
private suspend fun saveBitmapToMediaStore(bitmap: Bitmap, rotationDegrees: Int): CaptureResult {
    // ... 現有儲存邏輯 ...

    // 寫入 EXIF Orientation
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q) {
        contentResolver.openFileDescriptor(uri, "rw")?.use { pfd ->
            val exif = ExifInterface(pfd.fileDescriptor)
            exif.setAttribute(ExifInterface.TAG_ORIENTATION,
                getExifOrientation(rotationDegrees).toString())
            exif.saveAttributes()
        }
    }
}
```

**優點**:
- 不需要額外的 Bitmap 轉換
- 保留原始圖像品質

**缺點**:
- 需要從 LiveCameraSource 傳遞 rotationDegrees
- 部分圖像檢視器不支援 EXIF Orientation
- 需要修改多個檔案的介面

### 可行性結論

**推薦方案 A** - 在 `takePicture()` 應用旋轉

理由：
1. 改動範圍最小（只修改一個函數）
2. 確保輸出 Bitmap 方向正確，不依賴外部處理
3. 與現有預覽旋轉邏輯一致
