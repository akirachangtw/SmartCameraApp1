## 1. 專案背景 (Context)

### 問題描述

SmartCameraApp 是一款 AI 驅動的 Android 攝影構圖助手應用程式，旨在即時分析相機預覽畫面並提供構圖建議。v2.6.0 版本新增了**光線分析 (Lighting Analysis)** 功能，能夠偵測 5 種光線狀態並建議是否使用 HDR 模式。

在 P0-1 模擬器測試中，發現了一個**關鍵 Bug**：

**問題**: Overexposed（過曝）光線狀態從未被觸發

**影響**:
- 過曝場景無法正確警告使用者
- HDR 建議邏輯不完整（缺少過曝場景判斷）
- 測試覆蓋率僅 4/5 (80%)，Overexposed 狀態無法驗證

**根本原因**:
1. **優先級錯誤**: `AnalyzeLightingUseCase.kt` 中 HighContrast 優先於 Overexposed 進行判斷，導致同時滿足兩個條件的場景被誤判為 HighContrast
2. **測試圖片不足**: Gemini API 生成的 `hdr_overexposed_snow_glare.jpg` 高光比僅 7.39%，遠低於 15% 檢測閾值

### 🔧 已解決的關鍵錯誤

#### 錯誤 1: Overexposed 狀態優先級錯誤

**檔案**: `app/src/main/java/com/akirachang/ai/photographer/domain/usecase/AnalyzeLightingUseCase.kt`

**錯誤代碼** (第 165-186 行):
```kotlin
// BEFORE: Wrong priority order
private fun classifyLightingState(analysis: ExposureAnalysis): LightingState {
    return when {
        analysis.isBacklit -> LightingState.Backlight(...)       // Priority 1 ✅
        analysis.isHighContrast -> LightingState.HighContrast(...) // Priority 2 ❌
        analysis.isOverexposed -> LightingState.Overexposed(...)   // Priority 3 ❌
        analysis.isLowLight -> LightingState.Underexposed(...)     // Priority 4 ✅
        else -> LightingState.Normal
    }
}
```

**問題**:
- `hdr_overexposed_sunny_outdoor.jpg` 同時滿足 `isHighContrast` 和 `isOverexposed`
- 因為 HighContrast 優先級更高，永遠返回 HighContrast 狀態
- Overexposed 檢測邏輯永遠不會被執行

**修復代碼** (提交 `e59ec71`):
```kotlin
// AFTER: Correct priority order
private fun classifyLightingState(analysis: ExposureAnalysis): LightingState {
    return when {
        analysis.isBacklit -> LightingState.Backlight(...)       // Priority 1 ✅
        analysis.isOverexposed -> LightingState.Overexposed(...)   // Priority 2 ✅ FIXED
        analysis.isHighContrast -> LightingState.HighContrast(...) // Priority 3
        analysis.isLowLight -> LightingState.Underexposed(...)     // Priority 4 ✅
        else -> LightingState.Normal
    }
}
```

**理由**:
- Overexposed 是具體的曝光問題（細節已流失，不可逆）
- HighContrast 是場景特性（可透過 HDR 補救）
- 語義正確性：具體問題應優先於一般特性

### 4.1 核心修復代碼

#### 檔案: `AnalyzeLightingUseCase.kt`

**完整的 `classifyLightingState` 函數** (第 132-214 行):

```kotlin
/**
 * Classify exposure analysis into presentation state
 *
 * v2.6.0: Updated to use new LightingState structure with separated Backlight state
 *
 * Priority order (highest to lowest):
 * 1. Backlight (most critical - affects subject visibility)
 * 2. Overexposure (highlight clipping - specific exposure issue)
 * 3. High contrast (needs HDR - general scene characteristic)
 * 4. Underexposure (low light)
 * 5. Normal
 *
 * @param analysis ExposureAnalysis from detector
 * @return LightingState for UI
 */
private fun classifyLightingState(
    analysis: com.akirachang.ai.photographer.domain.model.ExposureAnalysis
): LightingState {
    return when {
        // Backlight - highest priority (separated from HighContrast in v2.6.0)
        analysis.isBacklit -> {
            // Calculate luminance difference for display
            val subjectLuminance = analysis.avgLuminance * 0.7f // Estimate (subject darker)
            val backgroundLuminance = analysis.avgLuminance * 1.3f // Estimate (background brighter)
            val luminanceDiff = kotlin.math.abs(backgroundLuminance - subjectLuminance)

            LightingState.Backlight(
                subjectLuminance = subjectLuminance,
                backgroundLuminance = backgroundLuminance,
                luminanceDifference = luminanceDiff
            )
        }

        // Overexposure - priority 2 (more specific than high contrast)
        analysis.isOverexposed -> {
            LightingState.Overexposed(
                highlightRatio = analysis.highlightRatio,
                avgLuminance = analysis.avgLuminance
            )
        }

        // High contrast (not backlit, not overexposed, but needs HDR)
        analysis.isHighContrast -> {
            // Calculate contrast ratio from dynamic range
            val minLevel = 127.5f - (analysis.dynamicRange / 2f)
            val maxLevel = 127.5f + (analysis.dynamicRange / 2f)
            val contrastRatio = if (minLevel > 0) maxLevel / minLevel else 10f

            LightingState.HighContrast(
                contrastRatio = contrastRatio,
                dynamicRange = analysis.dynamicRange,
                highlightRatio = analysis.highlightRatio,
                shadowRatio = analysis.shadowRatio
            )
        }

        // Low light (renamed to Underexposed in v2.6.0)
        analysis.isLowLight -> {
            LightingState.Underexposed(
                avgLuminance = analysis.avgLuminance,
                shadowRatio = analysis.shadowRatio
            )
        }

        // Check exposure score for subtle issues
        analysis.exposureScore < EXPOSURE_SCORE_THRESHOLD -> {
            // Moderate exposure issue - use HighContrast as catch-all
            val minLevel = 127.5f - (analysis.dynamicRange / 2f)
            val maxLevel = 127.5f + (analysis.dynamicRange / 2f)
            val contrastRatio = if (minLevel > 0) maxLevel / minLevel else 5f

            LightingState.HighContrast(
                contrastRatio = contrastRatio,
                dynamicRange = analysis.dynamicRange,
                highlightRatio = analysis.highlightRatio,
                shadowRatio = analysis.shadowRatio
            )
        }

        // Normal exposure
        else -> LightingState.Normal
    }
}
```

**關鍵變更**:
1. 第 165-171 行: Overexposure 檢查移至 Priority 2
2. 第 173-186 行: HighContrast 檢查降至 Priority 3
3. 第 137-142 行: 註解更新以反映正確優先級

fun analyze(histogram: Histogram, subjectBox: Rect? = null): ExposureAnalysis {
    // Basic metrics
    val avgLuminance = histogram.avgLuminance
    val highlightRatio = histogram.highlightRatio
    val shadowRatio = histogram.shadowRatio

    // Dynamic range estimation
    val dynamicRange = estimateDynamicRange(histogram)

    // Detection flags
    val isOverexposed = highlightRatio > OVEREXPOSURE_THRESHOLD
    val isLowLight = avgLuminance < LOW_LIGHT_THRESHOLD
