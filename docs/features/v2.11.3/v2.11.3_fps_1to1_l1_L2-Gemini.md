# Implementation Plan - Optimize 1:1 FPS on Pixel 9a

## Problem Description
In 1:1 aspect ratio mode, the app uses a **1920x1920 (3.7 MP)** resolution for both Preview and Image Analysis. This is significantly higher than 4:3 mode (~1.2 MP), causing:
1.  **Slow YUV to Bitmap conversion** in [LiveCameraSource](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/data/source/camera/LiveCameraSource.kt#66-1592).
2.  **Bottlenecks in ML Kit and OpenCV analysis** (300-500ms per frame).
3.  **Preview FPS drop (< 20 FPS)** due to high CPU/thermal load.

## Goal
Improve FPS in 1:1 mode by reducing the processing load while maintaining Preview quality.

## Risk Assessment

1.  **ML Kit Accuracy**: Reducing resolution from 3.7MP to ~1.2MP might slightly reduce detection range for small faces.
    -   *Mitigation*: 1.2MP (1080x1080) is standard for ML Kit (similar to 720p/1080p). Most 4:3 inputs are ~1MP. Impact expected to be negligible.
2.  **Optical Flow Precision**: Lower resolution for Optical Flow might reduce tracking precision.
    -   *Mitigation*: 1080x1080 is still very high res for OF. Should remain robust.
3.  **ViewPort Compatibility**: Mixing resolutions with `ViewPort` + `UseCaseGroup`.
    -   *Mitigation*: CameraX `ViewPort` handles cropping. As long as the aspect ratio (1:1) matches the ViewPort, CameraX should successfully bind. We must ensure the selected resolution is indeed 1:1 (or ViewPort will crop it, which is fine, but we want to maximize FOV).
