# OF Tracking Coordinate Space Fix - Implementation Plan

**Status**: Proposal
**Date**: 2026-02-19

# Goal Description
Fix the Optical Flow tracking failure where the tracking box does not follow the object.
**Root Cause**: The tracker uses high-resolution "Analysis" coordinates (1920x1920) but processes low-resolution "Preview" bitmaps (~720x720). The starting coordinate is out of bounds for the bitmap, causing immediate tracking loss or drift.

# User Review Required
> [!IMPORTANT]
> **Risk Assessment**:
> - **Precision Loss**: Scaling coordinates back and forth (1920 -> 720 -> 1920) introduces minor floating-point errors. This is acceptable for UI tracking boxes but might be jittery for pixel-perfect operations (not required here).
> - **Performance**: minimal impact (~2 multiplications per frame).
> - **Aspect Ratio**: Assumes Analysis and Preview streams have identical aspect ratios. If they differ (e.g., one is cropped), simple scaling will fail. *Verification needed: Code review suggests both follow the selected camera aspect ratio.*

#### [MODIFY] trackFromBitmap(bitmap: Bitmap)

Refine the [trackFromBitmap](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/data/source/camera/SmartCameraAnalyzer.kt#222-273) function to handle coordinate scaling:

1.  **Start Tracking (Downscale)**:
    - When applying `pendingTrackX/Y` (which are in 1920-space or Screen-space mapped to 1920-space), calculate `scaleX = bitmap.width / imageWidth` and `scaleY = bitmap.height / imageHeight`.
    - Initialize `OpticalFlowTracker` with the *bitmap's* dimensions (720x720), not the analysis dimensions.
    - Pass scaled coordinates to `startTracking`.

2.  **Tracking Loop (Upscale Result)**:
    - The `opticalFlowTracker` will return results in Bitmap space (720x).
    - Before calling `onOpticalFlowResult`, scale the point *back* to Analysis space (1920x) so [CameraViewModel](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/presentation/camera/CameraViewModel.kt#45-1724)'s `CoordinateTransformer` (which is bound to the Analysis size) works correctly.

```kotlin
// Pseudocode Logic
val scaleX = bitmap.width.toFloat() / imageWidth.toFloat()
val scaleY = bitmap.height.toFloat() / imageHeight.toFloat()

// 1. Start Scaling
if (hasPendingTrack) {
    val imagePoint = ... // (Current logic gets 1920-space point)
    val bitmapPoint = Point(imagePoint.x * scaleX, imagePoint.y * scaleY)
    tracker.startTracking(bitmapPoint, bitmap.width, bitmap.height)
}

// 2. Result Scaling
val result = tracker.track(grayMat)
val finalPoint = Point(result.point.x / scaleX, result.point.y / scaleY)
onOpticalFlowResult(finalPoint)
```
