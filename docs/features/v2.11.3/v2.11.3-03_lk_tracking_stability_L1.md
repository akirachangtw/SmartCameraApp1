# Level 1 規劃摘要｜v2.11.3 LK Tracking Stability

## 1. 目標（Goal）
修復 Pixel 9a 上 Optical Flow（Lucas-Kanade）追蹤不穩定的問題，使追蹤框能在手機快速左右移動時持續黏著主體，不提前消失。

---

## 2. 背景與已確認根因

### Pixel 9a 特殊架構
- `analyze()` (CameraX ImageAnalysis) **從不執行**；只有 `trackFromBitmap()` 以 ~28fps 跑
- Preview bitmap = 1920×1920（1:1 mode）
- CoordinateTransformer image space = 1920×1920（一致，無座標問題）

### 已確認的兩個根因（by Logcat）

| 問題 | Logcat 證據 | Root Cause |
|------|------------|------------|
| 對焦框立刻消失 | `RANSAC: inliers=1 / valid=30 < minRequired=12` | LK error filter 缺失，30 點全部誤追 |
| 移動後消失（2-cluster） | `RANSAC: inliers=0 / valid=12 < minRequired=4` | 前景/背景特徵分裂兩群，median≈0，3px floor 全拒 |
| 快速移動後消失（quality） | `[Diag] LOST: quality=0.257 < min=0.3` | pass2 找到 inlier 但 inlierRatio×baseQuality < 門檻 |

### 第三個根因（v2.11.3-03 新發現）

快速移動失敗鏈：
```
手機快速左右移動 → dist 77-164px/frame (downsampled 640px)
→ maxDistancePerFrame=25px clamp → center 落後物件位置
→ 下一幀 LK 從偏移位置找特徵 → LK error 升高
→ RANSAC pass2 觸發，找到 10/22 inliers (ratio=0.455)
→ quality = inlierRatio × baseQuality = 0.455 × 0.565 ≈ 0.257
→ minQuality=0.3 → LOST ❌
```

## 4. 風險清單

1. **LK error filter 過濾過度**：MAX_LK_ERROR=50f 設定若偏低，低光場景中有效點會被踢掉，追蹤更容易 LOST
2. **2-pass RANSAC 5× 倍數不足**：極端 2-cluster 情況下 pass2 仍可能找不到足夠 inlier
3. **minQuality 降低接受劣質追蹤**：quality=0.2 門檻若仍太低，可能接受 inlier ratio 不足的追蹤 → 框位置漂移
4. **velocity clamp 造成 center drift**：maxDistancePerFrame=25px 限制在快速移動時讓 center 落後物件，累積誤差後下一次 redetect 在錯誤位置
