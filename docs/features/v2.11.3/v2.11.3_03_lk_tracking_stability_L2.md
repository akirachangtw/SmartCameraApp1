## 3. 高風險點（High-risk areas：CameraX Preview/ImageAnalysis/模式切換/Thread/權限）
1. **CameraX pipeline 差異（Pixel 9a analyze() 不執行）**
   - 風險：修正可能只在「bitmap tracker 路徑」生效；其他機型走 analyze path 可能行為不同。
2. **Thread / 可見性**
   - `SmartCameraAnalyzer` 同時有 analyze() 與 trackFromBitmap()（即使 Pixel 9a analyze 不跑，其他機型仍可能跑）
   - 需注意：`imageWidth/imageHeight`、pending flag、tracker instance 的 thread safety；@Volatile 是否足夠，是否需要更強同步（此版不動它，但要確認不會被這次 config 調整放大問題）。
3. **模式切換（Live / Lock / Tap-to-track）**
   - 降低 minQuality 可能讓「應該 LOST」的情境變成「短時間繼續跟」，造成 UI 看起來飄。
4. **效能與 log 噪音**
   - OpticalFlowTracker 已新增多處 `Log.v/i`；在 28fps 可能造成 log 壓力（尤其 debug build）。此版不新增 log，但需留意驗證時 logcat filter 是否正確避免干擾 FPS。
