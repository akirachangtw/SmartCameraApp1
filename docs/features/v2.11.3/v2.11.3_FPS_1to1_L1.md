## 根因分析（Root Cause）

### 1:1 模式圖像解析度過大

| 長寬比 | 分析流解析度 | 像素數 | 相對比 |
|--------|-------------|--------|--------|
| 4:3    | ~1280×960   | 1.2 MP | 1.0x |
| 1:1    | **1920×1920** | 3.7 MP | **3.1x** |

1:1 模式圖像是 4:3 的 **3.1 倍像素數**，導致每個處理步驟都顯著變慢：

#### Logcat 測量（2026-02-19, 1:1 模式）

```
[v2.8.4 Guideline] OpenCV=200~250ms/frame  (4 FPS 上限)
[v2.8.4 E2E]       MLKit=300~520ms/frame
```

- **OpenCV 線條偵測**（Guideline analysis）：200-250ms → 最多 4 FPS
- **ML Kit 人臉+物件偵測**：300-520ms → 最多 3 FPS
- **SmartCameraAnalyzer 節流**：Pixel 9a 固定 500ms interval (2 FPS)

### 瓶頸路徑

```
1:1 ImageProxy (1920×1920)
  ├─ SmartCameraAnalyzer.analyze()
  │    ├─ ML Kit (300-520ms) ← 瓶頸
  │    └─ OpenCV OF tracking (在 analyze() 路徑)
  └─ getPreviewStream() ImageAnalysis (≤800px bitmap)
       └─ OpenCV Guideline analysis (200-250ms) ← 瓶頸

Preview FPS (實際顯示): 直接來自 PreviewUseCase，理論上不受分析影響
```

**待確認**：FPS < 20 是指「實際 PreviewView 顯示幀率」還是「分析處理幀率」？
- 若是 PreviewView 幀率降低：可能是 ISP 或記憶體壓力導致的
- 若是分析幀率：屬於預期行為（分析節流），但 UI 上的 FPS 顯示可能誤導用戶

## 解決方向（Candidate Fixes）

### 方案 A：Guideline analysis 縮圖後再處理

在 OpenCV 分析前，將 1920×1920 bitmap 縮圖至 960×960 或更小：

```kotlin
// In guideline analysis pipeline:
val scaledBitmap = if (bitmap.width > 960) {
    Bitmap.createScaledBitmap(bitmap, 960, 960, false)
} else bitmap
// Run OpenCV on scaledBitmap
```

**效果預估**：
- 像素數減少 4x → OpenCV 時間估計從 250ms → 60ms
- 線條偵測精度可能略降，但對構圖指引足夠

### 方案 B：限制 1:1 模式的 ImageAnalysis 解析度

在 CameraX ImageAnalysis 設定中，限制最大解析度：

```kotlin
imageAnalysis.setTargetResolution(Size(1080, 1080))  // cap at 1080×1080
```

**效果預估**：
- 1080×1080 vs 1920×1920 → 像素數減少 3.1x → 分析加速
- 可能影響 ML Kit 偵測精度（臉部/物件偵測在較低解析度下準確度可能下降）

### 方案 C：動態節流（依解析度自動調整）

修改 SmartCameraAnalyzer 的節流間隔，根據圖像尺寸動態調整：

```kotlin
val THROTTLE_INTERVAL_MS = when {
    Build.MODEL == "Pixel 9a" && imageWidth >= 1920 -> 1000L  // 1 FPS for 1920×1920
    Build.MODEL == "Pixel 9a" -> 500L                         // 2 FPS for smaller
    else -> 100L                                               // 10 FPS for others
}
```

**效果**：保持流暢 PreviewView，但分析幀率更低（UI 顯示的 FPS 是預覽 FPS 還是分析 FPS？需確認）

### 方案 D：分離 Guideline analysis 至背景低優先級執行

將 OpenCV guideline analysis 移至低優先級線程，避免影響相機預覽主路徑。
