## 3) 高風險點（High-risk areas：CameraX Preview/ImageAnalysis/模式切換/Thread/權限）
1. **座標系（PreviewView vs ImageAnalysis vs ML Kit）三方不一致**（高風險）：  
   - 常見坑：rotation swap、centerCrop content bounds、front camera mirror、分析輸入被縮放到固定尺寸（如 480×640）。  
   - Bug 1 本質就是此類問題；修正若只「換用 imageWidth/Height」但忽略 crop/rotation，可能仍然 <50 或分數跳動。
2. **Thread / State concurrency（TOCTOU）**（中高風險）：  
   - `updateTrackedObjectPosition()` 背景執行緒更新 `_state` 與 UI thread 的 `focusOnPoint()` 同時寫 `focusPoint`。  
   - 需要確保 guard 的位置正確、涵蓋所有更新點，否則仍會間歇覆蓋。
3. **模式切換 / tracking 來源切換**（中風險）：  
   - ML Kit tracking、OF tracking、manual tap、motion-triggered refocus 同時存在時，`focusIndicatorFading` / `trackedObjectId` / `isTracking` 的互動容易出現「狀態互相打架」。
4. **AE/AF Lock 回歸**（中風險）：  
   - auto-focus throttle、manual override、lock 狀態條件順序若被改動，可能造成 lock 時仍被自動對焦觸發。

## 4) 最小差異建議（Minimal diff approach：步驟化）
### Step A — 先修 Bug 2（TOCTOU）【P0，低風險，建議先落地】
1. 在 `updateTrackedObjectPosition()` 進入時計算 `val trackedId = _state.value.trackedObjectId`（保留既有行為）。  
2. 在所有 `_state.update { ... focusPoint = ... }` 的 lambda **內部**加入一致性檢查：  
   - `if (current.trackedObjectId != trackedId) return@update current`  
3. 覆蓋包含：  
   - 一般 tracking 更新路徑  
   - motion detection refocus path（若有）  
   - 任何以 trackedId 推導 focusPoint 的分支  
4. 確認 `focusOnPoint()`（manual tap）會將 `trackedObjectId = null`，從而讓背景更新自然失效。

### Step B — 修 Bug 1（saliency score）前，先把座標系「定義清楚」【P0，但需先釐清再改】
最小可行策略是：**saliency score 全程使用「ML Kit bbox 所在的那個 image space」的 width/height**，避免混用 PreviewView size。
1. 在 `DetectionResult`（或 MLKit wrapper）中找出：  
   - bbox 的座標空間：`InputImage` 的 width/height（可能已 rotation）  
2. 產生 `effectiveImageWidth/Height`（建議命名明確）：
   - 若 bbox 是 rotated 後的空間：用 rotated 後 width/height  
   - 若 bbox 是 raw：用 raw，並確保 bbox center 後續轉換同一套
3. `calculateSaliencyScore(boundingBox, isFace, effectiveImageWidth, effectiveImageHeight)`  
4. **不要**使用 PreviewView 尺寸做 normalized area / centrality。
5. 加 log（debug only）：在 score 計算時印出  
   - bbox(w,h)、effectiveImage(w,h)、normalizedSize、centrality、score  
   用 Pixel 9a 對臉測試，確認 score 穩定 > 50。

### Step C — 調整動畫（Issue 3）【P1，低風險】
1. 先採 **Option A：StiffnessHigh** 回到 v2.11.1 體感，diff 最小、可快速收斂。  
2. 若仍覺得「snap」太快再切 Option B（tween 80ms），但這屬體感調參，建議放在下一個 patch 或用 feature flag/const 便於回退。
