## 觀察重點

`CameraViewModel.kt` 中 `calculateSaliencyScore()` 已確認使用 `viewWidth`/`viewHeight`（螢幕尺寸）正規化 ML Kit image-space bbox，導致 score 永遠 < 50。`updateTrackedObjectPosition()` 的兩個 `_state.update` 呼叫均未在 lambda 內部重新驗證 `trackedObjectId`，存在 TOCTOU 風險。`CoordinateTransformer.imageWidth/imageHeight` 為 `private`，但 `updateContentBounds()` 已有完整的 rotation-swap 邏輯可直接複用。

## 方案選擇

採用「最小改動、最高確定性」策略：Bug 1 在 `autoFocusOnSalientTarget()` 內部就地計算 `effectiveImageWidth/Height`（複用 `updateContentBounds()` 的 rotation-swap 邏輯），避免修改 `CoordinateTransformer` 的可見性；Bug 2 在兩個 `_state.update` lambda 內加入 guard check；Fix 3 改回 `StiffnessHigh`。三項修改互相獨立，影響範圍極小。

## 實作步驟

### Step 1 — Bug 1：修正 `calculateSaliencyScore()` 函數簽名（`CameraViewModel.kt`）

在 `file:app/src/main/java/com/akirachang/ai/photographer/presentation/camera/CameraViewModel.kt` 中：

1. 將 `calculateSaliencyScore()` 的參數 `viewWidth: Int, viewHeight: Int` 重新命名為 `imageWidth: Int, imageHeight: Int`（KDoc 同步更新）。
2. 函數內部將所有 `viewWidth`/`viewHeight` 參考改為 `imageWidth`/`imageHeight`：
   - `normalizedSize = boxSize / (imageWidth * imageHeight)`
   - `imageCenterX = imageWidth / 2f`
   - `imageCenterY = imageHeight / 2f`

### Step 2 — Bug 1：在 `autoFocusOnSalientTarget()` 計算 effective image 尺寸（`CameraViewModel.kt`）

在 `autoFocusOnSalientTarget()` 中，取得 `detectionResult` 後，加入與 `updateContentBounds()` 相同的 rotation-swap 邏輯：

- 讀取 `detectionResult.imageWidth`、`detectionResult.imageHeight`、`detectionResult.rotationDegrees`
- 若 `rotationDegrees == 90 || rotationDegrees == 270`，則 swap → `effectiveImageWidth = rawImageHeight`、`effectiveImageHeight = rawImageWidth`
- 否則直接使用原始值

將 `calculateSaliencyScore()` 的兩個呼叫點（faces loop 與 objects loop）改為傳入 `effectiveImageWidth`/`effectiveImageHeight`，取代原本的 `viewWidth`/`viewHeight`。

> **注意**：`viewWidth`/`viewHeight` 仍需保留供 `focusOnPoint()` 呼叫使用，不要移除。

### Step 3 — Bug 2：`updateTrackedObjectPosition()` TOCTOU fix（`CameraViewModel.kt`）

在 `updateTrackedObjectPosition()` 中，針對兩個 `_state.update` 呼叫加入 guard：

**路徑 A — 正常位置更新**（目前約 line 809–810）：
- 將 `_state.update { it.copy(focusPoint = ...) }` 改為接收 `current` 參數的 lambda
- 在 lambda 開頭加入：若 `current.trackedObjectId != trackedId`，則 `return@update current`（不修改 state）

**路徑 B — Motion detection refocus**（目前約 line 788）：
- 將 `_state.update { it.copy(focusIndicatorFading = false, isFocusing = true) }` 同樣改為接收 `current` 參數
- 在 lambda 開頭加入相同的 `trackedObjectId` guard

`trackedId` 變數在函數頂部已從 `_state.value.trackedObjectId` 讀取，可直接在 lambda 內比對。

### Step 4 — Fix 3：FocusIndicator 動畫速度（`CameraScreen.kt`）

在 `file:app/src/main/java/com/akirachang/ai/photographer/presentation/camera/CameraScreen.kt` 的 `FocusIndicator()` composable 中：

- 將 `animatedX` 與 `animatedY` 的 `animationSpec` 中 `Spring.StiffnessMedium` 改回 `Spring.StiffnessHigh`（共 2 處）
- 更新行內注解，說明改回 `StiffnessHigh` 的原因（用戶反映 Medium 過慢）
