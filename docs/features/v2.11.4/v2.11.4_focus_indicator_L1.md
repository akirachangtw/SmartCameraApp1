## Bug 1: Fix 1 — 有人臉時不會出現對焦框

### 現象
APP 對著人臉時，對焦框不自動出現。Fix 1 的 auto-focus 功能完全失效。

### Root Cause (Level 2 分析)

**座標系不符導致 saliency score 永遠 < 50**

`calculateSaliencyScore()` 使用 `viewWidth`/`viewHeight` (PreviewView 螢幕尺寸)
來正規化 ML Kit 人臉 bbox 面積（人臉 bbox 在 image 座標系）：

```kotlin
// 錯誤：image 座標系的 bbox 除以 screen 座標系的面積
val normalizedSize = boxSize / (viewWidth * viewHeight)
```

**實測數值（Pixel 9a）**：
- ML Kit 影像大小：`480×640` px（logcat 確認：`chromaWidth=320, frame=640×480` → rotation 後 `480×640`）
- PreviewView 螢幕尺寸：`previewWidth ≈ 1080, previewHeight ≈ 2340`
- 人臉 bbox：e.g., `150×200` px（在 480×640 空間）

**Score 計算結果**：
```
normalizedSize = (150×200) / (1080×2340) = 30000 / 2527200 ≈ 0.012
sizeScore = 0.012 × 60 = 0.72  (應為 3.9)

centrality 計算也混用座標系：
  faceCenter(in image) = (240, 320)  vs  screenCenter = (540, 1170)
  → 距離誤差大，centrality ≈ 0.30
  centralityScore = 0.30 × 40 = 12.0

score = 0.72 + 12.0 + 30(face bonus) = 42.7 < 50 ← 永遠不觸發！
```

**Fix 1 的正確 score（修正後）**：
```
使用 imageWidth=480, imageHeight=640：
normalizedSize = 30000 / (480×640) = 30000 / 307200 ≈ 0.098
sizeScore = 0.098 × 60 = 5.86
imageCenter = (240, 320)  distance=0 → centrality=1.0 → centralityScore=40
score = 5.86 + 40 + 30 = 75.86 ✓（遠超 50）
```

### Fix Strategy

修改 `calculateSaliencyScore()` 參數：傳入 `imageWidth`/`imageHeight` 而非 `viewWidth`/`viewHeight`。

**修改檔案**：`CameraViewModel.kt`

```kotlin
// 修改前（Bug）：
private fun calculateSaliencyScore(
    boundingBox: android.graphics.Rect,
    isFace: Boolean,
    viewWidth: Int,       // ← 螢幕尺寸（錯誤）
    viewHeight: Int
): Float {
    val normalizedSize = boxSize / (viewWidth * viewHeight)       // ← 混用座標系
    val screenCenterX = viewWidth / 2f                            // ← 螢幕中心（錯誤）
    val screenCenterY = viewHeight / 2f
    // ...
}

// 修改後（Fix）：
private fun calculateSaliencyScore(
    boundingBox: android.graphics.Rect,
    isFace: Boolean,
    imageWidth: Int,      // ← image 座標系（正確）
    imageHeight: Int
): Float {
    val normalizedSize = boxSize / (imageWidth * imageHeight)     // ← 同一座標系
    val imageCenterX = imageWidth / 2f                            // ← image 中心（正確）
    val imageCenterY = imageHeight / 2f
    // ...
}
```

在 `autoFocusOnSalientTarget()` 呼叫時傳入 `detectionResult.imageWidth`/`imageHeight`：

```kotlin
// 修改前：
val score = calculateSaliencyScore(face.boundingBox, true, viewWidth, viewHeight)

// 修改後：
val score = calculateSaliencyScore(
    face.boundingBox, true,
    detectionResult.imageWidth,
    detectionResult.imageHeight
)
```

> **Note**: `detectionResult.imageWidth`/`imageHeight` 回傳 sensor 原始尺寸（640×480 landscape）。
> `autoFocusOnSalientTarget()` 中已透過 `rotationDegrees` swap → 傳前需確認是否 swap。
> 最安全做法：直接使用已 swap 的 `effectiveImageWidth/Height` 或由 CoordinateTransformer 取得。

## Bug 2: New Bug — 對焦框偶爾出現在錯誤位置

### 現象
- 對焦白色牙線盒，偶爾（2-3次/多次測試）對焦框出現在非點擊位置
- 間歇性（不是每次都發生）
- Sony/Pixel9a 內建相機無此問題

### Root Cause (Level 2 分析)

**TOCTOU Race Condition：`updateTrackedObjectPosition()` 在背景執行緒覆蓋 focusPoint**

```
時序（錯誤情境）：
[Background Thread] updateTrackedObjectPosition() 開始執行
  → 讀取 val trackedId = _state.value.trackedObjectId  // 舊值：face_A.trackingId
  → 計算 face_A 的螢幕位置 (face_x, face_y)

[Main Thread] 用戶點擊 → focusOnPoint() 執行
  → _state.update { focusPoint = (tap_x, tap_y), trackedObjectId = null }  ← 正確位置

[Background Thread] updateTrackedObjectPosition() 繼續
  → _state.update { focusPoint = (face_x, face_y) }  ← 覆蓋！

最終：focusPoint = (face_x, face_y)  →  對焦框出現在人臉位置（不是點擊位置）
```

**間歇性原因**：Race condition 只在 ML Kit 分析幀恰好與用戶點擊重疊時發生（每次不一定觸發）。

### Fix Strategy

在 `updateTrackedObjectPosition()` 的 `_state.update` lambda 內部再次檢查 `trackedObjectId`：

**修改檔案**：`CameraViewModel.kt`，`updateTrackedObjectPosition()` 函數

```kotlin
// 修改前（Bug）：
if (centerX != null && centerY != null) {
    val (screenX, screenY) = transformer?.imageToScreen(centerX, centerY) ?: (centerX to centerY)
    // ...
    _state.update { it.copy(focusPoint = Pair(screenX, screenY)) }  // ← 不檢查 trackedId
}

// 修改後（Fix）：
if (centerX != null && centerY != null) {
    val (screenX, screenY) = transformer?.imageToScreen(centerX, centerY) ?: (centerX to centerY)
    // ...
    _state.update { current ->
        // TOCTOU fix: 確保 focusOnPoint() 尚未清除 trackedObjectId
        if (current.trackedObjectId != trackedId) return@update current
        current.copy(focusPoint = Pair(screenX, screenY))
    }
}
```

這個修改同樣需套用於所有在 `updateTrackedObjectPosition()` 內呼叫 `_state.update` 的位置（包含 motion detection refocus path）。

## Issue 3: Fix 3 — 對焦框跟隨速度過慢

### 現象
對焦框跟隨移動主體的速度較慢，需要加快。

### Root Cause

v2.11.4 將 FocusIndicator 位置動畫從 `StiffnessHigh` 改為 `StiffnessMedium`，目的是「讓指示器看起來在跟隨」，但用戶認為速度太慢：

```kotlin
// 目前（v2.11.4，過慢）：
spring(dampingRatio = Spring.DampingRatioNoBouncy, stiffness = Spring.StiffnessMedium)

// v2.11.1 原始（較快）：
spring(dampingRatio = Spring.DampingRatioNoBouncy, stiffness = Spring.StiffnessHigh)
```

### Fix Strategy

**Option A**（建議）：改回 `StiffnessHigh`，保持 v2.11.1 行為：
```kotlin
spring(dampingRatio = Spring.DampingRatioNoBouncy, stiffness = Spring.StiffnessHigh)
```

**Option B**：使用 `tween(80)` 讓 ML Kit tracking 幾乎即時（ML Kit 本身已提供平滑 bbox）：
```kotlin
animationSpec = if (isTracking) tween(80) else tween(0)
```

**修改檔案**：`CameraScreen.kt`，`FocusIndicator()` composable，`animatedX`/`animatedY` 的 `animationSpec`。

## Issue 4: EXIF 缺少曝光資訊

### 現象
照片資訊 BottomSheet 中「曝光資訊」section 無 ISO / 快門 / 光圈數值。

### Root Cause & 已知限制

**根本原因**：SmartCameraApp 以 `bitmap.compress(JPEG)` 儲存照片，此路徑丟失所有硬體 EXIF。
後續用 `ExifInterface.setAttribute()` 只能寫入 Make/Model/DateTime（v2.11.4 已實作）。

**v2.11.4 已寫入**（新照片才有）：
- ✅ TAG_MAKE = "Google"
- ✅ TAG_MODEL = "Pixel 9a"
- ✅ TAG_SOFTWARE = "SmartCameraApp v2.11.4"
- ✅ TAG_DATETIME = 拍攝時間

**仍缺失**（需 Camera2Interop）：
- ❌ ISO（需 `TotalCaptureResult.get(CaptureResult.SENSOR_SENSITIVITY)`）
- ❌ 快門速度（需 `TotalCaptureResult.get(CaptureResult.SENSOR_EXPOSURE_TIME)`）
- ❌ 光圈（Pixel 9a 固定 f/1.7，可 hardcode 但不通用）
- ❌ 鏡頭型號（需 `CameraCharacteristics`）

**驗證方法**：拍攝**新照片**後開啟照片資訊，確認相機資訊欄位有 Make/Model/Software。
若仍無 → 可能是 v2.11.4 APK 未正確安裝（確認使用今日安裝版本）。

**長期修復**：v2.12.0 — Camera2Interop TotalCaptureResult 路徑（見 `plans/roadmap/v2.11-v2.1x-roadmap.md`）。

## Issue 5: Fix 2 — 如何測試 AUTO_FOCUS_THROTTLE

### Fix 2 說明
`autoFocusOnSalientTarget()` 新增 `AUTO_FOCUS_THROTTLE_MS = 2000ms` 獨立節流，
防止 auto-focus 在每個 ML Kit 偵測幀都觸發（原本無節流時每秒可觸發 5-10 次）。

### 測試方法
1. 開啟 Logcat：
   ```bash
   adb -s 59131JEBF17244 logcat -v time CameraViewModel:D *:S | grep "Smart Subject Focus"
   ```
2. 將相機對準人臉，保持靜止 30 秒
3. 觀察 "Smart Subject Focus" 訊息出現頻率
4. **預期**：最快每 2 秒出現一次（節流正常）
5. **驗證失敗條件**：每秒出現 3 次以上 → 節流失效
