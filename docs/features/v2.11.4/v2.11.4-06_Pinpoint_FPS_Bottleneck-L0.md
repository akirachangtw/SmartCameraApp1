## Observations

The FPS drop in 1:1 mode is caused by a **resolution mismatch** in `bindToLifecycle()` inside `file:app/src/main/java/com/akirachang/ai/photographer/data/source/camera/LiveCameraSource.kt`. A single `commonSelector` is shared across all three use cases (Preview, ImageAnalysis, ImageCapture). For 1:1 mode, the `ResolutionFilter` explicitly targets the resolution **closest to 1920×1920**, resulting in a ~3.7 MP `ImageProxy` per frame. In contrast, 4:3/16:9 modes use `AspectRatioStrategy` which CameraX resolves to ~480×360 (~0.17 MP). This is a **~21× pixel count difference**, directly multiplying the cost of YUV conversion, `transformBitmap()`, and ML Kit analysis per frame.

## Approach

Split `commonSelector` into two separate selectors: a **high-res selector** for `Preview` + `ImageCapture` (preserving visual quality and WYSIWYG), and a **low-res analysis selector** for `ImageAnalysis` only. For 1:1 mode, the analysis selector targets the smallest available square resolution (e.g., 480×480 or 720×720) instead of 1920×1920. The `ViewPort` remains unchanged — it still uses `Rational(1,1)` to guarantee WYSIWYG cropping across all use cases.

- `selectDeviceOptimalResolution()` returns a `targetResolution` (e.g., 1280×720 for Pixel) but it is only used for diagnostic logging (`selectedResolution`), **not** for the `ResolutionSelector`.
