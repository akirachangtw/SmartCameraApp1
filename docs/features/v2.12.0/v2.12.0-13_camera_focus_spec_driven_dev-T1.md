### Step 2：在 `TrackedObjectType.FACE` 分支中計算框大小

**位置**：`if (face != null)` 區塊內（目前第 834–853 行），在計算 `centerX`/`centerY` 之後、`if` 區塊結束之前。

> ⚠️ 注意：`transformer` 的讀取應在 `when` 分支內部進行（`_state.value.coordinateTransformer`），與 `shouldUpdate` 區塊中的 `transformer` 讀取保持一致，避免兩次讀取之間的 race。

### Step 4：修改 `shouldUpdate` 區塊中的 `_state.update` 呼叫

**位置**：第 919–929 行的 `if (shouldUpdate)` 區塊。

**目前程式碼結構**：
```
_state.update { current ->
    if (current.trackedObjectId != trackedId) return@update current
    current.copy(focusPoint = Pair(screenX, screenY))
}
```

**修改**：在 `current.copy(...)` 中，**同一個呼叫**內加入 `focusFrameWidthPx` 和 `focusFrameHeightPx`：
- 若 `newFrameW != null && newFrameH != null`：加入 `focusFrameWidthPx = newFrameW, focusFrameHeightPx = newFrameH`
- 若為 null（`transformer == null` 的 legacy 路徑）：不傳入這兩個欄位（保持 `current.copy` 的預設行為，即不更新）

實作方式：使用 Kotlin 的 `let` 或 `if` 在 `current.copy(...)` 內條件性地展開，或使用兩步 copy（但必須在同一個 `_state.update` lambda 內完成，不可拆成兩次 `_state.update`）。

推薦寫法（概念）：
```
current.copy(
    focusPoint = Pair(screenX, screenY),
    focusFrameWidthPx  = newFrameW ?: current.focusFrameWidthPx,
    focusFrameHeightPx = newFrameH ?: current.focusFrameHeightPx
)
```

這樣當 `newFrameW == null`（transformer 不可用）時，自動保留現有值，不更新框大小，符合「legacy fallback 路徑跳過更新」的要求。
