# v2.12.0-04 FocusIndicator 動態縮放 (L2 技術分析與細化)

基於 L1 的高層次規劃，本文件針對「對焦框動態縮放」功能進行 L2 級別的詳細技術可行性分析與實作細化。

## 1. ML Kit 資料整合 (Data Integration)

為將 ML Kit 的 `boundingBox` 傳遞給 UI，需更新狀態管理資料結構（例如 `CameraState`）。建議在 ViewModel 中計算好螢幕座標 (Screen-Space) 與 Dp 尺寸，避免在 Compose 中進行繁重的座標轉換。

**具體實作建議：**
在 UI State 中擴充對焦目標的定義：

```kotlin
import androidx.compose.ui.geometry.Offset
import androidx.compose.ui.unit.DpSize

data class FocusTarget(
    val center: Offset,             // 轉換至 Screen-space 的中心點座標
    val boundingBoxSize: DpSize?    // 經過 CoordinateTransformer 轉換並轉為 Dp 的目標尺寸
)

// 整合入現有的 State
data class CameraState(
    // ...
    val focusTarget: FocusTarget? = null
)
```
**資料流機制**：當 ML Kit 回傳偵測結果 (如 Face 或 Object)，ViewModel 透過 `CoordinateTransformer` 將 `android.graphics.Rect` 映射至畫面座標。從映射後的 Rect 求出 `width` 與 `height`，然後轉換為 `DpSize` (`width / density`, `height / density`) 存入 `CameraState`，達成單一資料來源 (Single Source of Truth)。

## 2. 尺寸計算邏輯 (Size Calculation Logic)

需將 `boundingBox` 的尺寸合理映射至 `48.dp` (預設/最小值) 到 `120.dp` (最大值) 之間。

**演算法設計：**
1. 提取 bbox 寬高的最大值 (Max Dimension)。
2. 可選：乘上視覺縮放係數 (Scale Factor) 確保框線不過度貼合目標邊緣。
3. 使用 Kotlin 的 `coerceIn` 函式進行範圍限制 (Clamp)。
4. 處理空值或極端值 (退回預設 `48.dp`)。

**程式碼範例：**
```kotlin
import androidx.compose.ui.unit.Dp
import androidx.compose.ui.unit.dp
import androidx.compose.ui.unit.coerceIn
import androidx.compose.ui.unit.max

val MIN_FOCUS_SIZE = 48.dp
val MAX_FOCUS_SIZE = 120.dp
const val VISUAL_PADDING_SCALE = 0.85f // 例如取目標大小的 85%

fun calculateFocusIndicatorSize(boxSize: DpSize?): Dp {
    if (boxSize == null || boxSize.width <= 0.dp || boxSize.height <= 0.dp) {
        // 沒有 bbox 或尺寸無效時，回歸基本大小
        return MIN_FOCUS_SIZE
    }
    
    // 取寬高中的最大值作為正方形框的邊長基準
    val maxDimension = max(boxSize.width, boxSize.height)
    val targetSize = maxDimension * VISUAL_PADDING_SCALE
    
    // 嚴格限制在 48.dp 到 120.dp 之間
    return targetSize.coerceIn(MIN_FOCUS_SIZE, MAX_FOCUS_SIZE)
}
```

## 3. 動畫狀態管理 (Animation Implementation)

為實現平滑且具備彈性的過渡效果，推薦使用 `animateDpAsState` 搭配 Jetpack Compose 的 `spring` 動畫規範。

**特定 API 與參數推薦：**
- **API**: `animateDpAsState` (處理依賴 State 自動過渡的推薦方式)。
- **Spring 參數**:
  - `dampingRatio = Spring.DampingRatioMediumBouncy` (中等彈性，視覺反饋明確，適合對焦框這種互動元素)。
  - `stiffness = Spring.StiffnessMediumLow` (中低剛性，避免框跟隨過於死板、生硬)。

**狀態宣告範例：**
```kotlin
val targetSizeDp = calculateFocusIndicatorSize(focusTarget?.boundingBoxSize)

val animatedSize by animateDpAsState(
    targetValue = targetSizeDp,
    animationSpec = spring(
        dampingRatio = Spring.DampingRatioMediumBouncy,
        stiffness = Spring.StiffnessMediumLow
    ),
    label = "FocusIndicatorSizeAnimation"
)
```

## 4. Composable 結構調整 (Composable Structure)

`FocusIndicator` 需要從內部寫死狀態改為由外部傳入 `FocusTarget`，並應用動態屬性。

**實作範例：**
```kotlin
@Composable
fun FocusIndicator(
    focusTarget: FocusTarget,
    modifier: Modifier = Modifier
) {
    // 1. 動態尺寸與動畫計算
    val targetSizeDp = calculateFocusIndicatorSize(focusTarget.boundingBoxSize)
    val animatedSize by animateDpAsState(
        targetValue = targetSizeDp,
        animationSpec = spring(
            dampingRatio = Spring.DampingRatioMediumBouncy,
            stiffness = Spring.StiffnessMediumLow
        ),
        label = "FocusSize"
    )

    // 2. 中心點位移計算
    val center = focusTarget.center
    val halfSizePx = with(LocalDensity.current) { (animatedSize / 2).toPx() }

    // 3. Canvas 繪製佈局
    Canvas(
        modifier = modifier
            // 強烈建議使用 graphicsLayer 做位移，避免觸發 Compose Layout 產生效能負擔
            .graphicsLayer {
                translationX = center.x - halfSizePx
                translationY = center.y - halfSizePx
            }
            .size(animatedSize) // 套用彈性動畫尺寸
    ) {
        // 繪製範圍現在已自適應 animatedSize
        drawRect(
            color = Color.White,
            style = Stroke(width = 2.dp.toPx())
        )
        // (可追加繪製角落括號 [...] 等視覺樣式)
    }
}
```

## 5. 邊界條件與效能考量 (Edge Cases / Considerations)

1. **極端輸入 (Null 或 Zero Dimensions)**：
   - 當 ML Kit 追蹤丟失 (`null`) 或解析錯誤（長/寬為 `0`）時，系統會穩定回傳 `MIN_FOCUS_SIZE` (`48.dp`)。由於使用了 `animateDpAsState`，對焦框不會突兀閃爍消失或縮小，而是會以 `spring` 彈性動畫平滑收縮回 `48.dp`。

2. **Compose 效能管理 (Composition Performance)**：
   - 由於 ML Kit 更新頻率極高 (30~60 FPS)，若直接改變 `Modifier.offset` 會強制觸發 Compose 的 Measure/Layout 階段，造成無謂的 CPU 消耗。
   - **解法**：如上方範例，必須將平移座標設定於 `Modifier.graphicsLayer { ... }` 區塊內。這種做法僅觸發 Draw 階段，能確保高 FPS 下的渲染順暢。

3. **BoundingBox 數值抖動 (Jittering)**：
   - 連續影格中偵測框的尺寸常有幾像素的抖動。
   - **解法 1 (動畫吸收)**：`spring` 動畫天然具有物理慣性，可吸收高頻的微小抖動。
   - **解法 2 (閾值過濾)**： 若視覺實測發現仍有明顯閃爍，可於 ViewModel 的 setter 加入條件判斷：新舊尺寸差異超過一定閾值 (`abs(new - old) > 2.dp`) 才推播更新。通常解法 1 已足夠滿足大部分情境。
