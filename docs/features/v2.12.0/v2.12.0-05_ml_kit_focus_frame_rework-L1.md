# v2.12.0-05 — ML Kit Focus Frame Rework（L1：高層次技術設計）

## 背景：三個 Bug 與根因摘要

### Bug A：Focus frame always square（對焦框永遠是正方形）
- **現況**：UI `FocusIndicator` 僅接收單一 `focusFrameSizePx`（邊長），渲染時 width=height。
- **影響**：對於長方形 bbox（例如 16:9 後鏡頭、遠距離人臉、細長物件），視覺對焦框與偵測目標不一致，且錯誤的尺寸可能間接影響使用者對「是否對到」的判斷。
- **修正方向**：`CameraState` 應能獨立管理 `focusFrameWidthPx` 與 `focusFrameHeightPx`，UI 動畫改為 `Size(animatedWidth, animatedHeight)`。

### Bug B：`focusFrameSizePx` reset by ML Kit（尺寸被 ML Kit 重置）
- **根因類型**：單一 `focusFrameSizePx`（正方形）造成「尺寸語義不足」：
  - 一旦 ML Kit 的 bbox 更新（或目標切換），尺寸會被重新推導為單一邊長，導致看起來像「被重置」或「被覆寫成預設」。
- **修正方向**：以 Bug A 的資料模型修正（寬高分離）取代單一邊長後，ML Kit 尺寸更新會自然對應到 bbox 的 width/height，減少不必要的隱性覆寫與錯覺重置。

### Bug C：後鏡頭對焦框位置錯誤 + 因 ML Kit target selection 錯誤導致 AF fail
- **現況**：`autoFocusOnSalientTarget()` 會同時把 faces 與 objects 都放進候選池，再用 score 取最大值；在某些場景（後鏡頭、人物 + 背景物件）容易選到「非人臉的高分物件」。
- **影響**：對焦框落在錯誤位置，並把 `startFocusAndMetering()` 打到非主要主體，造成「看似 AF 失敗」或對不到人臉。
- **修正方向**：**Face-first policy**：如果偵測到人臉，僅從 faces 產生候選並選擇；只有當 `faces.isEmpty()` 時才回退到 objects。

---

## 解決方案總覽（Architecture Overview）

核心概念：把「對焦框幾何」變成一個可被狀態管理、可被 ML Kit / User actions 一致更新的結構（width/height + center），並把「自動對焦目標選擇」改成明確的分層策略（faces > objects）。

```mermaid
graph TD
  A[ML Kit DetectionResult<br/>faces + objects + eyePositions] --> B[SalientTargetSelector<br/>Face-first]
  B --> C[TargetGeometryMapper<br/>image-space bbox -> screen-space center + size]
  C --> D[CameraState<br/>focusPoint + focusFrameWidthPx + focusFrameHeightPx]
  D --> E[CameraScreen / FocusIndicator<br/>animate Size(w,h)]
  B --> F[AutoFocusCoordinator]
  F --> G[CameraRepository.focusOnPoint]
  G --> H[CameraX startFocusAndMetering]
```

## 1) `CameraState` 修改（Data Model / Update Semantics）

### 資料模型調整

把單一 `focusFrameSizePx` 改為寬高分離（可保留舊欄位一段時間作 migration，但 UI 改讀新欄位）：

- 新增（或取代）：
  - `focusFrameWidthPx: Float`（0f 代表使用預設值/或表示「未指定」）
  - `focusFrameHeightPx: Float`
- 保留既有：
  - `focusPoint: Pair<Float, Float>?`（screen-space center）
  - `focusIndicatorFading`, `isFocusing`, `focusSuccess`（UI 動畫與淡出狀態）

建議引入一個更清晰的結構（概念級，L2 落地時擇一）：
- `FocusFrameSpec(centerPx: Offset, sizePx: Size, source: FocusFrameSource, tsMs: Long)`
- `FocusFrameSource = USER_TAP | MLKIT_FACE | MLKIT_OBJECT`

### 更新規則（何時更新寬高）

1. **ML Kit 更新（auto-focus 追蹤目標）**
   - 由 target bbox 推導 `widthPx/heightPx`（screen-space）
   - 可套用視覺係數 `k`（例如 1.2~1.6）讓框略大於 bbox，並對 width/height 分別 clamp 到 UI 可接受範圍
2. **User tap 更新（手動點按）**
   - 通常使用固定大小（例如 48dp 對應 px），或根據目前 zoom / mode 設定略微調整
   - 寬高可用同值（正方形）作為 UX 一致性，但仍走同一套資料模型（width=height）
3. **避免高頻抖動（重要）**
   - ML Kit bbox 每次更新可能造成頻繁 state 更新 → Compose 反覆重算與動畫抖動
   - 建議加「最小變更門檻」：
     - `abs(newW - oldW) < epsPx && abs(newH - oldH) < epsPx` 則不更新
   - 或只在 target 切換 / score 明顯變化 / 位置變化超過門檻時更新 size

## 2) `FocusIndicator` 重構（Render + Animate non-square）

### UI API 變更

`FocusIndicator` 從單一 size 改成接收寬高：
- `focusFrameWidthPx`, `focusFrameHeightPx`（或直接傳 `Size`）
- 仍以 `focusPoint` 作為中心定位

### 動畫策略

把原本：
- `animateDpAsState(targetSizeDp)`（單一維度）

改為：
- `animateDpAsState(targetWidthDp)` + `animateDpAsState(targetHeightDp)`（兩軸獨立）
- 最終渲染使用 `Size(animatedWidthPx, animatedHeightPx)`

### Canvas 繪製調整（關鍵差異）

原本使用 `halfSize`（正方形）計算四角 bracket；改為：
- `halfW = size.width / 2`
- `halfH = size.height / 2`
- 四角 bracket 的起點/終點分別以 `halfW/halfH` 計算

> 這可以直接修正 Bug A（永遠是正方形），並且讓「ML Kit 目標框」與 UI 對焦框在幾何上更一致。

## 3) `autoFocusOnSalientTarget()` 重構（Face-first selection）

### 新的高階流程（Face-first with fallback）

```mermaid
flowchart TD
  A[autoFocusOnSalientTarget()] --> B{faces.isNotEmpty()?}
  B -->|Yes| C[Build candidates from faces ONLY]
  B -->|No| D[Build candidates from objects ONLY]
  C --> E[Score + pick best]
  D --> E
  E --> F{score >= threshold?}
  F -->|No| G[return (no AF)]
  F -->|Yes| H[Map bbox/eye point to screen-space]
  H --> I[Update CameraState focusPoint + focusFrame W/H]
  I --> J[Trigger focus (if throttle/state allow)]
```

### Face 候選的焦點選取（eye vs center）

當有 face 時：
- **優先用 eye position**（若 `eyePositions` 可用且品質足夠）作為 focus point（Eye-AF UX）
- 否則 fallback 到 face bbox center

> 這能降低後鏡頭「因 object 得分更高而偏離人臉」的情況，並提升對焦成功率與使用者感知一致性。

### Objects fallback 的限制

只有當 `faces.isEmpty()` 才考慮 objects，避免：
- 人物在畫面中但被背景物件搶焦
- 對焦框/對焦點跳動造成 UI 與 HAL 行為不穩定

## 4) 架構影響評估（Modes / Lenses / Performance）

### Camera modes（拍照/錄影/比例切換）
- 寬高分離的 focus frame 對 modes 本身是低風險變更，但需要確認：
  - 4:3 / 16:9 切換時，bbox->screen mapping 的 scale/letterbox 計算一致
  - 不同 mode 下 focus frame 的 clamp 範圍是否一致（例如 UI 不要超出 preview 區域）

### Front vs Rear lens（鏡頭差異）
- 後鏡頭問題多半與「目標選擇」和「座標轉換」疊加：
  - Face-first 策略先降低選錯目標
  - bbox/eye point 的 mapping 必須正確處理 rotation + mirror（front camera）+ preview scaling
- 建議把「image-space → screen-space」集中成單一 mapper（避免各處自行推導 effectiveImgW/H）

### Performance（效能）
- 寬高分離本身成本極低；風險在於：
  - ML Kit result 高頻更新導致 UI size animation 反覆啟動
- 對策：
  - size/position 更新加 eps 門檻（debounce by delta）
  - 只在「被選中的 target」更新 focus frame（不要每個 bbox 都更新）
  - 保持 `FocusIndicator` 的 draw 計算 O(1)

## 5) 高階測試策略（Verification Plan）

### A. Unit tests（邏輯）
- `SalientTargetSelector`：
  - 有 faces 時永遠不選 objects（face-first）
  - `faces.isEmpty()` 時才會選 objects
  - eyePositions 存在時優先 eye point
- `TargetGeometryMapper`：
  - bbox->screen size/center 在 rotation 90/270 時寬高交換正確
  - front camera mirror 下 centerX 正確（若適用）

### B. UI tests / Screenshot tests（視覺）
- `FocusIndicator`：
  - 非正方形尺寸能正確渲染（長方形 bracket 不變形）
  - 寬高動畫能平滑過渡且不抖動（搭配 eps 門檻）

### C. Integration / Device QA（端到端）
- Rear lens + 人物前景 + 背景大物件：確認 focus point 不再跳到物件、對焦成功率提升
- Face-only / Object-only 場景：fallback 行為正確
- 4:3 / 16:9 切換、前後鏡頭切換：focus frame 不跑位、不縮回正方形、不被「重置」
