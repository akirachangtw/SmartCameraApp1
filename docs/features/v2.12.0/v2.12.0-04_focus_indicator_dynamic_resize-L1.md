# v2.12.0-04 FocusIndicator 動態縮放（對話存檔）

## 目標
在既有 Jetpack Compose `FocusIndicator`（Canvas）目前硬編碼 `48.dp` 的前提下，整合 ML Kit 的 `bounding box` 資料（`android.graphics.Rect` / `Size` 等），讓對焦框尺寸能依 bbox 動態縮放於 `48.dp`～`120.dp`，且尺寸變化以 `spring` 動畫平滑過渡（彈性效果）。

---

## 既有程式碼脈絡（來自 L0 摘要）
- `FocusIndicator` 是 `CameraScreen.kt` 的 `@Composable` private 函式，目前透過 `state.focusPoint` 傳入 `(x,y)`（screen-space px），尺寸在 Canvas draw scope 中硬編碼以 `48.dp.toPx()` 作為對焦框正方形邊長。
- ML Kit bbox 目前在 `CameraViewModel.updateTrackedObjectPosition()` 中只取 `boundingBox.exactCenterX/Y()` 轉成 screen-space 後存入 `focusPoint`，bbox 寬高資訊未進入 UI。
- 目標是把 bbox 的「大小」也帶到 UI，並驅動 `FocusIndicator` 的「Canvas 佈局尺寸」動態變更。

---

## 高層次解決方案規劃（助理回覆）

### 1) ML Kit bbox 如何整合進 Composable（資料流/架構）
- **Analyzer/Detector 層**：每幀產出偵測結果（含 `boundingBox`、`imageWidth/Height`、tracking id 等）。
- **ViewModel 層（Single Source of Truth）**：
  - 將 `boundingBox`（image-space）轉換成 **screen-space** 的：
    - 中心點（用於定位對焦框）
    - 寬高（用於推導對焦框目標尺寸）
  - 寫入 `CameraState`，避免只存 `focusPoint` 而丟失 bbox 尺寸。
- **UI/Compose 層**：
  - `CameraScreen` 讀取 `state.focusTarget`（或 `state.focusBox`），把「中心點 + 目標尺寸」交給 `FocusIndicator`。
  - `FocusIndicator` 改為接受動態 `targetSizeDp`（或 `targetSizePx`），並用動畫後的 size 驅動 `Canvas` 的 `Modifier.size(...)`。

建議 state 形狀（概念級，擇一）：
- `focusCenterPx: Offset` + `focusBoxSizePx: Size?`
- `focusRectPx: Rect`（screen-space rect，中心點與寬高都可從中推得）

---

### 2) 從 bbox 計算目標對焦框尺寸（48–120dp，含 clamp）
核心原則：**先把 bbox 尺寸統一到 screen-space px**，再推導 indicator 的「正方形邊長」，最後 `coerceIn(48.dp, 120.dp)`。

**做法 A：直覺對應 bbox（以最大邊為主）**
1. `bboxMaxPx = max(boxWidthPx, boxHeightPx)`（screen px）
2. 加上視覺係數 `k`（例如 0.6～1.0）避免框太大：`rawPx = bboxMaxPx * k`
3. `rawDp = rawPx.toDp(density)`
4. `targetDp = rawDp.coerceIn(48.dp, 120.dp)`

**做法 B：以比例映射到範圍（更穩定）**
1. `fraction = clamp(bboxMaxPx / previewMaxPx, 0..1)`（`previewMaxPx` 可為預覽容器的寬/高的某個代表值）
2. `targetDp = lerp(48.dp, 120.dp, fraction)`
3. 可選：對 `fraction` 做非線性（如 sqrt 或 S-curve）降低跳動（高層先不強制，視效果再加）

邊界/例外（高層規則）：
- bbox 不存在或追蹤失效：`targetDp = 48.dp`（或維持上一值後淡出）
- bbox 抖動：優先讓 `spring` 承擔平滑；必要時加閾值（例如變化 < 2.dp 不更新）

---

### 3) 將計算後尺寸動態套用到 Compose Canvas
- 由 `CameraScreen`/`FocusIndicator` 取得 `targetSizeDp`。
- `FocusIndicator` 以 `Modifier.size(animatedSizeDp)` 控制 Canvas 寬高（重點：改變「佈局尺寸」，而不是只在 draw 裡改一個常數）。
- 使用既有 `x,y`（screen-space px）做置中定位：
  - 若用 `Modifier.offset { IntOffset(...) }`：用 `animatedSizeDp.toPx()` 計算 half size，將 Canvas 左上角放到 `(x - half, y - half)`。
  - 或改用 `graphicsLayer { translationX/Y }` 也可；同樣以 half size 置中。

---

### 4) `spring` 動畫：尺寸在 48→120dp 平滑彈性過渡
兩種策略（擇一，皆符合高層需求）：

**策略 A：`animateDpAsState`（最簡單）**
- `val animatedSize by animateDpAsState(targetValue = targetDp, animationSpec = spring(...))`
- 適合 target 由 state 推導且頻繁更新的情境，Compose 自動銜接動畫。

**策略 B：`Animatable`（可控性更高）**
- `val sizeAnim = remember { Animatable(48.dp, Dp.VectorConverter) }`
- `LaunchedEffect(targetDp) { sizeAnim.animateTo(targetDp, spring(...)) }`
- 適合需要更精細控制：取消/重啟策略、不同狀態套不同 spring 參數、額外濾波等。

`spring` 參數方向（概念級）：
- 偏「快速收斂、些微回彈」：中等 stiffness、medium/low dampingRatio，讓 bbox 更新時視覺呈現彈性跟隨。

---

## 建議的端到端流程（濃縮版）
1. ML Kit 每幀產生 `boundingBox (image-space Rect)` → VM 挑選要追的 bbox（face/object）。
2. VM 用既有 `CoordinateTransformer` 把 bbox **中心點 + 寬高**轉到 **screen-space px**。
3. VM 寫入 `CameraState.focusTarget`（包含 `centerPx` + `boxSizePx` 或 `rectPx`）。
4. UI 從 `focusTarget` 推導 `targetSizeDp`（比例映射或直接對應 bbox），並 `coerceIn(48.dp, 120.dp)`。
5. `FocusIndicator` 用 `spring` 動畫把 `Canvas Modifier.size()` 從舊值平滑彈到新值，並用 `x,y` 對齊置中繪製。
