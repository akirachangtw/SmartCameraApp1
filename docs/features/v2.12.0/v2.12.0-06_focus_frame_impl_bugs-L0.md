## Bug D — 後鏡頭 size 在 postLockCooldown 期間固定 48dp

### 症狀
- 後鏡頭對焦人臉成功後，對焦框立即收縮為固定 48dp 正方形
- 整個 5s postLockCooldown 期間 + 下一次觸發前，框一直是 48dp

### 根本原因（三步連鎖）

```
Step 1: focus 成功 → afState = AfState.Locked（永遠不自動回到 Idle）
Step 2: 1s 後 dwell fade → focusFrameWidthPx = 0f, focusFrameHeightPx = 0f（主動重置）
Step 3: autoFocusOnSalientTarget() → currentState.afState is AfState.Locked
        → `!is Locked` 條件擋住 size update → size 永遠無法更新

後果: 5s postLockCooldown + 直到下次 focusOnPoint 完成前 = 框一直是 48dp
```

### 觸發條件
- 任何成功對焦的後鏡頭（transformer 非 null）
- 與 Bug B 原始問題互斥（Bug B 是 transformer=null 的前鏡頭）

### 影響範圍
- `CameraViewModel.kt:1348–1355`（size update condition）

## Bug E — close-up 近拍時框退化為正方形

### 症狀
- 人臉佔畫面 > 35% 時，對焦框變成正方形（通常 200dp × 200dp）
- 非正方形效果只在中遠距拍攝（人臉 < 25% 畫面）才生效

### 根本原因

```kotlin
// FocusIndicator 目前實作：獨立 coerceIn 各軸
val targetWidthDp  = focusWidthPx.toDp().coerceIn(48.dp, 200.dp)   // 303dp → 200dp
val targetHeightDp = focusHeightPx.toDp().coerceIn(48.dp, 200.dp)  // 402dp → 200dp
// W = H = 200dp → 正方形！
```

例：Sony XQ-BT52（密度 2.75x），人臉 bbox = Rect(98,119-345,365) in 480×640 image:
- screen frame after 1.5x = 833.6 × 1107.0px → 303dp × 402dp
- 兩軸均超過 200dp → 各自截斷到 200dp → 正方形

### 觸發條件
- 任何一軸 screen-space 尺寸 > 200dp（即 549px on 2.75x）
- 高密度螢幕（>2x）+ 近距離人臉最易觸發

### 影響範圍
- `CameraScreen.kt:706–724`（FocusIndicator size 計算）

## Bug F — 後鏡頭 ML Kit 追蹤模式下「一直處著對焦狀態」

### 症狀
- 後鏡頭 Eye-AF 觸發後，進入 ML Kit tracking mode（isTracking=true）
- Indicator 持續顯示搜尋動畫（isFocusing=true），使用者感覺永遠在對焦

### Log 證據
```
findTappedTarget: tapped face trackingId=60
ML Kit tracking started: ID=60, type=FACE
FocusClamp: isFocusing=true, isTracking=true
FocusClamp: LaunchedEffect(isFocusing=true, isLocked=false) triggered
```

### 根本原因（假說，待確認）

`autoFocusOnSalientTarget()` 呼叫 `focusOnPoint(isUserTap=false)` 時：
- `findTappedTarget()` 找到人臉 → 進入 ML Kit tracking path
- ML Kit tracking mode：`enteredMLKitTrackingMode=true` → 跳過 dwell fade → indicator 永遠不淡出
- 每次 postLockCooldown 到期（5s），Eye-AF 重新觸發 → isFocusing=true 短暫閃現
- 使用者觀感：indicator 不停在搜尋動畫與鎖定動畫之間切換

### 影響範圍
- `CameraViewModel.kt:autoFocusOnSalientTarget()`（Eye-AF → ML Kit tracking 路徑）
- 可能需要區分「使用者主動 tap」和「Eye-AF 自動觸發」的 tracking 行為

### 優先度
- Low（功能性問題，非崩潰）
- 本 session 暫不修正，記錄為已知問題

## 潛在風險

1. **Bug D 修正引入新問題**：若放寬 size update 條件，可能在 Locked 期間 size 仍每幀更新（原始 Bug B 前鏡頭問題復發）。需要精確的條件：「有真實尺寸（>0f）就更新；只有新尺寸是 0f 且 Locked 時才擋」

2. **Bug E 比例縮放影響最小尺寸保護**：比例縮放後，若 W 縮到 < 48dp，需要確保兩軸都至少 48dp，但不能因此破壞比例

3. **Bug F 修正可能影響主動 Tap-to-Track**：autoFocusOnSalientTarget 的 ML Kit tracking 進入邏輯若改變，需確保使用者 Tap 的 tracking 行為不受影響
