# v2.12.0-07 — Native Camera Experience Repli（L1：架構規劃摘要）

目的：針對三個問題建立「可模組化、可擴充、可漸進導入」的高層次架構規劃，並描述與 Android 相機 API（以 CameraX 為主，保留 Camera2 fallback 的空間）及 ML/影像分析管線的整合方式。

## 一、問題與對應解法（Scope）

1. **Front Camera Focus UI Smoothness**
   - 解法：**UI 解耦 + 座標平滑化**（不要讓 UI 直接追 raw bbox/landmark）。
2. **Face Focus — No Constant Scanning**
   - 解法：**具備防抖（movement tolerance）+ timeout/backoff 的人臉智能對焦策略**（只在「必要」時觸發對焦）。
3. **Object Focus — Precise Object Tracking**
   - 解法：**AI 物件偵測 + 追蹤（tracking）+ 動態 bbox 繪製**，並把結果餵給對焦/測光（metering）策略。

---

## 二、設計原則（Modularity First）

- **分層清楚**：UI（顯示/互動）≠ Focus/Tracking 策略（domain）≠ Camera API（device control）≠ Image/ML（analysis）。
- **單向資料流**：frame → analysis → target state → policy → camera control；UI 只訂閱「已整理過」的狀態。
- **可替換元件**：Face/Object detector 可替換（ML Kit / 自研模型）；Tracker 可替換（trackingId / Optical Flow）。
- **漸進導入**：每個子策略都可獨立開關（feature flags），避免一次大改動造成回歸。

---

## 三、目標架構（High-level Components）

```mermaid
flowchart LR
  subgraph CameraLayer[Camera Layer]
    CX[CameraX UseCases\nPreview + ImageAnalysis] --> CCA[CameraControlAdapter\n(startFocusAndMetering)]
  end

  subgraph AnalysisLayer[Analysis Layer]
    IA[Frame Dispatcher\n(backpressure/throttle)] --> FD[FaceDetector (ML Kit)]
    IA --> OD[ObjectDetector (ML Kit / model)]
    FD --> TState[RawTargetState]
    OD --> TState
    TState --> TRK[TargetTracker\n(trackingId / OpticalFlow)]
    TRK --> MAPPER[CoordinateTransformer\n(image->screen)]
  end

  subgraph DomainLayer[Domain / Policy Layer]
    MAPPER --> TARGET[TargetStateStore\n(smoothed + validated)]
    TARGET --> FP[FaceFocusPolicy\n(tolerance/timeout/backoff)]
    TARGET --> OP[ObjectFocusPolicy\n(dynamic metering region)]
    FP --> ORCH[FocusOrchestrator]
    OP --> ORCH
    ORCH --> CCA
  end

  subgraph UiLayer[UI Layer (Compose)]
    TARGET --> UISTATE[CameraUiState]
    UISTATE --> FI[FocusIndicator / OverlayRenderer]
  end
```

### 主要模組責任（責任分配）

- `FrameDispatcher`：控制 analysis 頻率、背壓（backpressure）、時間戳對齊（避免舊 frame 造成 UI/對焦回跳）。
- `FaceDetector` / `ObjectDetector`：輸出 image-space 的 bbox/landmarks + 可信度。
- `TargetTracker`：把「偵測」延伸成「追蹤」；偵測可低頻，追蹤可高頻（更平滑、更即時）。
- `CoordinateTransformer`：統一處理 rotation/mirror/letterbox，提供 image→screen 的 mapping（單一真相來源）。
- `TargetStateStore`：保存「當前 target」的**穩定座標/尺寸**（包含平滑、遺失處理、時間戳）。
- `FaceFocusPolicy` / `ObjectFocusPolicy`：決定何時觸發對焦、用什麼 metering region、何時鎖定/解鎖。
- `FocusOrchestrator`：把 policy 的決策轉成 Camera API 行為（start/cancel、timeout、結果分類）。
- `CameraControlAdapter`：封裝 CameraX（或 Camera2）對焦/測光呼叫，隔離 API 細節與裝置差異。
- `OverlayRenderer (FocusIndicator)`：只負責呈現（動畫/淡出/視覺），不包含「何時要對焦」的決策。

## 四、逐解法的組件、整合步驟、互動方式

### A. UI 解耦：Front Camera Focus UI Smoothness

**核心想法**：UI 不直接追 ML Kit bbox；而是訂閱 `TargetStateStore` 產出的 `UiFocusFrame`（已平滑、已映射到 screen-space、已 clamp）。

**主要組件**
- UI：`FocusIndicator`（Compose）、`OverlayRenderer`
- Domain：`FocusUiSmoother`（例如 EWMA/OneEuro）、`UiFrameComposer`（把 target 轉成 UI frame）
- Shared：`CoordinateTransformer`（mirror/rotation/preview scale）

**整合步驟**
1. 建立 `TargetStateStore`，分成兩份資料：`rawTarget`（detector 輸出）與 `stableTarget`（tracker+smoother 輸出）。
2. `FocusUiSmoother` 只處理 UI 所需的 `center + size`，並可依 target 類型（FACE/OBJECT）套不同參數。
3. UI 改訂閱 `CameraUiState.uiFocusFrame`（不是 raw bbox），並將「淡出/持續顯示」的生命週期與對焦 coroutine 解耦。

**互動方式（事件流）**
- Detector/Tracker 更新 `TargetStateStore` → `CameraUiState` 更新 → `FocusIndicator` 以 animation 呈現；對焦策略失敗/取消不應直接清空 UI（除非 target 丟失超過 TTL）。

**依賴/風險**
- 前鏡頭 mirror 若處理錯誤，平滑會掩蓋問題；因此 `CoordinateTransformer` 必須先成為單一可信 mapping。

---

### B. 人臉智能對焦：No Constant Scanning（tolerance + timeout/backoff）

**核心想法**：把「偵測到人臉」與「觸發對焦」拆開；人臉存在時只在「位移超過容忍、鎖定過期、或品質下降」時才觸發對焦。

**主要組件**
- Analysis：`FaceDetector (ML Kit Face Detection)`（可輸出 bbox + landmarks/eyes）
- Domain：`FaceFocusPolicy`、`AfStateMachine`（或同等狀態機）、`AfTriggerThrottleController`（節流/退避）、`StabilityTracker`
- Camera：`CameraControlAdapter`（focus+metering、timeout、cancel）

**關鍵策略（高層）**
- `movementTolerancePx`：小幅抖動不觸發 refocus（防抖）。
- `lockHoldMs`：成功後至少保持一段時間不重掃（避免常態掃描）。
- `focusTimeoutMs`：單次 action 超時後分類為 `TimedOut`，交給 backoff（而不是無限重試）。
- `qualityGate`：可選，用 face size / confidence 判斷「是否值得 refocus」。

**整合步驟**
1. `FaceDetector` 輸出 → `TargetStateStore` 產出 `stableFaceTarget`（含時間戳、位移量、可信度）。
2. `FaceFocusPolicy` 以 `stableFaceTarget` + `AfStateMachine` 狀態判斷是否觸發 `FocusRequest`。
3. `FocusOrchestrator` 對 `FocusRequest` 進行：
   - 合併/去重（相同 target 不重複觸發）
   - 套用 `timeout` 與 `cooldown/backoff`
   - 將結果回寫至狀態機（Locked/Failed/Cooldown）

**互動方式（避免常態掃描）**
- UI 可持續顯示 face frame（平滑後），但 Camera API 的 focus action 只在 policy 允許時觸發。

**依賴/風險**
- 裝置 HAL 差異：成功/失敗回報語義可能不同，`CameraControlAdapter` 應集中做結果分類與相容策略。

---

### C. 物件對焦：Precise Object Tracking（AI detection + tracking + dynamic bbox）

**核心想法**：用 AI 偵測做「初始化與校正」，用追蹤做「高頻更新與穩定」，同時輸出動態 bbox（給 overlay）與動態 metering region（給 focus）。

**主要組件**
- Analysis：
  - `ObjectDetector`：ML Kit Object Detection（含 `trackingId` 的情境優先用）
  - `TargetTracker`：trackingId-based tracker；必要時加上 `OpticalFlowTracker` 做補強（偵測低頻、追蹤高頻）
- Domain：
  - `ObjectFocusPolicy`：根據 bbox 尺寸/移動量決定 metering 區域與 refocus 時機
  - `MeteringRegionEstimator`：由 bbox 推導 metering size（小物件→小區域，大物件→大區域，並 clamp）
- UI：`OverlayRenderer` 依 `UiFocusFrame` 繪製「跟著物件變形」的方框

**整合步驟**
1. Detector 提供 bbox + `trackingId` → `TargetTracker` 維持 current object（丟失時進入 grace period，避免 UI 閃爍）。
2. `CoordinateTransformer` 將 bbox corners 映射到 screen-space，得到可旋轉/可變形的 `UiFocusFrame`（至少支援 W/H 動態）。
3. `ObjectFocusPolicy` 以 bbox 面積比例/中心位移決定：
   - 是否觸發 focus
   - metering region size（例如 0.08–0.35 of long edge 的 fraction）

**互動方式（雙輸出）**
- 同一份 `stableObjectTarget` 同時驅動：
  - Overlay：高頻更新 frame（視覺跟手）
  - Focus：低頻觸發 metering action（避免 HAL 過載）

**依賴/風險**
- ML 偵測耗時：需搭配 `FrameDispatcher` 節流，並避免 detector 舊結果覆蓋 tracker 新狀態（時間戳檢查）。

---

## 五、資料模型與介面（建議形狀）

- `RawTargetState`：`type(FACE/OBJECT)`, `bbox(image-space)`, `confidence`, `trackingId?`, `timestamp`
- `StableTargetState`：`center(screen)`, `size(screen)`, `velocity`, `lostSinceMs`, `timestamp`
- `UiFocusFrame`：`centerX/Y`, `width/height`, `rotation?`, `alpha`, `style(type-based)`
- `FocusRequest`：`meteringPoint`, `meteringRegionSize`, `reason(moved/timeout/userTap)`

這些資料模型讓 UI/Policy/CameraControl 可以用「同一套語意」互動，但不必共享 detector/CameraX 的細節。

---

## 六、依賴與導入順序（避免跨層爆炸）

1. **先收斂座標系**：`CoordinateTransformer` 成為唯一 mapping，並加入基本驗證（front mirror/rotation）。
2. **再做 UI 解耦 + 平滑**：先讓視覺穩定，便於驗證後續策略。
3. **再上 FaceFocusPolicy（tolerance/timeout/backoff）**：只改「觸發邏輯」，不動 UI。
4. **最後上 Object tracking + dynamic metering**：同時產出 bbox（給 UI）與 metering region（給對焦）。

以上每一步都應能以 feature flag 獨立開關，降低回歸風險並便於 A/B。
