## 1. 統一碰撞偵測與目標解析 (Unified Hit-Test & Target Resolution)

為解決同一個點擊事件因為邏輯分散而導致的不一致問題，我們將引入 `resolveTapTarget` 函式，作為唯一且標準的點擊分類器。

### 資料結構定義 (`TapTargetInfo`)
利用 Kotlin 的 `sealed class` 嚴格定義點擊目標的分類，確保後續處理時編譯器能強制涵蓋所有情境 (Exhaustive `when`)：

```kotlin
sealed class TapTargetInfo {
    // 點擊到 ML Kit 識別的人臉
    data class Face(val trackingId: Int?, val rectPx: RectF) : TapTargetInfo()
    // 點擊到 ML Kit 識別的物件
    data class Object(val trackingId: Int?, val rectPx: RectF) : TapTargetInfo()
    // 點擊到空白處 (泛型對焦)
    data class Generic(val pointPx: PointF) : TapTargetInfo()
}

// (輔助類別假設)
sealed class MLKitTarget {
    abstract val boundingBox: RectF
    abstract val trackingId: Int?
    data class FaceTarget(override val boundingBox: RectF, override val trackingId: Int?) : MLKitTarget()
    data class ObjectTarget(override val boundingBox: RectF, override val trackingId: Int?) : MLKitTarget()
}
```

### 碰撞偵測演算法實作 (Pseudo-code)
碰撞邏輯遵循「Face-First Policy」，並在重疊目標中選擇「中心點距離點擊處最近」的 Target，增進 UX 準確度。

```kotlin
fun resolveTapTarget(
    x: Int, 
    y: Int, 
    currentMLKitTargets: List<MLKitTarget>
): TapTargetInfo {
    val tapPoint = PointF(x.toFloat(), y.toFloat())
    
    // 1. 優先檢查是否點擊到「人臉」(Face-First Policy)
    val faces = currentMLKitTargets.filterIsInstance<MLKitTarget.FaceTarget>()
    val tappedFace = faces.minByOrNull { face ->
        if (face.boundingBox.contains(tapPoint.x, tapPoint.y)) {
            // 計算點擊點與 Bbox 中心的距離，若有多張臉重疊，選距離最近的
            val centerX = face.boundingBox.centerX()
            val centerY = face.boundingBox.centerY()
            hypot((centerX - tapPoint.x).toDouble(), (centerY - tapPoint.y).toDouble())
        } else {
            Double.MAX_VALUE // 排除未碰撞的目標
        }
    }
    
    if (tappedFace != null && tappedFace.boundingBox.contains(tapPoint.x, tapPoint.y)) {
        return TapTargetInfo.Face(tappedFace.trackingId, tappedFace.boundingBox)
    }

    // 2. 退避檢查是否點擊到「物件」
    val objects = currentMLKitTargets.filterIsInstance<MLKitTarget.ObjectTarget>()
    val tappedObject = objects.minByOrNull { obj ->
        if (obj.boundingBox.contains(tapPoint.x, tapPoint.y)) {
            val centerX = obj.boundingBox.centerX()
            val centerY = obj.boundingBox.centerY()
            hypot((centerX - tapPoint.x).toDouble(), (centerY - tapPoint.y).toDouble())
        } else {
            Double.MAX_VALUE
        }
    }

    if (tappedObject != null && tappedObject.boundingBox.contains(tapPoint.x, tapPoint.y)) {
        return TapTargetInfo.Object(tappedObject.trackingId, tappedObject.boundingBox)
    }

    // 3. 兩者皆未命中，視為點擊空白處 (Generic Tap)
    return TapTargetInfo.Generic(tapPoint)
}
```

## 2. 明確目標狀態重置與預設框 (Explicit Target State Reset & Default Box)

目前 `Generic Tap` 容易因為狀態覆蓋或 sentinel 值 (`0f`) 而導致對焦框渲染異常。我們將固定泛型點擊時的物理尺寸，並徹底重置 `FocusUiSmoother` 的濾波器。

### 尺寸定義與構建實作

```kotlin
// 定義預設的泛型對焦框尺寸為 72.dp
val DEFAULT_TAP_BOX_SIZE_DP = 72.dp

/**
 * 處理 Generic Tap，建構明確尺寸的 Rect 並傳遞給 UI。
 */
fun handleGenericTap(tapInfo: TapTargetInfo.Generic, density: Density) {
    // 1. 轉換 dp 為 pixel
    val boxSizePx = with(density) { DEFAULT_TAP_BOX_SIZE_DP.toPx() }
    val halfSize = boxSizePx / 2f
    
    // 2. 以點擊坐標為中心，建構出完整的預設對焦 RectF
    val newDefaultRect = RectF(
        tapInfo.pointPx.x - halfSize,
        tapInfo.pointPx.y - halfSize,
        tapInfo.pointPx.x + halfSize,
        tapInfo.pointPx.y + halfSize
    )
    
    // 3. 顯式地將新的 Rect 推入 UI 平滑器。
    // 重要：設定 resetFilter = true，代表這是一個強制介入的全新坐標，
    // 必須清除先前的 EMA 或 One-Euro 濾波殘留，防止對焦框從原本目標「緩慢飄移」到新點，應改為「瞬間閃現並重繪」。
    focusUiSmoother.setTargetRect(newDefaultRect, resetFilter = true)
}
```

## 3. UI 渲染與前鏡頭硬體繞道解耦 (Decouple Front Camera UI from Hardware Bypass)

過去因為前鏡頭可能是泛焦 (Fixed Focus)，觸發 AF 時底層會直接回報或跳過，同時錯誤地使「UI 也放棄更新對焦框」。我們要實行 **「硬體 AF Bypass ≠ UI Bbox Bypass」**。

### 多執行緒與相容性實作

```kotlin
fun executeFocusAction(
    tapInfo: TapTargetInfo, 
    cameraCapabilities: CameraCapabilities,
    coroutineScope: CoroutineScope
) {
    // 1. 【永不 Bypass UI】：不論硬體能力如何，ML Kit Bbox / Generic Rect 必須進入 UI 管線
    val targetRect = when (tapInfo) {
        is TapTargetInfo.Face -> tapInfo.rectPx
        is TapTargetInfo.Object -> tapInfo.rectPx
        is TapTargetInfo.Generic -> calculateDefaultRect(tapInfo.pointPx)
    }
    
    // 考慮到 ML Kit 分析可能在背景 Thread 發生，
    // 必須切換到 Main Thread (Dispatchers.Main) 刷新 UI StateFlow，確保 Compose 正常重繪不引發 Exception。
    coroutineScope.launch(Dispatchers.Main) {
        val isNewTarget = (tapInfo is TapTargetInfo.Generic) // 可擴充為辨識 trackingId 改變
        focusUiSmoother.setTargetRect(targetRect, resetFilter = isNewTarget)
    }

    // 2. 【硬體 AF Bypass 分流】：根據鏡頭對焦能力決定下放給 CameraX 的 Flag。
    val factory = SurfaceOrientedMeteringPointFactory(previewWidth, previewHeight)
    val point = factory.createPoint(targetRect.centerX(), targetRect.centerY(), targetRect.width())

    if (cameraCapabilities.isFixedFocus) {
        // [精準修改]: 僅省略 FLAG_AF。
        // Fixed-Focus 鏡頭雖然不能調節焦距，但依然能根據點擊區域調節曝光 (AE) 與白平衡 (AWB)。
        val meteringAction = FocusMeteringAction.Builder(
            point, 
            FocusMeteringAction.FLAG_AE or FocusMeteringAction.FLAG_AWB
        ).build()
        
        cameraControl.startFocusAndMetering(meteringAction)
        Log.d("FocusOrchestrator", "Hardware AF Bypassed (Fixed-Focus). Sent AE/AWB intent only.")
        
        // 此處可直接觸發 UI 的 "FOCUSED" 狀態顏色指示，不需等待底層 AF Timeout。
    } else {
        // 一般鏡頭：標準 AF + AE + AWB 測光程序
        val focusAction = FocusMeteringAction.Builder(
            point, 
            FocusMeteringAction.FLAG_AF or FocusMeteringAction.FLAG_AE or FocusMeteringAction.FLAG_AWB
        ).build()
        
        cameraControl.startFocusAndMetering(focusAction)
    }
}
```

### 技術重點回顧
1. **多執行緒防護**：UI 的 Rect 刷新被明確框列在 `Dispatchers.Main`，防止 Camera Controller 的背景回呼污染主要線程。
2. **曝光保留**：即使 Fixed Focus 不能 AF，上述實作證明了傳遞 `FLAG_AE` 依然能保證點擊對焦時最核心的**觸控測光效果 (Touch Metering)** 不喪失。
