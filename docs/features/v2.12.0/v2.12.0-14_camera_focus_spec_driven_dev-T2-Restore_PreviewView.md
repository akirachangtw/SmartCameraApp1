# [T2][v2.12.0-14] Restore PreviewView on Release Build — USE_PREVIEWVIEW_DISPLAY + Metering Fallback 警告強化

## 背景與根因

根據 GPT5.4 架構審查（`file:docs/features/v2.12.0/v2.12.0-14_camera_focus_spec_driven_dev-GPT5.4.md`），真機 release build 目前 `USE_PREVIEWVIEW_DISPLAY = false`，導致 device path 走 bitmap fallback（`ContentScale.Crop`），而非正確的 `PreviewView + FIT_CENTER` 路徑。

這使得以下四個幾何真相**不一致**：
- UI 框位置（overlay）
- 使用者點擊位置（tap）
- CameraX metering point（HAL）
- Optical Flow 追蹤起始點（OF）

### 現況確認

| 項目 | Debug Build | Release Build |
|------|-------------|---------------|
| `USE_PREVIEWVIEW_DISPLAY` | ✅ `true`（v2.10.0 已開啟） | ❌ `false`（仍關閉） |
| `PreviewViewportContainer` | ✅ 已存在，正確計算 `contentBounds` | ✅ 已存在 |
| `LiveCameraSource.meteringPointFactory` | ✅ 使用 `PreviewView.meteringPointFactory` | ⚠️ `previewView == null` 時靜默退回 legacy |

## 精確修改說明

### 修改 1：`app/build.gradle.kts` — 開啟 release build 的 PreviewView

找到第 92-94 行：
```kotlin
// v2.8.6 Phase 2: PreviewView migration for Graphics memory fix (disabled in release for now)
buildConfigField("Boolean", "USE_PREVIEWVIEW_DISPLAY", "false")
```

改為：
```kotlin
// v2.12.0-14: Enabled for release — geometry truth aligned with debug build
buildConfigField("Boolean", "USE_PREVIEWVIEW_DISPLAY", "true")
```

### 修改 2：`LiveCameraSource.kt` — 強化 metering fallback 警告

找到 `previewView == null` 的 fallback 路徑（第 671-673 行附近）：
```kotlin
Log.w(TAG, "[v2.11.1 P0-1] PreviewView not set - using legacy factory (letterbox not handled)")
```

改為：
```kotlin
Log.e(TAG, "[v2.12.0-14] CRITICAL: PreviewView not set — metering point uses legacy SurfaceOrientedFactory (letterbox NOT handled). Focus accuracy degraded.")
```

（將 `Log.w` 升級為 `Log.e`，並更新訊息標記版本號，方便 Logcat 過濾）
