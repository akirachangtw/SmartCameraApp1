## Fix D — 後鏡頭 postLockCooldown 期間 size 固定 48dp

### 問題條件精確化

| 狀態 | transformer | 期望行為 |
|------|------------|---------|
| afState = Locked, transformer 非 null | focusWidthPx > 0 | **應更新** — 後鏡頭有真實尺寸，追蹤人臉 bbox |
| afState = Locked, transformer = null | focusWidthPx = 0 | **不應更新** — 前鏡頭 Bug B：用 0 覆蓋上次的有效尺寸 |
| afState ≠ Locked | 任意 | **應更新** — Idle/Focusing/Failed 均即時更新 |

### 修正方案

```kotlin
// 舊條件（過於嚴格，後鏡頭在 Locked 期間也被擋）：
if (currentState.afState !is AfState.Locked) { update }

// 新條件（精確 Bug B 範圍：只擋 Locked + 新尺寸為 0f 的情境）：
if (focusWidthPx > 0f || focusHeightPx > 0f || currentState.afState !is AfState.Locked) {
    _state.update { it.copy(focusFrameWidthPx = focusWidthPx, focusFrameHeightPx = focusHeightPx) }
}
```

**邏輯說明**:
- `focusWidthPx > 0f`（transformer 非 null）→ 有真實尺寸 → **永遠更新**
- `focusWidthPx == 0f` && `afState is Locked` → 前鏡頭 Locked 期間 → **擋住**（Bug B）
- `focusWidthPx == 0f` && `afState !is Locked` → Idle/Failed 狀態無尺寸 → **允許**（正常重置）

## Fix E — close-up 近拍時比例縮放替代獨立 coerceIn

### 修正目標

保持非正方形比例，同時限制最大顯示尺寸不超過合理範圍。

### 修正方案（FocusIndicator）

```kotlin
// 舊實作（獨立截斷，破壞比例）：
val targetWidthDp  = focusWidthPx.toDp().coerceIn(48.dp, 200.dp)
val targetHeightDp = focusHeightPx.toDp().coerceIn(48.dp, 200.dp)

// 新實作（比例縮放後再截下限）：
val rawWidthDp  = if (focusFrameWidthPx  > 0f) with(density) { focusFrameWidthPx.toDp()  } else 48.dp
val rawHeightDp = if (focusFrameHeightPx > 0f) with(density) { focusFrameHeightPx.toDp() } else 48.dp
val maxDp = 200.dp
val minDp = 48.dp
// 若任一軸超過 maxDp，等比縮小到 maxDp（保持 W:H 比例）
val scaleFactor = if (maxOf(rawWidthDp, rawHeightDp) > maxDp) {
    maxDp / maxOf(rawWidthDp, rawHeightDp)
} else 1f
val targetWidthDp  = (rawWidthDp  * scaleFactor).coerceAtLeast(minDp)
val targetHeightDp = (rawHeightDp * scaleFactor).coerceAtLeast(minDp)
```

**例：人臉 close-up**
- 輸入：833.6 × 1107.0px → rawW = 303dp, rawH = 402dp
- maxOf = 402dp > 200dp → scaleFactor = 200/402 = 0.498
- 結果：303 × 0.498 = 151dp × 200dp ← 保持 0.755 比例 ✓

**例：中距離人臉**
- 輸入：378.0 × 499.5px → rawW = 137dp, rawH = 181dp
- maxOf = 181dp < 200dp → scaleFactor = 1.0
- 結果：137dp × 181dp（不受影響）✓

## Bug G（補充新發現）— 對焦框位置/尺寸未正確包覆物件

### 症狀（v2.12.0-06 實機測試）
- 物件（白色牙線盒）被 ML Kit 偵測，但對焦框**未將物件框起來**
- 框的位置或尺寸與物件的實際螢幕位置不符

### 可能原因（待 logcat 確認）
1. **Coordinate mapping 錯誤**：`transformer.imageToScreen()` bbox 角點轉換有誤（Left/Top 和 Right/Bottom 用同一次 call 的 y 值混用）
2. **Scale factor 1.5x 方向誤算**：W 和 H 分開計算後各自 × 1.5，沒問題；但若 transformer 在 portrait/landscape 旋轉後座標軸交換，可能 W/H 互換
3. **前後鏡頭座標系差異**：前鏡頭鏡像翻轉後，imageToScreen 的 X 軸方向不同

### 需要的 logcat 資訊
```
Smart Subject Focus: image=(x, y), screen=(x, y), frame=WxHpx
```
以及同時期的 `face bbox` 尺寸，計算一致性。

### 優先度
- Medium（功能性問題，影響使用體驗）
- 需要更多 log 後確認是否與 Bug E 同一根源
