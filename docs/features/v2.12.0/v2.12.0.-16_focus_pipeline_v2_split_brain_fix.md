## User Request

The user requested an "Epic Surgery" to eliminate the split-brain state where the legacy `FocusIndicator` pipeline and the new `FocusOverlay` V2 pipeline run simultaneously.

Required surgical phases:

1. Phase 1: Remove the legacy pipeline
   - Target files: `CameraViewModel.kt`, `CameraScreen.kt`
   - Remove legacy `FocusIndicator` rendering from `CameraScreen.kt`
   - Add a strict V2 guard or deprecate `updateTrackedObjectPosition()` in `CameraViewModel.kt`
   - Intercept front-camera taps in `focusOnPoint()` and hard-return before any legacy HAL focus path
   - Make tap intent activate immediately via `isTapToFocusActive = true`, without coupling it to `afState=Locked`

2. Phase 2: Repair geometry and object-tracking wiring
   - Target file: `CameraViewModel.kt`
   - Fix `sensorToViewMatrix = null` so `GeometryMapper` receives a real matrix instead of always falling back to `FIT_CENTER`
   - Remove `hasFaces = result.faces.isNotEmpty()` as an absolute blocker for object tracking
   - Allow `autoFocusOnSalientTarget()` to run when there are no faces, or when the user manually taps, so tracker/object bbox handling can proceed

3. Phase 3: Remove short-circuit logic and unlock optical flow
   - Target files: `CameraViewModel.kt`, `DefaultEyeAfPolicyResolver.kt`
   - Set `allowOpticalState = true` on the front-camera path
   - Remove the `isAlreadyVisualLocked` HAL bypass
   - Ensure `FocusController.apply()` is actually invoked and its `FocusControllerResult` is fed back into `FocusStateMachine`

4. Phase 4: Decouple Compose animation frequency
   - Target file: `FocusOverlay.kt`
   - Do not use `primaryBox` as a `LaunchedEffect` key
   - Use `visualTargetState` and `target.stableId` as the animation lifecycle key instead

Execution discipline requested by the user:

- This is an "external surgery" style refactor
- The response should clearly identify modified line ranges and code snippets
- Legacy `if/else` entanglement must be cut cleanly, not preserved

## Current Diagnosis Collected Before Patch

The following issues were confirmed in the codebase:

- `CameraScreen.kt` currently renders both `FocusIndicator` and `FocusOverlay`, causing the double-overlay split-brain condition
- `CameraViewModel.updateTrackedObjectPosition()` still writes legacy screen-space focus output and can still call legacy `focusOnPoint()`
- `CameraViewModel.focusOnPoint()` still drives the legacy HAL path on front camera
- `CameraViewModel.buildUserIntentState()` currently derives `isTapToFocusActive` from `isAEAFLocked` or `afState is AfState.Locked`, which is the wrong coupling
- `CameraViewModel.buildNewPipelineGeometryContext()` hardcodes `sensorToViewMatrix = null`
- `CameraViewModel.observePreviewForAnalysis()` still gates `autoFocusOnSalientTarget()` behind `hasFaces`
- `CameraViewModel.runNewFocusPipeline()` contains `isAlreadyVisualLocked` logic that can bypass `FocusController.apply()`
- `DefaultEyeAfPolicyResolver.kt` still disables `allowOpticalState` on front-camera paths
- `FocusOverlay.kt` uses `LaunchedEffect(visualTargetState, overlayModel.primaryBox)`, which cancels animation on every moving bbox update

## Implementation Intent

The next code patch will:

- excise the legacy UI render path
- seal the legacy tracked-object updater under V2
- move tap intent to an explicit tap session instead of `afState`
- provide a real image-to-view matrix to the V2 geometry path
- allow object tracking to proceed without faces
- remove the `VisualLocked` HAL short-circuit
- retime `FocusOverlay` animation using stable identity rather than live rectangle coordinates
