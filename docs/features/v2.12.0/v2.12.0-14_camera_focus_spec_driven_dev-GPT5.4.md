## 3. SSOT 對照後的高階結論

### 3.1 主要結論

目前程式不是單純存在一兩個 bug，而是整體架構只足以支撐：

- 單一 active target
- 單一 focus ring
- 部分 optical flow
- 混合且不完全一致的座標系

但 SSOT 要求的是：

- 單一 HAL focus + 多層視覺框
- 統一的 image/content/screen 座標轉換
- 前後鏡頭分流策略
- fixed-focus 明確旁路
- Eye-AF / Object Focus / Generic Tap / AE-AF Lock 清楚分層

### 3.2 關鍵判斷

- 目前 active detection path 沒有完整輸出 `eyePositions`，導致 Eye-AF 在主路徑上實際退化成 face-center AF。
- 真機目前關閉 `PreviewView`，使 UI preview、overlay、metering point 未共享同一個幾何真相，直接影響 Eye-AF 成功率。
- 目前只有一個 active `trackedObjectId` 與一個 `focusPoint`，天然無法滿足 SSOT 所要求的多人臉多框顯示。
- Optical Flow 目前只服務 generic tap，不服務 Eye-AF / object-focus，與 SSOT 不一致。

## 4. 程式現況核對摘要

### 4.1 Eye-AF 資料鏈缺口

舊的 `MLKitDetector` 會產出 `eyePositions`：

- `file:app/src/main/java/com/akirachang/ai/photographer/data/source/ml/MLKitDetector.kt`

但目前實際使用的 bitmap 分析路徑在建立 `DetectionResult` 時只填入：

- `faces`
- `objects`
- `imageWidth`
- `imageHeight`
- `rotationDegrees`

未填入 `eyePositions`：

- `file:app/src/main/java/com/akirachang/ai/photographer/presentation/camera/CameraViewModel.kt`

這使得：

- 前鏡頭 Eye-AF 退化為 face bbox/center 驅動
- 後鏡頭 Eye-AF 與 UI 表現和 SSOT 預期不一致

### 4.2 真機 Preview 幾何不一致

真機 build 目前 `USE_PREVIEWVIEW_DISPLAY = false`：

- `file:app/build.gradle.kts`

因此 device path 實際走 bitmap preview fallback：

- `file:app/src/main/java/com/akirachang/ai/photographer/presentation/camera/components/CameraPreview.kt`

而 bitmap fallback 使用 `ContentScale.Crop`，但 HAL metering 仍可能使用 legacy factory 或 CameraX 自身幾何，導致：

- UI 框位置
- 使用者點擊位置
- CameraX metering point
- optical flow tracking start point

不完全一致。

### 4.3 單一 active target 模型

目前 `CameraState` 只有：

- 單一 `focusPoint`
- 單一 `trackedObjectId`
- 單一 `trackedObjectType`

代表目前架構本質上是：

- 一個主追蹤框
- 一個 HAL focus target

而非 SSOT 的：

- 多個半透明候選框
- 單一 active 焦點框

### 4.4 Optical Flow 能力分裂

目前 OF 只會在 generic tap 路徑啟動。  
ML Kit subject hit 時走的是 ML tracking，而不是 OF tracking。

這造成：

- Generic tap：固定 72dp + OF 正常
- Eye-AF / object focus：有機會動態框，但沒有 OF

這和 SSOT 第 1.1 節要求的「Eye-AF / 物件對焦支援光流追蹤」不一致。

## 5. 對使用者三個現象的規格判讀

### 5.1 前鏡頭：Eye-AF 框固定大小且無法進入成功狀態，光流正常

判讀：

- 與 SSOT 不符。
- SSOT 定義前鏡頭只允許 Eye-AF，且應有 Cyan 視覺、夾爪動畫、停留 1 秒後淡出、持續追蹤。
- 現況因 Eye-AF 主路徑資料鏈不完整，前鏡頭高機率退化為 face center 路徑。
- 若前鏡頭為 fixed-focus，理論上應直接用 bypass 合成 Locked 狀態；若實測沒有成功狀態，表示 bypass 與 UI state 同步仍不完整。

### 5.2 後鏡頭：Eye-AF 無法成功、無多人臉對焦、無法光流追蹤

判讀：

- 與 SSOT 不符。
- 後鏡頭 Eye-AF 無法光流追蹤，現況屬設計結果，不是單一 bug。
- 不支援多人臉對焦，現況屬架構限制，不是偶發。
- 對焦成功狀態不穩，最大嫌疑是 preview/metering 幾何不一致與 Eye-AF 資料鏈不完整。

### 5.3 後鏡頭：點擊物件框固定大小、無法依物件大小調整，但能成功且 OF 正常

判讀：

- 此現象高度符合目前 generic tap 路徑。
- 代表 tap 很可能沒有命中 ML object，而是退到 generic path。
- generic path 本來就應固定 72dp，且應啟用 OF。
- 真正的問題不在 OF，而在 object hit-test / object filter 過嚴，使「明明點到物件，卻沒進到 Subject(Object) 路徑」。

## 6. Architectural Review

### 6.1 架構缺口總表

1. **DetectionPipeline 分裂**
   - `MLKitDetector` 有眼睛 landmark 能力
   - `CameraViewModel.observePreviewForAnalysis()` 卻直接組裝另一份 `DetectionResult`
   - 結果能力不一致

2. **Coordinate System 不單一**
   - `PreviewViewportContainer` 使用 FIT_CENTER 幾何
   - `CoordinateMapper` 是 CENTER_CROP 幾何
   - `bitmap fallback` 又是 `ContentScale.Crop`
   - device path 目前仍混用

3. **Focus 控制責任分散**
   - `CameraViewModel` 同時持有：
     - 手勢解析
     - ML target arbitration
     - OF 啟停
     - AF state machine
     - Fixed-focus policy
   - 責任過大，不利於票據拆分與後續驗證

4. **Overlay 狀態模型不足**
   - 現有只有單一 `FocusIndicator`
   - 不足以支援多人臉半透明候選框

5. **Hardware Capability 與 Product Policy 未完全對齊**
   - 已有 `FixedFocusDetector`
   - 但前鏡頭「只允許 Eye-AF，不允許 manual tap」尚未做 policy gating

### 6.2 推薦架構分層

建議收斂為以下四個核心模組：

1. `DetectionPipeline`
   - 唯一產出完整 `DetectionResult`
   - 包含 face, object, eyePositions, rotation-aware dimensions

2. `CoordinateTransformService`
   - 唯一負責 image/content/screen 的雙向轉換
   - device path 禁止退回 legacy `CoordinateMapper`

3. `FocusOrchestrator`
   - 唯一負責：
     - active target arbitration
     - fixed-focus bypass
     - HAL trigger policy
     - OF/ML tracking mode 選擇

4. `FocusOverlayStore`
   - 維護：
     - active focus ring
     - passive candidate rings
     - AE/AF lock ring

## 7. L2 實作指南

### 7.1 座標系定義

L2 必須固定三層座標系：

1. `Image Space`
   - ML Kit 與 optical flow 的基準空間

2. `Content Space`
   - 實際 preview 內容區域，排除 FIT_CENTER 的 letterbox

3. `Screen Space`
   - Compose / pointer input / overlay 使用的螢幕座標

### 7.2 Rotation Canonicalization

對 `rotation == 90 || rotation == 270` 時採用 upright image dimensions：

```text
effectiveW = rawH
effectiveH = rawW
```

否則：

```text
effectiveW = rawW
effectiveH = rawH
```

### 7.3 後鏡頭 image -> screen 轉換矩陣

```text
sx = contentWidth / effectiveW
sy = contentHeight / effectiveH

M_back =
[ sx   0   contentLeft ]
[ 0    sy  contentTop  ]
[ 0    0   1           ]
```

計算式：

```text
screenX = contentLeft + imageX * sx
screenY = contentTop  + imageY * sy
```

### 7.4 前鏡頭 image -> screen 轉換矩陣

前鏡頭需處理 mirror：

```text
sx = contentWidth / effectiveW
sy = contentHeight / effectiveH

M_front =
[ -sx  0   contentLeft + contentWidth ]
[ 0    sy  contentTop                 ]
[ 0    0   1                          ]
```

計算式：

```text
screenX = contentLeft + (effectiveW - imageX) * sx
screenY = contentTop  + imageY * sy
```

### 7.5 screen -> image 反向轉換

後鏡頭：

```text
imageX = (screenX - contentLeft) / sx
imageY = (screenY - contentTop)  / sy
```

前鏡頭：

```text
imageX = effectiveW - ((screenX - contentLeft) / sx)
imageY = (screenY - contentTop) / sy
```

### 7.6 L2 強制規則

1. device path 不允許再 fallback 到 `CoordinateMapper.CENTER_CROP`
2. `PreviewView + ViewPort.FIT + contentBounds` 是唯一座標真相來源
3. `CameraViewModel` 不再自行拼湊 image/content/screen 幾何
4. `Optical Flow` 若要使用 image coords，必須先經 `CoordinateTransformService.screenToImage()`

## 8. Fixed-Focus Bypass L2 指南

### 8.1 目標

對 fixed-focus 鏡頭：

- 不進入 HAL autofocus failure/backoff loop
- 仍保有合理的 UI focus feedback
- 仍可執行 AE/AWB metering

### 8.2 應前移到 FocusOrchestrator 的規則

不要只在 `LiveCameraSource` 做 bypass callback，應在 Focus policy 層就做分流：

```text
if lens is fixed-focus:
  skip FLAG_AF
  allow AE/AWB metering only
  synthesize AfState.Focusing
  then synthesize AfState.Locked
  never enter timeout/backoff/failure loop
```

### 8.3 前鏡頭 fixed-focus 規則

```text
if currentCamera == FRONT and isFixedFocusLens:
  disable manual tap
  disable AE/AF lock UI
  allow Eye-AF only
  allow optional AE/AWB metering at eye point
  emit Locked synthetically
```

### 8.4 後鏡頭 fixed-focus 規則

```text
if currentCamera == BACK and isFixedFocusLens:
  generic tap / object / face ring may still show
  HAL path uses AE|AWB only
  success is synthetic success
  generic optical flow may remain enabled
```

### 8.5 L2 驗收標準

1. fixed-focus front camera 不再出現 FAILED -> backoff loop
2. fixed-focus front camera 不再允許 manual tap
3. fixed-focus bypass 仍可觸發 Cyan focus success UI
4. Eye-AF lock 不得誤顯示 Yellow
