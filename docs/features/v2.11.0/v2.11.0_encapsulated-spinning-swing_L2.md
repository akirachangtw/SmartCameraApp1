```kotlin
// 當前代碼 (CameraScreen.kt:592-593)
```

**L1 計劃方案**:
```kotlin
val animatedRadius by animateFloatAsState(
```

**技術評估**:
| 項目 | 評估 | 說明 |

**優化建議**:
- ✅ **保持 L1 方案**：實作簡單、性能優秀、效果明顯
- ✨ **視覺增強**：可選增加 `EaseInOut` 緩動曲線，提升科技感


### 2. 搜尋中 Jitter 動畫（快速跳動）

#### ⚠️ 可行性: **70%**（需優化方案）

**L1 計劃方案**:
```kotlin
val jitterOffset = remember { mutableStateOf(Offset.Zero) }

LaunchedEffect(isFocusing) {
    if (isFocusing && !isTracking && !isLocked) {
        while (true) {
            jitterOffset.value = Offset(
                x = Random.nextFloat() * 6f - 3f,  // ±3px
                y = Random.nextFloat() * 6f - 3f
            )
            delay(120)  // 120ms interval
        }
    } else {
        jitterOffset.value = Offset.Zero
    }
}
```

**技術風險評估**:
| 風險項 | 等級 | 說明 | 緩解策略 |
|--------|------|------|---------|
| **無限迴圈 CPU 佔用** | 🟡 中 | `while(true) + delay(120)` 持續佔用協程 | 改用 `infiniteRepeatable` |
| **GPU 重繪頻率** | 🔴 高 | 120ms = 8.3 FPS 額外重繪，可能衝突 Compose 重組 | 降低頻率至 200ms (5 FPS) |
| **記憶體抖動** | 🟡 中 | 頻繁更新 `mutableStateOf` 觸發重組 | 改用 `Animatable` |
| **與 Spring 動畫衝突** | 🟡 中 | Tracking 模式下 Spring + Jitter 疊加 | 已有 `!isTracking` 守衛，安全 |

**⚠️ 關鍵問題: GPU 性能風險**

Pixel 9a 已有溫控問題（v2.9.9 Phase 9B），額外的 Jitter 動畫（8.3 FPS）疊加在：
- CameraX Preview (30 FPS)
- ML Kit 分析 (2 FPS，節流後)
- Optical Flow 運算 (2 FPS，節流後)
- Compose UI 重組 (60 FPS)

**總 GPU 負載預估**: 60 (Compose) + 8.3 (Jitter) = **68.3 FPS 重繪請求**

在 Pixel 9a 上可能觸發 GPU 節流，導致：
- Frame time > 16ms (低於 60 FPS)
- 溫控降頻
- 電池消耗增加

#### ✨ **優化方案 B: 微震動 + 淡入淡出（科技感增強版）**

**核心理念**: 不使用純隨機跳動，改用**微震動 + 週期性脈衝**，更符合「AI 運算中」的科技感

**改進代碼**:
```kotlin
// Micro-vibration jitter (科技感微震動)
val jitterIntensity by animateFloatAsState(
    targetValue = if (isFocusing && !isTracking && !isLocked) 1f else 0f,
    animationSpec = infiniteRepeatable(
        animation = tween(durationMillis = 300, easing = LinearEasing),
        repeatMode = RepeatMode.Reverse
    ),
    label = "jitter_intensity"
)

val jitterOffset = remember { Animatable(Offset.Zero, Offset.VectorConverter) }

LaunchedEffect(isFocusing) {
    if (isFocusing && !isTracking && !isLocked) {
        // Subtle pulse animation (微脈衝動畫)
        jitterOffset.animateTo(
            targetValue = Offset(
                x = sin(System.currentTimeMillis() * 0.01f) * 2f * jitterIntensity,
                y = cos(System.currentTimeMillis() * 0.01f) * 2f * jitterIntensity
            ),
            animationSpec = infiniteRepeatable(
                animation = tween(durationMillis = 300, easing = FastOutSlowInEasing),
                repeatMode = RepeatMode.Reverse
            )
        )
    } else {
        jitterOffset.snapTo(Offset.Zero)
    }
}
```

**優勢**:
- ✅ GPU 負載極低（使用 `Animatable` 插值，無額外重繪）
- ✅ 科技感更強（正弦波微震動 vs 隨機抖動）
- ✅ 符合「AI 運算中」的視覺語言
- ✅ 無記憶體抖動

**劣勢**:
- ⚠️ 實作複雜度較高
- ⚠️ 需調整參數以達到最佳效果

### 3. 對焦成功 Overshoot 動畫（縮小彈回）

#### ⚠️ 可行性: **60%**（技術方案需重構）

**L1 計劃方案**:
```kotlin
val scale by animateFloatAsState(
    targetValue = targetScale,
    animationSpec = if (focusSuccess == true && !isFocusing) {
        spring(
            dampingRatio = Spring.DampingRatioMediumBouncy,
            stiffness = Spring.StiffnessMedium
        )
    } else {
        tween(durationMillis = 300)
    },
    label = "focus_scale"
)

LaunchedEffect(focusSuccess) {
    if (focusSuccess == true) {
        delay(50)
        // Scale animation handled by animateFloatAsState
    }
}
```

**❌ 技術問題: 狀態機設計缺陷**

| 問題 | 說明 | 影響 |
|------|------|------|
| **無法觸發縮小 10%** | `targetScale` 始終為 1.0，無法產生 0.9 → 1.0 彈回 | 動畫不會執行 |
| **Spring 參數錯誤** | `DampingRatioMediumBouncy` 不會縮小，只會彈回 | 無法達成「縮小 10% 再彈回」 |
| **狀態競爭** | `focusSuccess` 與 `scale` 無直接連動 | 可能無法觸發 |

---

#### ✨ **修正方案: 使用 Animatable 手動控制序列**

**核心理念**: Overshoot 需要**兩階段動畫序列**：
1. Phase 1: 縮小至 0.9（100ms）
2. Phase 2: 彈回至 1.0（200ms，Spring 彈性）

**改進代碼**:
```kotlin
// Replace animateFloatAsState with Animatable
val scale = remember { Animatable(1.0f) }

// Trigger overshoot animation on focus success
LaunchedEffect(focusSuccess) {
    when {
        // Focus success → Overshoot sequence
        focusSuccess == true && !isFocusing && !isTracking && !isLocked -> {
            // Phase 1: Shrink to 0.9 (100ms)
            scale.animateTo(
                targetValue = 0.9f,
                animationSpec = tween(durationMillis = 100, easing = FastOutLinearInEasing)
            )
            // Phase 2: Bounce back to 1.0 (200ms, spring)
            scale.animateTo(
                targetValue = 1.0f,
                animationSpec = spring(
                    dampingRatio = Spring.DampingRatioMediumBouncy,
                    stiffness = Spring.StiffnessHigh  // High stiffness for snappy bounce
                )
            )
        }
        // Tracking or locked → scale 1.0
        isTracking || isLocked -> {
            scale.snapTo(1.0f)
        }
        // Focusing → scale 1.2
        isFocusing -> {
            scale.animateTo(1.2f, animationSpec = tween(300))
        }
        // Default → scale 1.0
        else -> {
            scale.snapTo(1.0f)
        }
    }
}

// Use scale.value in Canvas
val radius = 28.dp.toPx() * scale.value
```

**優勢**:
- ✅ 精確控制兩階段動畫序列
- ✅ 明確的「縮小 10% → 彈回」效果
- ✅ 狀態機清晰，無競爭條件

**劣勢**:
- ⚠️ 需重構現有 `animateFloatAsState` 為 `Animatable`
- ⚠️ 實作複雜度提升

---

#### ✨ **替代方案: 簡化版 Overshoot（快速實現）**

如果時程緊張，可採用**單階段 Spring 動畫**：

```kotlin
val scale by animateFloatAsState(
    targetValue = when {
        isTracking || isLocked -> 1.0f
        isFocusing -> 1.2f
        focusSuccess == true -> 1.0f
        else -> 1.0f
    },
    animationSpec = if (focusSuccess == true && !isFocusing) {
        // Overshoot spring (彈性過衝)
        spring(
            dampingRatio = Spring.DampingRatioLowBouncy,  // Low bouncy for overshoot
            stiffness = Spring.StiffnessHigh
        )
    } else {
        tween(durationMillis = 300)
    },
    label = "focus_scale"
)
```

**效果**: 從 1.2 → 1.0 時會先衝到 0.95 再彈回 1.0（類似 Overshoot）

**優勢**:
- ✅ 實作簡單（僅修改 Spring 參數）
- ✅ 保持 L1 代碼結構

**劣勢**:
- ⚠️ Overshoot 效果較弱（0.95 vs 0.9）
- ⚠️ 依賴 `isFocusing → focusSuccess` 狀態轉換

### ✨ 優化方案: 呼吸燈 + 旋轉脈衝（科技感升級）

**核心理念**: 結合「呼吸燈 + 微旋轉 + 脈衝」，模擬「AI 正在運算」的專業視覺

**改進代碼**:
```kotlin
// Breathing light effect (呼吸燈效果)
val breathingAlpha by animateFloatAsState(
    targetValue = if (isFocusing && !isTracking && !isLocked) 1.0f else 0f,
    animationSpec = infiniteRepeatable(
        animation = tween(durationMillis = 1000, easing = FastOutSlowInEasing),
        repeatMode = RepeatMode.Reverse
    ),
    label = "breathing_alpha"
)

// Pulse rotation effect (脈衝旋轉效果)
val rotationAngle by animateFloatAsState(
    targetValue = if (isFocusing && !isTracking && !isLocked) 360f else 0f,
    animationSpec = infiniteRepeatable(
        animation = tween(durationMillis = 2000, easing = LinearEasing),
        repeatMode = RepeatMode.Restart
    ),
    label = "rotation"
)

// Apply effects in Canvas
Canvas(modifier = modifier.graphicsLayer {
    rotationZ = if (isFocusing) rotationAngle else 0f
}) {
    val currentAlpha = if (isFocusing) {
        0.6f + 0.4f * breathingAlpha  // 0.6 - 1.0 範圍呼吸
    } else {
        alpha
    }

    // Draw arcs with breathing alpha
    drawArc(
        color = color,
        startAngle = 5f,
        sweepAngle = 80f,
        ...
        alpha = currentAlpha,
        style = Stroke(width = strokeWidth)
    )
}
```

**視覺效果**:
1. **呼吸燈**: Alpha 在 0.6 - 1.0 之間循環（1 秒週期）
2. **脈衝旋轉**: 整個對焦框順時針旋轉（2 秒一圈）
3. **青色**: 保持 `0xFF00E5FF`（賽博青）

**優勢**:
- ✅ 科技感極強（呼吸 + 旋轉 = AI 運算中）
- ✅ GPU 負載低（`graphicsLayer` 硬件加速）
- ✅ 符合專業相機視覺語言（如 Canon R5 的對焦動畫）
