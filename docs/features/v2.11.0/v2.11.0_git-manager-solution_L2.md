# Git 管理流程改進 L2 分析與最佳方案

> **文件狀態**: Draft
> **對應 Issue**: Fix Git Manager Process Disconnection
> **日期**: 2026-02-15

## 1. 問題分析

### 核心問題
開發者在執行合併（Merge）操作時，完全跳過了 `devspec/MERGE_SOP.md` 定義的關鍵步驟（特別是 Phase 2 文檔同步），導致：
1.  **文檔與代碼脫節**：代碼已合併，但對應的決議文檔（Design Decisions）與測試報告未同步。
2.  **遺失關鍵檔案**：如 v2.10.0 的決議文檔和 16KB 相關腳本未被正確帶入 v2.11.0。
3.  **依賴人工記憶**：`stage_verification_checklist.md` 僅關注「驗證」，未包含「合併程序」，兩者無連結。

### 根本原因
- **流程斷裂**: 開發者跑完 `stage_verification_checklist.md` 確認功能正常後，就直接執行 `git merge`，中間缺乏「Check Point」。
- **工具缺失**: 沒有自動化工具檢查「文檔同步」是否執行。

---

## 2. 最佳建議方案：Smart Check 機制

我建議實施一個「**漸進式自動化 (Progressive Automation)**」方案，核心是引入一個 `git_smart_check.py` 工具，並將其整合到現有流程中。

### 方案架構

#### A. 工具開發：`tools/check_merge_readiness.py`
開發一個 Python 腳本，用於在合併前/推送前檢查狀態。

**功能**:
1.  **版本偵測**: 自動從 `build.gradle.kts` 或 `libs.versions.toml` 讀取當前版本。
2.  **SOP 執行證據檢查**: 
    - 檢查是否已創建 `devspec/DOCS_SYNC_LOG_*.md`（證明已執行文檔同步）。
    - 檢查 `devspec/BRANCH_RELEASES.md` 是否有當前版本的更新記錄。
3.  **關鍵檔案檢查**: 掃描 `docs/plan/` 和 `docs/test_results/`，確保沒有遺漏上一版本的檔案。

#### B. 流程整合
修改 `devspec/stage_verification_checklist.md`，新增 **Phase 6: Merge Readiness**。

```markdown
## Phase 6: Merge Readiness (新增)
> 執行此步驟以確保合併安全

### 6.1 執行 Smart Check
python tools/check_merge_readiness.py
# 輸出範例:
# [PASS] Docs Sync Log found along with ...
# [PASS] Branch Releases updated...
# [READY] You are safe to merge using MERGE_SOP.md
```

#### C. 強制性 (Optional but Recommended)
可以配置 Git Pre-push hook，如果檢測到正在 push 到 `main` 或 `develop` 且未通過 check，則發出警告（但不需完全阻擋，避免緊急修復困難）。

## 3. 風險評估 (Risk Assessment)

### Risk 1: 開發者繞過工具 (High Risk)
- **描述**: 開發者覺得腳本麻煩，直接 `git merge --no-verify` 或忽略警告。
- **影響**: 問題重演，文檔持續遺失。
- **緩解措施**: 
    - **低阻力設計**: 腳本必須極快 (<1s)。
    - **正向回饋**: 腳本輸出明確的「✅ READY」綠色信號，給予安心感。
    - **整合 GUI**: 將此檢查加入 `tools/stage_verification_gui.pyw` 的最後一個 Tab。

### Risk 2: 腳本誤報 (False Positives) (Medium Risk)
- **描述**: 腳本因為版本號解析錯誤或檔案路徑變更，錯誤地阻擋或警告。
- **影響**: 降低開發效率，開發者對工具失去信任。
- **緩解措施**: 
    - 提供 `--bypass` 或 `--force` 參數。
    - 腳本邏輯保持簡單，只檢查「存在性」而非「內容正確性」。

### Risk 3: 維護成本 (Low Risk)
- **描述**: 專案結構改變（如 docs 目錄移動）導致腳本失效。
- **影響**: 需要額外維護腳本。
- **緩解措施**: 在 `tools/README.md` 中記錄腳本邏輯，使用相對路徑。

---

## 4. 實施計劃 (Action Items)

1.  **Create Script**: `tools/check_merge_readiness.py`
2.  **Update Checklist**: 修改 `devspec/stage_verification_checklist.md` 加入 Phase 6。
3.  **Update SOP**: 修改 `devspec/MERGE_SOP.md` 提及此工具。
4.  **Integration**: 更新 `tools/stage_verification_gui.pyw` (Optional, Phase 2)。

## 5. 結論
採用「**工具輔助 + 流程嵌入**」是最佳解。不完全依賴強制 Hook（保留靈活性），但透過 Checklist 明確要求執行檢查腳本，將「隱性記憶」轉化為「顯性步驟」。
