# v2.11.0 Saliency Autofocus (視覺顯著性對焦) 可行性評估報告

本報告針對「使用視覺顯著性 (Saliency) 進行自動對焦」的功能提出技術評估、風險分析與最佳實作建議。

## 1. 核心定義與目標
**目標**：讓相機自動判斷畫面中的「主角」，並在使用者未點擊螢幕時，自動進行對焦與追蹤。
**LumiFrame 願景**：模擬人類攝影師的眼光，自動識別畫面中最具「視覺顯著性」的區域（通常是人臉、高對比物體或畫面中心的動態主體）。

## 2. 技術方案比較

| 方案 | 技術核心 | 準確度 (Saliency) | 效能消耗 (Pixel 9a) | 熱控風險 | 開發複雜度 | 評估結果 |
|------|:--------:|:----------------:|:------------------:|:--------:|:----------:|:--------:|
| **A. True Saliency** |端對端深度學習模型 (如 U²-Net, BASNet) | ⭐⭐⭐⭐⭐ (極高) | 🔴 高 (需持續推論) | 🔴 極高 | 🔴 高 (需整合 TFLite) | **不可行** (v2.11.0) |
| **B. Traditional CV** | OpenCV (Spectral Residual / Fine Grained) | ⭐⭐ (中等) | 🟡 中 (CPU 密集) | 🟡 中 | 🟡 中 | **不建議** |
| **C. ML Kit Proxy** | 利用現有 Object Detection 結果進行啟發式權重計算 | ⭐⭐⭐ (足夠實用) | 🟢 低 (已在運作中) | 🟢 低 | 🟢 低 | **推薦方案** ✅ |

### 詳細分析
*   **方案 A (True Saliency)**：雖然能精確捕捉「人眼會看哪裡」，但在 Pixel 9a 已有熱控壓力的前提下，跑一個額外的 Segmentation 模型是不切實際的。這會導致取景器掉幀嚴重。
*   **方案 C (ML Kit Proxy)**：`CameraViewModel` 目前已經在跑 ML Kit 偵測 (10 FPS)。我們只需在 `detectionResult` 更新時加入一段輕量級邏輯：**「從所有偵測到的物體中，選出最大且最靠近中心的」**，將其視為「顯著目標」。
    *   **優勢**：**零額外算力成本**（重用現有數據）。

## 3. 推薦方案：Smart Subject Focus (基於方案 C)

建議在 v2.11.0 實作 **「智慧主體鎖定」** 作為 Saliency 的實務替代方案。

### 演算邏輯 (Heuristic logic)
系統每 500ms 評估一次當前畫面：
1.  **先決條件**：當前未處於「手動鎖定 (Locked)」或「正在手動對焦 (Focusing)」狀態。
2.  **權重計算**：對所有偵測到的人臉與物件計算分數。
    *   `Score = (BoxSize * 0.6) + (Centrality * 0.4)`
    *   人臉 (Face) 額外獲得 +30 分加權。
3.  **觸發對焦**：若最高分目標的信心度 > 閾值，且位置穩定（未劇烈移動），則自動觸發 `focusOnPoint` 並進入追蹤模式。

## 4. 風險評估

### A. 使用者體驗風險 (UX Risk)
*   **風險**：AI 自作聰明，對焦到使用者不想要的背景物體。
*   **緩解**：
    *   **Override 機制**：使用者的「手動點擊」永遠擁有最高優先權 (High Priority)。一旦使用者手動點擊，系統應暫停「自動捕捉」5-10 秒。
    *   **信心閾值**：寧可不抓，也不要抓錯。只有在目標非常明確（如佔畫面 1/3 的人臉）時才自動觸發。

### B. 效能風險 (Performance Risk)
*   **評估**：採用方案 C 對 CPU/GPU 幾乎無額外負擔。
*   **結論**：安全。

## 5. 結論與建議

**結論**：在 v2.11.0 引入重型 Saliency 模型是不明智的。
**建議**：利用現有的 ML Kit 數據，實作 **「智慧主體權重演算法」**。這能以最低成本達成 80% 的體驗升級，讓相機看起來「很有智慧」。
