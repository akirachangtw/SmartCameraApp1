# v2.11.0 對焦功能開發可行性評估與實作計劃

## Context（背景）

### 為什麼需要這個變更

用戶要求評估 LumiFrame AI 規劃文檔（`plans/v2.9.9-LumiFrame-AI-Focusing-light-shallow-deep.md`）中三個功能在 v2.11.0 的開發可行性：

- **A. 前置鏡頭（自拍模式）**：ML Kit 人臉追蹤 + 自動對焦
- **B. 後置鏡頭（全場景）**：Saliency 視覺顯著性檢測
- **C. 視覺語言協議**：4 種對焦狀態視覺回饋（搜尋/成功/鎖定/淡出）

**核心設計目標**：「智能且科技感風格」—— 當前對焦功能過於基礎，不符合 AI Photographer Assistant 的科技感定位。LumiFrame AI 視覺語言協議提供了專業的視覺反饋系統，能提升使用者體驗的智能感與科技感。

### 當前問題

1. **視覺語言協議不完整**：當前僅有基礎淡出動畫（Alpha 1.0 → 0.4），缺少 LumiFrame 規劃的精緻視覺反饋：
   - ❌ 搜尋中 Jitter 動畫（未實現）
   - ❌ 對焦成功 Overshoot 彈回（未實現）
   - ⚠️ 持續停留框線變細（未實現）

2. **Saliency 自動對焦缺失**：ML Kit 不提供 Saliency Map，需 TensorFlow Lite 模型（待評估討論）

3. **前置鏡頭狀態**：✅ 已驗證正常（v2.9.6 Phase 2.1，Pixel 9a 實機測試通過）

### 預期結果

實作 LumiFrame AI 完整視覺語言協議（包含 Jitter + Overshoot），提升對焦功能的智能感與科技感，符合 AI Photographer Assistant 的產品定位。

### 完整版視覺語言協議（LumiFrame AI Section C）

**目標**：實現 LumiFrame AI 完整視覺語言協議，提升對焦功能的智能感與科技感

**修改內容**：

#### 1. 持續停留動畫（框線變細 + 半徑縮小）

**位置**：CameraScreen.kt，行 592-593

**當前代碼**：
```kotlin
val radius = 28.dp.toPx() * scale
val strokeWidth = 2.5.dp.toPx()
```

**修改為**：
```kotlin
// Animated radius (normal 28dp → fading 24dp)
val animatedRadius by animateFloatAsState(
    targetValue = if (isFading) 24.dp.toPx() else 28.dp.toPx(),
    animationSpec = tween(durationMillis = 500),
    label = "focus_radius"
)
val radius = animatedRadius * scale

// Animated stroke width (normal 2.5dp → fading 1.5dp)
val animatedStrokeWidth by animateFloatAsState(
    targetValue = if (isFading) 1.5.dp.toPx() else 2.5.dp.toPx(),
    animationSpec = tween(durationMillis = 500),
    label = "focus_stroke"
)
val strokeWidth = animatedStrokeWidth
```

---

#### 2. 搜尋中 Jitter 動畫（快速跳動）

**位置**：CameraScreen.kt，行 527-551（animatedX/Y 邏輯）

**設計規格**（LumiFrame AI 文檔）：
- 搜尋中（isFocusing）：虛線四邊形，Alpha 1.0，快速跳動代表運算中
- Jitter 幅度：±2-3px 隨機位移
- Jitter 頻率：100-150ms 間隔

**實現方案**：
```kotlin
// Add jitter offset for searching animation
val jitterOffset = remember { mutableStateOf(Offset.Zero) }

LaunchedEffect(isFocusing) {
    if (isFocusing && !isTracking && !isLocked) {
        // Jitter animation loop
        while (true) {
            jitterOffset.value = Offset(
                x = Random.nextFloat() * 6f - 3f,  // ±3px
                y = Random.nextFloat() * 6f - 3f
            )
            delay(120)  // 120ms interval
        }
    } else {
        jitterOffset.value = Offset.Zero
    }
}

// Apply jitter to animated position
val finalX = animatedX + jitterOffset.value.x
val finalY = animatedY + jitterOffset.value.y
```

**技術考量**：
- 使用 `LaunchedEffect` 驅動動畫迴圈
- `Random.nextFloat()` 生成隨機位移
- 需確保不與 Spring 動畫衝突（tracking 模式關閉 jitter）

---

#### 3. 對焦成功 Overshoot 動畫（縮小彈回）

**位置**：CameraScreen.kt，行 555-559（scale 動畫）

**設計規格**（LumiFrame AI 文檔）：
- 對焦成功瞬間：縮小 10% 再彈回
- 彈回效果：Overshoot 彈簧感
- 時長：300ms

**當前代碼**：
```kotlin
val scale by animateFloatAsState(
    targetValue = if (isTracking || isLocked) 1.0f else if (isFocusing) 1.2f else 1.0f,
    animationSpec = tween(durationMillis = 300),
    label = "focus_scale"
)
```

**修改為**：
```kotlin
// Overshoot animation state
val targetScale = when {
    isTracking || isLocked -> 1.0f
    isFocusing -> 1.2f
    focusSuccess == true -> 1.0f  // Success → trigger overshoot
    else -> 1.0f
}

val scale by animateFloatAsState(
    targetValue = targetScale,
    animationSpec = if (focusSuccess == true && !isFocusing) {
        // Overshoot animation: shrink 10% then bounce back
        spring(
            dampingRatio = Spring.DampingRatioMediumBouncy,  // Bouncy feel
            stiffness = Spring.StiffnessMedium
        )
    } else {
        tween(durationMillis = 300)
    },
    label = "focus_scale"
)

// Trigger overshoot on success
LaunchedEffect(focusSuccess) {
    if (focusSuccess == true) {
        // Temporarily set scale to 0.9 (shrink 10%)
        // Spring animation will bounce back to 1.0
        delay(50)
        // Scale animation handled by animateFloatAsState
    }
}
```

**技術考量**：
- 使用 `Spring.DampingRatioMediumBouncy` 產生彈回效果
- 需處理 `focusSuccess` 狀態變化觸發時機
- 可選方案：使用 `Animatable` 手動控制縮放序列

## Saliency 功能（延後評估）

**決策**：❌ **不在 v2.11.0 實現**

**理由**：
1. 技術複雜度高（需 TFLite 模型整合）
2. GPU 資源佔用大（Pixel 9a 已有溫控問題）
3. Scope creep 風險（v2.11.0 應專注於對焦修正）

**替代方案**：保持手動 Tap-to-Focus

**v4.0.0 規劃**：
- 整合 TensorFlow Lite Saliency 模型（U²-Net 或 BASNet）
- ARCore Depth API 整合
- AGSL Bokeh shader 實作
- 虛擬光源聯動
