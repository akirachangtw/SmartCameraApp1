# v2.8.2 Phase C Feasibility: RenderScript GPU Acceleration

## 1. 綜述 (Executive Summary)
針對 **v2.8.1 Phase B-1 (Integer Math)** 測試結果顯示 CPU 優化已達極限 (YUV 轉換僅提升 10%)，瓶頸確認為 `ByteBuffer.get` 與 `Bitmap.setPixels` 的記憶體傳輸開銷。

本計畫 (Phase C) 將轉向 **GPU 加速方案**，使用 Android `RenderScript` API 執行 `ScriptIntrinsicYuvToRGB`，繞過 CPU 迴圈與 JNI 邊界檢查。

---

## 2. 技術可行性驗證 (Technical Feasibility)

### 為什麼選擇 RenderScript?
1.  **解決 JNI 瓶頸**: RenderScript Script 執行於 Driver 層，無需每像素跨越 JNI。
2.  **解決數學瓶頸**: 使用 GPU/DSP 平行處理，速度通常為 CPU 的 5-10 倍。
3.  **相容性**: 雖然 Android 12 Deprecated，但在 AGP 8.0+ 配合 `renderscript.support.mode` 仍可運作，且是對現有專案 (API 24+) 成本最低的方案。

### 關鍵實作細節
-   **Input**: `Type.Element.U8` (Luma) + `Type.Element.U8` (Chroma interlaced).
-   **Output**: `Bitmap` (ARGB_8888).
-   **Performance Target**: YUV Conversion Time < 5ms.

### 風險評估
-   **Deprecation**: 需使用 Support Library 模式。
-   **Device Compatibility**: 部分廠商對 RS 支援不完整，需保留 Java fallback 機制。

---

## 3. 實作計畫 (Implementation Plan)

### Step 1: 環境配置 (Gradle)
```kotlin
android {
    defaultConfig {
        renderscriptTargetApi = 21
        renderscriptSupportModeEnabled = true
    }
}
```

### Step 2: RenderScript Converter 實作
建立 `RenderScriptYuvConverter.kt`:
1.  初始階段 (`init`): 建立 `RenderScript` context, `ScriptIntrinsicYuvToRGB`, `Type.Builder` (固定尺寸分配)。
2.  每幀執行 (`convert`):
    -   將 ByteBuffer 複製到 Allocation (或者使用 `Allocation.createTyped` with `USAGE_SHARED` 嘗試零拷貝)。
    -   執行 `script.forEach(outAlloc)`.
    -   `outAlloc.copyTo(bitmap)`.

### Step 3: Fallback 機制
保留原有的 `YuvConverter` (Integer implementation) 作為 Fallback，若 RS 初始化失敗則切換回 CPU 模式。

### Step 4: 整合
修改 `LiveCameraSource.kt`，優先使用 `RenderScriptYuvConverter`。
