## P0: 座標系統統一（CRITICAL - 必須優先修復）

### 問題根因（ChatGPT 深度分析）

**三套座標系統不一致**：

```
1. ViewPort + PreviewView (FIT_CENTER)
   └─ 產生黑邊（letterbox），實際預覽區域 < 螢幕尺寸

2. ML Kit Detection (ImageAnalysis)
   └─ 使用 Bitmap 座標，需映射到 PreviewView

3. FocusMeteringAction (SurfaceOrientedMeteringPointFactory)
   └─ 使用 viewWidth/viewHeight，未考慮 FIT_CENTER 黑邊
```

**結果**：
- 格線超出預覽邊界（使用螢幕全尺寸）
- 對焦框不貼合物件（座標映射錯誤）
- Eye-AF 對焦點偏移（落到無效區域）
- Optical Flow 追蹤漂移（累積誤差）

```kotlin
suspend fun focusOnPoint(
    x: Float,
    y: Float,
    viewWidth: Int,
    viewHeight: Int
): Result<Unit> = withContext(Dispatchers.Main) {
    try {
        val preview = preview ?: return@withContext Result.failure(...)
        val cameraControl = cameraControl ?: return@withContext Result.failure(...)
```

```kotlin
class PreviewCoordinateMapper(
    private val screenWidth: Int,
    private val screenHeight: Int,
    private val aspectRatioMode: AspectRatioMode
) {
    /**
     * 計算 PreviewView 實際內容區域（扣除黑邊）
     */
    fun calculatePreviewBounds(): RectF {
        val targetRatio = when (aspectRatioMode) {
            RATIO_1_1 -> 1f
            RATIO_4_3 -> 4f / 3f
            RATIO_16_9 -> 16f / 9f
        }

        val screenRatio = screenWidth.toFloat() / screenHeight

        return if (screenRatio > targetRatio) {
            // Pillarbox (黑邊在左右)
            val previewWidth = screenHeight * targetRatio
            val offsetX = (screenWidth - previewWidth) / 2f
            RectF(offsetX, 0f, offsetX + previewWidth, screenHeight.toFloat())
        } else {
            // Letterbox (黑邊在上下)
            val previewHeight = screenWidth / targetRatio
            val offsetY = (screenHeight - previewHeight) / 2f
            RectF(0f, offsetY, screenWidth.toFloat(), offsetY + previewHeight)
        }
    }

    /**
     * ImageAnalysis 座標 → PreviewView 座標
     */
    fun imageToPreview(
        imageX: Float,
        imageY: Float,
        imageWidth: Int,
        imageHeight: Int
    ): PointF {
        val bounds = calculatePreviewBounds()

        // 正規化到 [0, 1]
        val normalizedX = imageX / imageWidth
        val normalizedY = imageY / imageHeight

        // 映射到 PreviewView 實際區域
        return PointF(
            bounds.left + normalizedX * bounds.width(),
            bounds.top + normalizedY * bounds.height()
        )
    }
}
```

**風險**：
- 🟡 手動計算容易出錯（需完整單元測試）
- 🟡 需處理裝置旋轉、前鏡頭鏡像

```kotlin
// 新增狀態變數（Line 108 後）
private var lastAutoFocusTime: Long = 0L
private var lastEyePosition: PointF? = null
private val AUTO_FOCUS_THROTTLE_BASE = 2000L      // 2 秒基礎節流
private val EYE_MOVEMENT_THRESHOLD = 50f          // Eye 移動閾值（px）

// 修改 autoFocusOnSalientTarget()（Line 1021 開頭）
private fun autoFocusOnSalientTarget() {
    val now = System.currentTimeMillis()
    val currentState = _state.value

    // v2.11.1: Adaptive throttling
    val shouldThrottle = when {
        // 基礎節流：2 秒內不重複對焦
        now - lastAutoFocusTime < AUTO_FOCUS_THROTTLE_BASE -> true

        // Eye-AF 例外：若 Eye 移動 > 50px，提前解除節流（最快 400ms = 2.5Hz）
        lastEyePosition != null && now - lastAutoFocusTime > 400L -> {
            val eyePos = detectionResult.eyePositions.firstOrNull()?.nearestEye
            if (eyePos != null) {
                val distance = sqrt(
                    (eyePos.x - lastEyePosition!!.x).pow(2) +
                    (eyePos.y - lastEyePosition!!.y).pow(2)
                )
                distance < EYE_MOVEMENT_THRESHOLD  // 移動 < 50px 才節流
            } else {
                true
            }
        }

        else -> false
    }

    if (shouldThrottle) return

    // ... existing candidate selection ...

    if (topCandidate != null && topCandidate.second > 50f) {
        val (x, y) = topCandidate.first

        // v2.11.1: Update last Eye position
        lastEyePosition = detectionResult.eyePositions.firstOrNull()?.nearestEye?.let {
            PointF(it.x, it.y)
        }

        focusOnPoint(x, y, viewWidth, viewHeight)
        lastAutoFocusTime = now
    }
}
```

**優點**：
- ✅ 靜態場景：2 秒節流（避免抖動）
- ✅ 動態場景：Eye 移動 > 50px 時提前觸發（最快 2.5Hz）
- ✅ 平衡穩定性與響應性

```kotlin
// 新增函數（Line 1070 後）
private fun calculateAdaptiveFrameSize(
    boundingBox: Rect,
    viewWidth: Int,
    viewHeight: Int
): Pair<Float, Float> {
    // Traycer 公式：boxSize = max(48dp, min(120dp, boundingBox.width() * 0.8))
    val boxWidthPx = boundingBox.width().toFloat()
    val boxHeightPx = boundingBox.height().toFloat()

    // 轉換為 dp（假設螢幕密度 density = 3.0）
    val density = 3.0f  // 應從 Context 取得
    val boxWidthDp = (boxWidthPx / density) * 0.8f
    val boxHeightDp = (boxHeightPx / density) * 0.8f

    // 限制範圍：48dp - 120dp
    val finalWidth = boxWidthDp.coerceIn(48f, 120f)
    val finalHeight = boxHeightDp.coerceIn(48f, 120f)

    return Pair(finalWidth, finalHeight)
}
```

```kotlin
// PreviewViewportContainer.kt
@Composable
fun PreviewViewportContainer(
    screenWidth: Dp,
    screenHeight: Dp,
    aspectRatioMode: AspectRatioMode,
    modifier: Modifier = Modifier,
    content: @Composable (contentBounds: Rect) -> Unit
) {
    val targetRatio = when (aspectRatioMode) {
        RATIO_1_1 -> 1f / 1f
        RATIO_4_3 -> 4f / 3f
        RATIO_16_9 -> 16f / 9f
    }

    val screenWidthPx = with(LocalDensity.current) { screenWidth.toPx() }
    val screenHeightPx = with(LocalDensity.current) { screenHeight.toPx() }
    val screenRatio = screenWidthPx / screenHeightPx

    val contentBounds = if (screenRatio > targetRatio) {
        // Pillarbox (黑邊在左右)
        val contentWidth = screenHeightPx * targetRatio
        val offsetX = (screenWidthPx - contentWidth) / 2f
        Rect(
            offsetX.toInt(),
            0,
            (offsetX + contentWidth).toInt(),
            screenHeightPx.toInt()
        )
    } else {
        // Letterbox (黑邊在上下)
        val contentHeight = screenWidthPx / targetRatio
        val offsetY = (screenHeightPx - contentHeight) / 2f
        Rect(
            0,
            offsetY.toInt(),
            screenWidthPx.toInt(),
            (offsetY + contentHeight).toInt()
        )
    }

    Box(
        modifier = modifier
            .fillMaxSize()
            .background(Color.Black)  // 黑邊背景
    ) {
        Box(
            modifier = Modifier
                .offset {
                    IntOffset(
                        contentBounds.left,
                        contentBounds.top
                    )
                }
                .size(
                    width = (contentBounds.width()).toDp(),
                    height = (contentBounds.height()).toDp()
                )
        ) {
            content(contentBounds)
        }
    }
}
```

```kotlin
// GridOverlay.kt
@Composable
fun GridOverlay(
    modifier: Modifier = Modifier,
    visible: Boolean = true,
    color: Color = Color.White.copy(alpha = 0.4f),
    strokeWidth: Float = 2f,
    contentBounds: Rect? = null  // v2.11.1: New parameter
) {
    if (!visible) return

    Canvas(modifier = modifier.fillMaxSize()) {
        // v2.11.1: Use contentBounds (fallback to Canvas size)
        val width = contentBounds?.width()?.toFloat() ?: size.width
        val height = contentBounds?.height()?.toFloat() ?: size.height

        val leftThird = width / 3f
        val rightThird = width * 2f / 3f
        val topThird = height / 3f
        val bottomThird = height * 2f / 3f

        // Draw vertical lines
        drawLine(
            color = color,
            start = Offset(leftThird, 0f),
            end = Offset(leftThird, height),
            strokeWidth = strokeWidth
        )
        drawLine(
            color = color,
            start = Offset(rightThird, 0f),
            end = Offset(rightThird, height),
            strokeWidth = strokeWidth
        )

        // Draw horizontal lines
        drawLine(
            color = color,
            start = Offset(0f, topThird),
            end = Offset(width, topThird),
            strokeWidth = strokeWidth
        )
        drawLine(
            color = color,
            start = Offset(0f, bottomThird),
            end = Offset(width, bottomThird),
            strokeWidth = strokeWidth
        )
    }
}
```

```kotlin
private fun handleThermalStatusChange(status: Int) {

        ThermalStatus.THERMAL_STATUS_SEVERE,
```

## 🎓 關鍵學習與決策記錄

### 決策 1: PreviewView.meteringPointFactory vs 手動計算

**選擇**：PreviewView.meteringPointFactory

**理由**：
- CameraX 官方 API，已處理所有邊緣案例
- Gemini（CameraX 專家）專業建議
- 減少維護成本

**風險緩解**：保留方案 B 作為 fallback

---

### 決策 2: Eye-AF 優先級加成 +30 vs +100

**選擇**：+30（Traycer 方案）

**理由**：
- 更保守，避免「小人臉壓過大主體」
- 可後續調整（30 → 50 → 100）
- 降低風險

---

### 決策 3: 固定節流 2s vs 動態節流

**選擇**：混合策略（2s 基礎 + Eye 移動例外）

**理由**：
- 平衡穩定性（靜態場景）與響應性（動態場景）
- ChatGPT 2-5Hz 建議 + Claude 2s 建議的整合
- 最佳使用者體驗

---

### 決策 4: 角落括號顯示時機

**選擇**：保持原設計（僅 Success/Locked）

**理由**：
- 符合 v2.11.0 設計規範
- 視覺語言協議：Searching（無括號）→ Success（括號出現）
- Traycer 建議會導致「一直看到括號」，失去視覺回饋

---

### 決策 5: PreviewViewportContainer vs aspectRatio Modifier

**選擇**：PreviewViewportContainer（ChatGPT 方案）

**理由**：
- 統一座標系統（P0 核心目標）
- 一次性解決所有 Overlay 問題
- 自動處理 touch 事件座標轉換

## 🚨 Critical Warnings（關鍵警告）

### ❌ DO NOT

1. **不要直接使用 `size.width/height` 繪製 Overlay**
   - 原因：未考慮 FIT_CENTER 黑邊
   - 正確做法：使用 `PreviewViewportContainer` 提供的 `contentBounds`

2. **不要手動計算座標映射**（除非 PreviewView API 不可用）
   - 原因：容易出錯，維護成本高
   - 正確做法：使用 `PreviewView.meteringPointFactory`

3. **不要在 Optical Flow 未監控溫度時提高 FPS 至 30**
   - 原因：Pixel 9a 溫控風險
   - 正確做法：先實作熱控監控，再啟用高 FPS

4. **不要修改 `showCornerBrackets` 邏輯為 `isFocusing`**
   - 原因：違反 v2.11.0 設計規範
   - 正確做法：保持 `focusSuccess == true || isLocked`

5. **不要跳過單元測試**
   - 原因：座標映射錯誤會導致系統性偏移
   - 正確做法：完整測試所有長寬比（1:1, 4:3, 16:9）
