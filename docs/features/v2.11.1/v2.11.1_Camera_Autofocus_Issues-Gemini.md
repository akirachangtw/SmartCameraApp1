# Detailed Implementation Plan & Risk Assessment

## Goal Description
Resolve reported camera issues:
1.  **Eye-AF/AF**: No automatic focus on preview start.
2.  **Smart Subject Focus**: Fixed focus box size, stuck "Focusing" state, missing fade animation and double-layer UI.
3.  **Grid Lines**: Lines extending into black bars (out of preview bounds).
4.  **Tracking**: Poor tracking performance.

## User Review Required
> [!IMPORTANT]
> **Performance Impact**: Enhancing Optical Flow (30FPS, larger window) increases CPU load. Thermal monitoring will be crucial.
> **UI Changes**: Focus Indicator will be significantly redesigned (Double-Layer, Dynamic Size).

## Risk Assessment

### 1. Performance & Thermal (High Risk)
*   **Risk**: Increasing Optical Flow to 30 FPS + 51px Window will significantly increase CPU/GPU usage, potentially causing thermal throttling on older devices (e.g., Pixel 9a mentioned in logs).
*   **Mitigation**:
    -   Monitor [LiveCameraSource](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/data/source/camera/LiveCameraSource.kt#66-1549) thermal status.
    -   If `THERMAL_STATUS_MODERATE` is reached, dynamically downgrade [OpticalFlowConfig](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/data/opencv/OpticalFlowConfig.kt#16-189) (15 FPS, 31px Window).

### 2. Focus Jitter (Medium Risk)
*   **Risk**: Dynamic focus box size might jitter rapidly due to frame-by-frame noise in ML detection bounding boxes.
*   **Mitigation**:
    -   Implement **Exponential Moving Average (EMA)** for box width/height in [CameraViewModel](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/presentation/camera/CameraViewModel.kt#44-1503).
    -   $\text{NewSize} = \text{OldSize} \times 0.8 + \text{MeasuredSize} \times 0.2$.

### 3. Focus Fighting (Low Risk)
*   **Risk**: If [focusOnPoint](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/data/repository/CameraRepositoryImpl.kt#722-736) is triggered repeatedly while Tracking is active, the lens might "pump" (hunt for focus).
*   **Mitigation**:
    -   Only trigger [focusOnPoint](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/data/repository/CameraRepositoryImpl.kt#722-736) on **initial tap** or **significant depth change**.
    -   Do NOT re-trigger AF if the object is moving laterally (X/Y) but size (Z) is constant.

### 4. UI Layout (Low Risk)
*   **Risk**: 1:1 Aspect Ratio might cause GridOverlay to clip if not centered correctly.
*   **Mitigation**:
    -   Use standard `Modifier.aspectRatio` with `Alignment.Center` in a parent Box filling max size.

## Verification Plan
1.  **Smoke Test**: Launch app, ensure preview visible, no crash.
2.  **AF Test**: Point at new object -> Camera should verify focus (breathing) without touch.
3.  **UI Test**:
    -   Tap Face -> Box matches face size.
    -   Wait 1s -> Box fades to 40% opacity.
    -   Verify Double-Layer (Brackets + Rect).
4.  **Grid Test**: Cycle 4:3 -> 16:9 -> 1:1. Grid lines must stay inside image.
5.  **Track Test**: Shake camera. Focus box should stick to object.
