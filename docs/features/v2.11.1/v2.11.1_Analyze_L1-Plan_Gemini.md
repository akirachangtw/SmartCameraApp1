# v2.11.1 P0 座標系統統一 - 分析與最佳修復方案

## 1. 核心問題分析

該計劃（`quiet-humming-meadow.md`）準確地識別了 v2.11.1 P0 測試失敗的根本原因：**座標系統不一致** 與 **PreviewView 生命週期時序問題**。

### 🔴 Critical Issue #1: Tap-to-Focus 邊界失效
*   **根本原因**：誤以為 `PreviewView.meteringPointFactory` 會自動過濾 Letterbox 黑邊區域。實際上它只做座標轉換，不負責邊界判定。
*   **影響**：在非 16:9 比例下，點擊黑邊仍會觸發對焦，導致對焦在錯誤位置（或無效區域）。

### 🔴 Critical Issue #2: Grid Overlay 超出邊界
*   **根本原因**：`PreviewView` 的實際內容區域（Content Bounds）在 `Lifecycle` 綁定前無法獲取。目前的修復方案試圖過早獲取 `SurfaceView`，導致失敗。
*   **影響**：Grid 線延伸到黑邊，視覺品質不專業。

---

## 2. 最佳建議方案 (Best Practice Solution)

建議採取 **「雙管齊下」** 的策略：短期修復（Hotfix）與長期重構（Refactor）。針對 P0 階段，我們優先執行 **穩健的 Hotfix**。

### ✅ 方案 A：針對 Issue #1 (Tap-to-Focus)
**策略**：在 ViewModel 層級進行「預先過濾 (Pre-filtering)」。不要依賴底層 `LiveCameraSource` 去猜測 UI 邊界。

1.  **利用 `PreviewView.meteringPointFactory` 驗證**：
    雖然它不過濾點擊，但它能判斷座標是否有效。
2.  **引入 `ContentBounds` 檢查**：
    在 `CameraScreen.kt` 的 `detectTapGestures` 中，先檢查點擊座標是否在有效的 `previewContentBounds` 內，再傳遞給 ViewModel。
    *   **優點**：邏輯最乾淨，UI 層負責 UI 邊界判定。

### ✅ 方案 B：針對 Issue #2 (Grid Overlay)
**策略**：使用 `ViewTreeObserver` 監聽 Layout 變化，但需加入「重試機制」與「空值保護」。

1.  **延遲獲取**：在 `onGlobalLayout` 中，若 `count == 0` 或 `SurfaceView` 仍為空，則不移除 Listener，繼續等待下一次 Layout pass。
2.  **主動查詢**：在 `CameraPreview` 的 `onPreviewViewCreated` 回調中，主動觸發一次邊界計算。

## 3. 風險評估 (Risk Assessment)

### ⚠️ 高風險 (High Risk)
*   **時序競爭 (Race Condition)**：`ContentBounds` 的計算依賴 `PreviewView` 內部的 `SurfaceView` 已經 layout 完成。如果在 Surface 準備好之前就繪製 Grid，Grid 可能會先全螢幕顯示，然後「跳」回正確位置。
    *   **緩解**：在 `ContentBounds` 準備好之前，GridOverlay 應保持隱藏 (Invisible)。

### ⚠️ 中風險 (Medium Risk)
*   **不同機型適配**：`meteringPointFactory` 在不同廠商的實作可能有細微差異（雖然是 Jetpack 庫，但底層 OEM 行為不同）。
    *   **緩解**：保留 Fallback 機制，若 Factory 創建失敗，退回全螢幕座標。

### 🟢 低風險 (Low Risk)
*   **Play Protect 警告**：確認為模擬器環境問題，不影響發布版。

## 4. 執行路徑 (Execution Roadmap)

1.  **Step 1 (Fix Issue #2)**: 完成 `CameraViewModel.kt` 中的 `ViewTreeObserver` 邏輯，確保能正確獲取並更新 `contentBounds`。
2.  **Step 2 (Fix Issue #1)**: 在 `CameraScreen.kt` 引入邊界檢查邏輯。
    ```kotlin
    onTap = { offset ->
        // 只有在預覽區域內才觸發
        if (previewContentBounds.contains(offset)) {
            viewModel.onEvent(CameraUiEvent.FocusOnPoint(...))
        }
    }
    ```
3.  **Step 3 (Verify)**: 執行驗證測試（16:9, 4:3, 1:1）。
