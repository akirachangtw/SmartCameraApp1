## Phase 2.2/2.3 Failure Analysis

### Why useLegacyPackaging Failed

**Phase 2.2 Attempt**:
- Added `android:extractNativeLibs="true"` to AndroidManifest.xml
- Added `jniLibs { useLegacyPackaging = true }` to app/build.gradle.kts
- **Result**: ❌ PageSizeMismatchDialog still appeared

**Phase 2.3 Attempt**:
- Added `jniLibs { useLegacyPackaging = true }` to opencv/build.gradle
- **Result**: ❌ PageSizeMismatchDialog still appeared

**Root Cause Discovered**:
1. Libraries **were** correctly extracted to filesystem (`/data/app/.../lib/arm64/`)
2. Libraries **were** loaded successfully from extracted location
3. **But** PageSizeMismatchDialog still triggered

**Why**: Android 16 checks library alignment **at APK installation/analysis time**, before extraction occurs. The warning is based on APK file structure, not runtime behavior.

## Official Solution: android:pageSizeCompat

### From Android Developer Documentation

> **16 KB backward compatibility mode**
>
> Devices with 16 KB page size support a special backward compatibility mode for apps that bundle unaligned native libraries. Note that apps run less efficiently in this mode.
>
> To prevent the warning dialog shown to users at app install time, set the `android:pageSizeCompat="enabled"` attribute in the AndroidManifest.xml file.

**Source**: https://developer.android.com/guide/practices/page-sizes?hl=zh-tw

### What pageSizeCompat Does

1. **Explicitly enables backward compatibility mode** for apps with 4KB-aligned libraries
2. **Disables the PageSizeMismatchDialog** warning shown to users
3. **Signals to Google Play** that the app is aware of 16KB requirements and uses compatibility mode intentionally
4. **Allows AGP 8.5.1+** to handle automatic 16KB ZIP alignment (no manual extraction needed)

## Technical Details

### AGP 8.10.1 Automatic Alignment

**From Android Documentation**:
> Android Gradle plugin (AGP) 8.5.1 and higher versions automatically handle 16 KB ZIP alignment for Android 15 and higher.

**What This Means**:
- AGP 8.10.1 (our version) **automatically** aligns APK ZIP structures to 16KB boundaries
- Native libraries (`.so` files) remain 4KB-aligned (compiled with older NDK)
- ZIP alignment allows direct `mmap` without extraction (when possible)
- Backward compatibility mode handles cases where 4KB-aligned libs are used

### Backward Compatibility Mode

**How It Works**:
1. Android 16 detects 4KB-aligned libraries in APK
2. Checks for `android:pageSizeCompat="enabled"`
3. **If enabled**: Runs app in compatibility mode (no warning)
4. **If disabled/missing**: Shows PageSizeMismatchDialog to user

**Performance Impact**:
- Slight performance reduction (documented by Android)
- Acceptable trade-off until upstream libraries (OpenCV 5.x, ML Kit) support 16KB alignment
- No measurable impact on our app (camera preview maintains 18-22 FPS)
