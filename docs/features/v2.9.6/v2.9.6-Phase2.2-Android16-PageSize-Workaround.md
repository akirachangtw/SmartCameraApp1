# v2.9.6 Phase 2.2 - Android 16 PageSizeMismatchDialog 修復方案

## 問題背景

### 發現時間
2026-01-26 - 實體 Pixel 9a (Android 16) 測試

### 問題描述
應用在 Android 16 上首次啟動時顯示 `PageSizeMismatchDialog` 警告對話框，列出以下原生函式庫未對齊 16KB 頁面邊界：

- `libopencv_java4.so` (OpenCV 4.13.0)
- `libface_detector_v2_jni.so` (ML Kit)
- `libmlkitcommonpipeline.so` (ML Kit)
- `libc++_shared.so`
- `libsurface_util_jni.so`
- `libimage_processing_util_jni.so`
- `libdatastore_shared_counter.so`
- `libandroidx.graphics.path.so`

### 影響範圍
- **功能影響**: 無（點擊「確定」後應用正常運作）
- **用戶體驗**: 差（每次啟動需手動關閉警告對話框）
- **優先級**: 中（不影響核心功能，但影響 UX）

---

## 根因分析

### 為什麼 Phase 2.1 的修復無效？

**Phase 2.1 實作**:
```kotlin
// app/build.gradle.kts
ndkVersion = "27.0.12077973"

jniLibs {
    useLegacyPackaging = false  // Modern packaging for 16KB alignment
}
```

**Phase 2.1 的假設**:
- NDK 27 支援 16KB 對齊
- 現代化封裝會自動對齊原生函式庫

**實際狀況**:
- ✅ NDK 27 **確實支援** 16KB 對齊
- ✅ 我們自己編譯的函式庫**可以**對齊
- ❌ **但是**：第三方預編譯函式庫（OpenCV、ML Kit）**不受我們控制**
- ❌ 這些函式庫由上游提供，使用舊版 NDK 編譯，**未對齊 16KB**

### 技術細節

Android 16 引入了 **16KB 頁面大小**支援（部分裝置），要求所有原生函式庫必須對齊到 16KB 邊界。

**對齊檢查流程**:
1. APK 安裝時，系統檢查 `.so` 檔案在 APK 中的位置
2. 如果使用 `extractNativeLibs="false"` + `useLegacyPackaging=false`（現代封裝）
3. 系統會直接從 APK 中 mmap 載入 `.so`，要求對齊
4. 如果 `.so` 未對齊 16KB → 顯示 `PageSizeMismatchDialog`

**我們的情況**:
- OpenCV 4.13.0: 使用 NDK < 27 編譯，未對齊 16KB
- ML Kit: Google 提供的預編譯函式庫，未對齊 16KB
- 其他第三方函式庫: 同樣未對齊

## 修復方案

### 選擇的方案: extractNativeLibs Workaround

由於無法重新編譯上游函式庫，我們採用 **extractNativeLibs="true"** 繞過對齊檢查。

### 實作變更

#### 1. AndroidManifest.xml
```xml
<application
    ...
    android:extractNativeLibs="true">
```

**作用**: 告訴系統將原生函式庫從 APK 解壓縮到檔案系統，而不是直接 mmap。

#### 2. app/build.gradle.kts
```kotlin
jniLibs {
    useLegacyPackaging = true  // Workaround for Android 16 PageSizeMismatchDialog
}
```

**作用**: 配合 `extractNativeLibs="true"`，使用傳統封裝方式。

#### 3. 版本更新
```kotlin
versionCode = 54
versionName = "2.9.6-phase2.2"
```

## 方案評估

### 優點 ✅

1. **立即解決用戶體驗問題** - 不再顯示警告對話框
2. **不需等待上游更新** - OpenCV 5.x / ML Kit 更新時間不確定
3. **零功能影響** - 所有功能正常運作
4. **向後相容** - 在 Android < 16 上同樣有效

### 缺點 ⚠️

1. **稍微增加安裝空間**
   - 原生函式庫會被解壓縮到 `/data/app/.../lib/`
   - 估計增加約 10-15MB

2. **安裝時間稍長**
   - 首次安裝需解壓縮原生函式庫
   - 估計增加 1-2 秒

3. **非最佳長期方案**
   - 理想情況應使用 16KB 對齊的函式庫
   - 但這需要等待上游更新

### 與其他方案比較

| 方案 | 優點 | 缺點 | 採用 |
|------|------|------|------|
| **extractNativeLibs workaround** | 立即解決、不依賴上游 | 稍微增加空間 | ✅ 採用 |
| 等待上游更新 | 最佳長期方案 | 時間不確定（可能數月） | ⏳ 追蹤中 |
| 自行重新編譯 OpenCV | 完全控制 | 維護成本高、不適用 ML Kit | ❌ 不採用 |
| 移除第三方函式庫 | 無對齊問題 | 失去核心功能 | ❌ 不可行 |

## 長期規劃

### 追蹤上游更新

定期檢查以下函式庫是否發布 16KB 對齊版本：

1. **OpenCV**
   - 目前版本: 4.13.0
   - 追蹤: OpenCV 5.x（預計 2026 Q2-Q3）
   - 網址: https://github.com/opencv/opencv/releases

2. **ML Kit**
   - 目前版本: com.google.mlkit:* (多個模組)
   - 追蹤: Google ML Kit 更新
   - 網址: https://developers.google.com/ml-kit/release-notes

### 移除 Workaround 的時機

當以下條件**全部滿足**時，可考慮移除 workaround：

1. ✅ OpenCV 發布 16KB 對齊版本
2. ✅ ML Kit 發布 16KB 對齊版本
3. ✅ 升級所有第三方函式庫到對齊版本
4. ✅ 測試確認無 PageSizeMismatchDialog
5. ✅ 移除 `android:extractNativeLibs="true"`
6. ✅ 改回 `useLegacyPackaging = false`

**預估時間**: 2026 Q3-Q4
