#### 問題 1: OrientationEventListener 未觸發
**症狀**：
- Logcat 顯示 "OrientationEventListener enabled" ✅
- 但完全沒有 "Orientation changed: X° → rotation=Y" 記錄 ❌
- 表示 `onOrientationChanged()` 回調從未被呼叫

**影響**：
- `currentRotation` 維持初始值 `ROTATION_0`
- `updateTargetRotation()` 從未執行
- ImageCapture.targetRotation 實際上是 **null**（builder 未設置）

#### 問題 2: 照片方向錯誤
**測試結果**：
| 拍攝方向 | 預期結果 | 實際結果 | 狀態 |
|---------|---------|---------|------|
| 直立 (0°) | 正確顯示 | 逆時針旋轉 90° | ❌ 錯誤 |
| 橫向左 (90°) | 正確顯示 | 正確 | ✅ 正確 |
| 橫向右 (270°) | 正確顯示 | 順時針旋轉 180° | ❌ 錯誤 |

**分析**：
- 橫向左正確可能是「巧合」（sensor orientation 270° 剛好匹配裝置旋轉）
- 其他方向錯誤證實 `targetRotation` 未動態更新
- 若監聽器有觸發，應該 3 個方向都正確

#### 問題 3: 預覽同步異常
**症狀**：
- 使用者報告：「旋轉到 90° 時預覽會先逆時針旋轉 90°」
- 「需要旋轉到 135° 再回到 90° 預覽才正常」
- 預覽畫面與裝置方向不同步

**可能原因**：
- Preview.targetRotation 未即時更新
- PreviewView 內部的 rotation 邏輯與 OrientationListener 衝突
- 135° 是 rotation mapping 的邊界值（135-224° → ROTATION_180），可能觸發 fallback 行為

#### 問題 4: 預覽 UI 跟著翻轉（次要）
**症狀**：
- 相機介面元素（快門按鈕、設定等）會跟著裝置旋轉
- 應該鎖定在 Portrait 方向

**原因**：
- Activity 的 `screenOrientation` 可能未設定為 `portrait`

## 4. 風險清單（Risks）

### 風險 1: OrientationListener 裝置兼容性 🔴 Critical
**描述**：
- 某些裝置的 `OrientationEventListener.canDetectOrientation()` 返回 true，但實際不回調
- OEM 客製化系統可能有不同的加速度計權限或省電策略

**緩解措施**：
- 加入 fallback 機制：使用 `DisplayManager.DisplayListener` 或 `Activity.onConfigurationChanged()`
- 若 5 秒內未收到任何 onOrientationChanged 回調，切換到 Display rotation

### 風險 2: Rotation Mapping 邏輯錯誤 🟡 Major
**描述**：
- 當前 mapping 可能與 CameraX 預期的座標系不一致
- 不同 sensor orientation (90°/270°) 的裝置需要不同的 mapping

**緩解措施**：
- 需要檢查 Sony XQ-BT52 的 `CameraCharacteristics.SENSOR_ORIENTATION`
- 可能需要根據 sensor orientation 調整 mapping

### 風險 3: Preview 與 Capture rotation 不同步 🟡 Major
**描述**：
- 若 Preview 使用 Display rotation，Capture 使用 OrientationListener rotation，可能不同步
- 使用者看到的預覽方向與拍出來的照片不一致

**緩解措施**：
- 三個 UseCase (Preview/Analysis/Capture) 必須使用**同一個 rotation source**
- 統一使用 OrientationListener 或統一使用 Display rotation

### 風險 4: 效能回歸（onOrientationChanged 高頻呼叫）🟢 Minor
**描述**：
- `onOrientationChanged()` 每次加速度計數據變化都會呼叫（可能每 50-100ms）
- 頻繁呼叫 `updateTargetRotation()` 可能影響效能

**緩解措施**：
- 已實作 `if (rotation != currentRotation)` 過濾
- 僅在 rotation 值真正改變時才更新（45° 閾值）

### 風險 5: 模式切換回歸（Static/Debug mode）🟢 Minor
**描述**：
- StaticImageSource 模式可能沒有 OrientationListener
- Debug mode 可能需要手動設定 rotation

**緩解措施**：
- OrientationListener 僅在 LiveCameraSource 啟用
- Static mode 可以固定使用 ROTATION_0（靜態圖片無方向問題）

```kotlin
    // 1. 先獲取當前 Display rotation 作為初始值
    val display = context.getSystemService<WindowManager>()?.defaultDisplay
    currentRotation = display?.rotation ?: Surface.ROTATION_0

    // 2. 建立 OrientationEventListener
    orientationListener = object : OrientationEventListener(context) {
        // ... existing code ...
    }

    // 3. Enable listener
    if (orientationListener?.canDetectOrientation() == true) {
        orientationListener?.enable()
        Log.i(TAG, "OrientationEventListener enabled, initial rotation: $currentRotation")
    }
}
```

### Plan B（加入 Fallback 機制，若 Plan A 失敗）

#### 目標
若 OrientationEventListener 在某些裝置上仍不可靠，使用 Display rotation 作為 fallback。

#### 步驟

**Step 1: 實作雙重監聽機制**
```kotlin
// 1. Display rotation listener (fallback)
private var displayListener: DisplayManager.DisplayListener? = null

private fun initRotationTracking() {
    // Try OrientationEventListener first
    initOrientationListener()

    // Setup Display rotation fallback
    val displayManager = context.getSystemService<DisplayManager>()
    displayListener = object : DisplayManager.DisplayListener {
        override fun onDisplayChanged(displayId: Int) {
            val display = displayManager?.getDisplay(displayId)
            val newRotation = display?.rotation ?: Surface.ROTATION_0
            if (newRotation != currentRotation) {
                currentRotation = newRotation
                updateTargetRotation(newRotation)
                Log.d(TAG, "Display rotation changed: $newRotation (fallback)")
            }
        }
        override fun onDisplayAdded(displayId: Int) {}
        override fun onDisplayRemoved(displayId: Int) {}
    }
    displayManager?.registerDisplayListener(displayListener, Handler(Looper.getMainLooper()))
}
```

**Step 2: 5秒無響應切換 fallback**
```kotlin
private fun initOrientationListener() {
    // ... existing code ...

    // Setup timeout check
    Handler(Looper.getMainLooper()).postDelayed({
        if (!orientationListenerTriggered) {
            Log.w(TAG, "OrientationListener not responding, using Display rotation fallback")
            // displayListener will take over
        }
    }, 5000)
}
```

#### 預期結果
- ✅ 即使 OrientationEventListener 失敗，仍能靠 Display rotation 工作
- ⚠️ Display rotation 更新頻率較低（僅在螢幕真正旋轉時）
- ⚠️ 不支援「倒置」(upside down) 偵測
