
# v2.9.6 Pixel 9a 相容性與優化可行性計畫書

## 1. 執行摘要

根據實體裝置測試結果 (`v2.9.6-Phase2.1`) 與官方 Android 文件分析，SmartCameraApp 在 Pixel 9a (Android 16) 上展現了極佳的功能相容性。
目前主要的相容性發現是，由於新裝置從 4KB 記憶體分頁過渡到 16KB 分頁，導致出現 **頁面大小不匹配 (Page Size Mismatch)** 的警告。

本計畫書針對以下事項提出解決方案：
1.  **16KB 頁面對齊**：解決 `PageSizeMismatchDialog` 警告，確保符合 Google Play 上架規範。
2.  **EXIF Metadata**：修復照片缺少方向標籤的問題。

---

## 2. 16KB 頁面對齊 (Android 15+ & Pixel 9a)

### 2.1 Google Play 相容性規範
根據 [Android 開發者文件](https://developer.android.com/guide/practices/page-sizes?hl=zh-tw)：
*   **強制規定**：自 **2025 年 11 月 1 日**起，所有提交至 Google Play 的新應用程式與更新 (若指定 Android 15 / API Level 35+)，**必須支援 16KB 頁面大小** 裝置。
*   **支援定義**：應用程式需能在 16KB 頁面大小的裝置上安裝並正常執行，無崩潰或重大功能異常。

### 2.2 問題描述
在支援 16KB 分頁的 Android 15/16 裝置 (如 Pixel 9a) 上，本 App 目前使用未對齊的原生函式庫 (OpenCV, ML Kit)，導致啟動時顯示系統警告：*"This app uses native libraries that are not aligned to 16KB page boundaries."*

### 2.3 解決方案與合規性分析

我們面臨兩種主要路徑來符合規範：

| 選項 | 方法 | 可行性 | Google Play 合規性 |
| :--- | :--- | :--- | :--- |
| **A. 提取原生函式庫 (目前方案)** | 在 Gradle 設定 `useLegacyPackaging = true`。<br>此設定強制在安裝時將 `.so` 檔解壓縮至儲存空間，而非直接從 APK 進行 `mmap`。 | **高** | **✅ 合規**。<br>官方文件明確列為支援 16KB 裝置的有效方法之一 (特別是針對無法重新編譯的第三方函式庫)。這確保了 App 能在 16KB 裝置上正常運作且無警告。 |
| **B. 重新編譯函式庫 (真正對齊)** | 使用 `-z max-page-size=16384` 重新編譯所有 `.so` 檔。 | **低** | **✅ 合規 (最佳效能)**。<br>但 ML Kit 為閉源無法重編，OpenCV 重編成本高。適合做為長期目標 (等待上游更新)。 |

### 2.4 執行策略
鑒於必須在 2025 年 11 月前合規，且依賴的 ML Kit 尚未更新：

1.  **短期 (Phase 2.2 - 現在)**：採用 **選項 A (提取原生函式庫)**。
    *   **實作**：`build.gradle.kts` 中設定 `useLegacyPackaging = true`。
    *   **預期結果**：消除 Pixel 9a 上的警告，符合 Google Play 要求的 "支援 16 KB 設備"。
2.  **長期 (2025 Q3)**：持續追蹤 OpenCV 與 ML Kit 的官方更新。若上游發布原生 16KB 對齊版本，則移除 legacy packaging 設定以優化安裝大小。

## 3. EXIF 方向標籤 (EXIF Orientation Tags)

### 3.1 問題描述
使用 CameraX 拍攝的照片在手機上顯示方向正確 (因依賴影像 metadata)，但在 PC/Web 上檢視時可能會旋轉 (例如直式變橫式)。

### 3.2 解決方案 (Phase 3)
*   整合 `androidx.exifinterface`。
*   在 `ImageCapture` 回調 (callback) 中：
    1.  讀取 `imageProxy.imageInfo.rotationDegrees`。
    2.  將角度映射為 EXIF 方向常數 (1, 6, 3, 8)。
    3.  在儲存前將標籤注入 JPEG 位元流 (byte stream)。

## 4. 實作步驟

### Phase 2.2: 16KB 對齊修復 (已實作)
**目標**：消除使用者可見的警告並符合 Play Store 規範。

1.  **修改 `app/build.gradle.kts`**：
    ```kotlin
    android {
        packaging {
            jniLibs {
                useLegacyPackaging = true // 啟用 android:extractNativeLibs="true"
                                          // 這是官方認可的 16KB 裝置支援方案
            }
        }
    }
    ```
2.  **驗證**：
    *   安裝於 Pixel 9a (Android 16)。
    *   **Pass Criteria**：App 啟動無 `PageSizeMismatchDialog` 警告。
