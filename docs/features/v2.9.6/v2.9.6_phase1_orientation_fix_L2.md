## 3. 高風險點（High-risk areas）

### 🔴 Critical Risk 1: Rotation Mapping 與 Sensor Orientation 不匹配

**風險描述**:
當前 rotation mapping 假設：
```
裝置方向 → Surface rotation
0-44°     → ROTATION_0 (0°)
45-134°   → ROTATION_270 (270°)
135-224°  → ROTATION_180 (180°)
225-314°  → ROTATION_90 (90°)
```

但實際 CameraX 需要的 targetRotation 公式為：
```
targetRotation = (sensorOrientation + deviceRotation + compensation) % 360
```

若 sensor orientation ≠ 270°，當前 mapping 可能完全錯誤。

**影響**:
- 所有方向照片都錯
- 前後鏡頭行為不一致

**緩解措施**:
1. **必須**在 bindToLifecycle 後立即 log sensor orientation
2. 根據 sensor orientation 動態調整 mapping（或使用 CameraX 提供的 rotation utility）
3. 考慮使用 `camera.cameraInfo.getSensorRotationDegrees(displayRotation)` 直接計算

**檢查清單**:
- [ ] Log sensor orientation（後置鏡頭）
- [ ] Log sensor orientation（前置鏡頭）
- [ ] 驗證 mapping 公式是否需要調整

---

### 🟡 Major Risk 2: onOrientationChanged 觸發延遲或遺漏

**風險描述**:
用戶報告「旋轉到 135° 再回到 90° 才正常」暗示：
- onOrientationChanged 在 90° 時沒有觸發
- 在 135° 時觸發了（因為跨越 135-224° 邊界）
- 回到 90° 時再觸發一次

可能原因：
1. OrientationEventListener 有內建的 **debounce/hysteresis**（防抖動）
2. 某些角度範圍內不會觸發回調
3. 加速度計數據不穩定，需要「明確」的角度變化才觸發

**影響**:
- 輕微旋轉（例如 0° → 30° → 0°）可能不會觸發
- 使用者需要「過度旋轉」才能讓 app 更新

**緩解措施**:
1. **降低 rotation threshold**（如果 OrientationEventListener 支援，但標準 API 不支援）
2. **使用 Display rotation 作為 fallback**（見 Plan B）
3. **在 onResume/onConfigurationChanged 強制更新**一次 rotation

**檢查清單**:
- [ ] 測試小角度旋轉（0° → 20° → 0°）是否觸發
- [ ] 測試邊界角度（43°/46°/133°/136°）是否觸發
- [ ] 考慮加入 Configuration change listener 作為補充

**目的**: 若 sensor orientation ≠ 270°，調整 mapping 邏輯

**程式碼**（範例：sensor orientation = 90°）:
```kotlin
override fun onOrientationChanged(orientation: Int) {
    if (orientation == ORIENTATION_UNKNOWN) return

    // Adjust mapping based on sensor orientation (90° sensor)
    val rotation = when (orientation) {
        in 45..134 -> Surface.ROTATION_90    // Landscape right
        in 135..224 -> Surface.ROTATION_180  // Upside down
        in 225..314 -> Surface.ROTATION_270  // Landscape left
        else -> Surface.ROTATION_0           // Portrait
    }

    if (rotation != currentRotation) {
        currentRotation = rotation
        updateTargetRotation(rotation)
        Log.d(TAG, "Orientation changed: $orientation° → rotation=$rotation")
    }
}
```

## 8. 已知限制與後續工作

### Phase 1 修復的限制
1. **不支援 Upside Down (180°) 偵測**
   - 大多數 Android 裝置預設禁用 180° 旋轉
   - OrientationEventListener 可以偵測，但 Display rotation 不會變成 ROTATION_180
   - 影響: 倒置拍照可能方向錯誤（實務上很少發生）

2. **OrientationListener 延遲**
   - 使用者快速旋轉時，可能有 100-300ms 延遲
