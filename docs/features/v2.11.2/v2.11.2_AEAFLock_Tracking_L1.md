## What（問題描述）

修復三個已在 Pixel 9a 實機測試中確認的問題：

| # | 問題 | 嚴重度 |
|---|------|--------|
| Bug A | AE/AF Lock 座標錯誤：長按 B 點，卻鎖定在 A 點 | 🔴 Critical |
| Bug B | AE/AF Lock 成功後無 3-phase 機械咬合動畫 | 🟡 High |
| Bug C | Optical Flow 追蹤效果差：頻繁丟失、不穩定 | 🟡 High |

## Why（根本原因）

### Bug A — 座標錯誤
`CameraViewModel.lockAEAF()` 清除了 ML Kit tracking（`trackedObjectId`），但**沒有停止 Optical Flow tracking**（`trackedPointActive` 仍為 true）。

`setupOpticalFlowTracking()` 的 callback 在 `lockAEAF()` 執行 async CameraX 操作期間，持續每幀寫入 `focusPoint`，用 A 點座標覆蓋剛設好的 B 點，導致：
- FocusIndicator 顯示在 A 點位置
- CameraX lock 也指向 A 點（因為 focusPoint 被覆蓋）

### Bug B — 無動畫
`LiveCameraSource.lockAEAF()` 用 `result.isFocusSuccessful` 判斷成功/失敗：

```kotlin
if (result.isFocusSuccessful) {
    continuation.resume(Result.success(Unit))   // 動畫路徑
} else {
    continuation.resume(Result.failure(...))    // 失敗路徑 → 無動畫
}
```

CameraX 的 `isFocusSuccessful` 表示「AF 是否完全收斂」，而**非鎖定是否套用**。在暗場景、主體移動、焦距邊界等情況下均可能回傳 `false`，即使鎖定已實際套用。

→ ViewModel 走失敗路徑：`focusSuccess = false`、`isAEAFLocked = false`、500ms 後清除指示器，用戶看不到任何反饋。

### Bug C — Tracking 效果差
`OpticalFlowConfig` DEFAULT 參數過於保守：
1. `redetectionInterval = 15`（每 15 幀 = 每 1s 重新偵測特徵點）
   → LK 每幀剔除失敗點，點集從 30 縮至個位數，RANSAC 判定 LOST
2. `ransacDistanceThreshold = 0.5`（threshold = max(3, 0.5×median)）
   → 小動作場景 threshold = 3px，抖動超過 3px 即大量剔除有效點

## 潛在風險

1. **LiveCameraSource 修改風險（低）**
   移除 `isFocusSuccessful` gate 後，`future.get()` 拋 exception 的情況仍由外層 catch 捕捉，`Result.failure` 正確傳遞。無回歸風險。

2. **OpticalFlowConfig CPU 風險（低-中）**
   `redetectionInterval: 15→5` 使 `goodFeaturesToTrack` 從每 1s 執行一次變為每 333ms。Pixel 9a Tensor G4 應可承受，需實機確認 FPS 無下降。

3. **競爭條件風險（低）**
   `stopOpticalFlowTracking()` 是設定 flag 的同步操作（無 IO/suspend），state update 在之後執行，順序明確。即使 OF callback 在極短窗口再觸發一次，`trackedPointActive = false` 確保不再處理。

## 驗證方法

| 場景 | 預期結果 |
|------|---------|
| 點 A 對焦 → 長按 B | 黃框在 B 點，不在 A |
| 長按任意點（任何光線） | 黃框 + 3-phase 動畫必定出現 |
| Optical Flow 追蹤 5 秒 | 追蹤穩定，不頻繁丟失 |
