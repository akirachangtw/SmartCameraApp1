# AE/AF Lock & Tracking Improvements (v2.11.2)

## Goal
Fix critical AE/AF Lock bugs and improve Optical Flow tracking stability on Pixel 9a.
This addresses requirements from `docs\features\v2.11.2\v2.11.2_AEAFLock_Tracking_L1.md`.

## User Review Required
> [!NOTE]
> **UX Change**: AE/AF Lock animation will now appear even if focus does not perfectly converge (e.g., low light). This is standard behavior for "Lock" features but differs from the previous strict success check.

> [!NOTE]
> **Performance**: Optical Flow feature re-detection frequency is increased (1s -> ~333ms). This is expected to be well within Pixel 9a capabilities but should be monitored for battery impact if left running for extended periods.

## Proposed Changes

### Presentation Layer
#### [MODIFY] [CameraViewModel.kt](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/presentation/camera/CameraViewModel.kt)
- **Bug A Fix**: In `lockAEAF()`, explicitly call `stopOpticalFlowTracking()` and set `trackedPointActive = false`. 
- This prevents the background Optical Flow analyzer from overwriting the user's manual lock point with old/drifting tracking coordinates.

### Data Layer
#### [MODIFY] [LiveCameraSource.kt](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/data/source/camera/LiveCameraSource.kt)
- **Bug B Fix**: In `lockAEAF()`, remove the `if (result.isFocusSuccessful)` check for the return value.
- The function will now return `Result.success(Unit)` as long as the lock request was sent to CameraX, ensuring the "Lock" animation plays.

#### [MODIFY] [OpticalFlowConfig.kt](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/data/opencv/OpticalFlowConfig.kt)
- **Bug C Fix**: Tune parameters for better stability.
    - `redetectionInterval`: 15 -> 5 (Improve feature replenishment rate)
    - `ransacDistanceThreshold`: 0.5f -> 1.0f (Allow slightly more motion tolerance before discarding points)

## Verification Plan

### Manual Verification
1.  **Verify Bug A (Coordinate Lock)**
    -   Point camera at Object A (wait for tracking/focus).
    -   Long press on Object B (different location).
    -   **Pass**: Yellow "Locked" box appears at B.
    -   **Fail**: Yellow box snaps back to A.

2.  **Verify Bug B (Animation)**
    -   Cover camera lens (force low light/focus fail).
    -   Long press anywhere.
    -   **Pass**: "AE/AF Locked" animation (yellow expansion) plays and lock indicator persists.
    -   **Fail**: No animation, UI remains in auto mode.

3.  **Verify Bug C (Tracking Stability)**
    -   Tap to track an object.
    -   Move camera moderately for 5-10 seconds.
    -   **Pass**: Tracking box stays on subject without frequent "lost" states.
