## 4. Root Cause Analysis

### 4.1 Performance Bottleneck Identification

**Hypothesis 1**: LiveCameraSource Overhead ⚠️
- **Evidence**: Emulator (StaticImageSource) is faster than real device (LiveCameraSource)
- **Impact**: YUV→Mat conversion + camera buffer management adds ~80ms overhead
- **Likelihood**: **HIGH**

**Hypothesis 2**: ARM CPU Slower Than Expected ⚠️
- **Evidence**: Best frame 88ms (vs emulator best 14ms)
- **Impact**: ARM Cortex may not be optimized for OpenCV operations
- **Likelihood**: **MODERATE**

**Hypothesis 3**: OpenCV Parameters Too Aggressive ✅
- **Evidence**: 10 lines detected (MAX_LINES = 10)
- **Impact**: Hough Transform processing all candidates
- **Likelihood**: **HIGH**

**Hypothesis 4**: Image Resolution Too High ⚠️
- **Evidence**: Unknown camera resolution (likely 1920x1080 or higher)
- **Impact**: Larger image = more pixels to process
- **Likelihood**: **MODERATE**

### 4.2 Profiling Data (from Logs)

**Processing Pipeline Breakdown** (estimated):
```
1. Bitmap.toGrayMat()         : ~20-30ms  (RGBA→Gray conversion)
2. Canny Edge Detection        : ~30-40ms  (Gradient + threshold)
3. Hough Line Transform        : ~40-60ms  (Line detection)
4. Line Filtering & Sorting    : ~10-20ms  (Top 10 lines)
5. Result Callback             : ~2-5ms    (StateFlow update)
---------------------------------------------------
Total                          : ~100-155ms (matches observed average)
```

**Bottleneck**: Steps 2+3 (Canny + Hough) account for **~70-100ms** (70-75% of total time).

## 6. Recommendations

### 6.1 Immediate Actions Required

#### Option A: Parameter Optimization (Recommended) 🔧

**Target**: Reduce Hough Transform complexity

**Changes to [GuidelineAnalyzer.kt](../app/src/main/java/com/akirachang/ai/photographer/data/source/analysis/GuidelineAnalyzer.kt)**:

```kotlin
// BEFORE (Current - Sprint 3)
private const val HOUGH_THRESHOLD = 50         // Minimum votes
private const val HOUGH_MIN_LINE_LENGTH = 50.0 // Minimum line length (pixels)
private const val MAX_LINES = 10               // Maximum lines to return
private const val MIN_LINE_STRENGTH = 0.3f     // Minimum strength threshold

// AFTER (Optimized - Sprint 4+)
private const val HOUGH_THRESHOLD = 70         // Increase to reduce false positives (+20)
private const val HOUGH_MIN_LINE_LENGTH = 80.0 // Longer lines only (+30 pixels)
private const val MAX_LINES = 6                // Reduce line count (-4)
private const val MIN_LINE_STRENGTH = 0.5f     // Stronger lines only (+0.2)
```

**Expected Impact**:
- Reduce Hough Transform candidates by ~40-50%
- **Estimated speedup**: 132.8ms → **60-80ms** (2x faster)
- **Tradeoff**: Fewer lines detected, but higher quality lines

#### Option B: Image Downsampling 📐

**Target**: Reduce input image resolution

**Changes to [ImageProxyExtensions.kt](../app/src/main/java/com/akirachang/ai/photographer/data/source/camera/ImageProxyExtensions.kt)**:

```kotlin
fun Bitmap.toGrayMat(): Mat {
    // Downsample to 640x480 for faster processing
    val scaledBitmap = Bitmap.createScaledBitmap(
        this,
        640,
        (640.0 * height / width).toInt(),
        true
    )

    val rgbaMat = Mat()
    Utils.bitmapToMat(scaledBitmap, rgbaMat)

    val grayMat = Mat()
    Imgproc.cvtColor(rgbaMat, grayMat, Imgproc.COLOR_RGBA2GRAY)

    rgbaMat.release()
    scaledBitmap.recycle()

    return grayMat
}
```

**Expected Impact**:
- Reduce pixel count by ~70% (assuming 1920x1080 → 640x480)
- **Estimated speedup**: 132.8ms → **40-60ms** (3x faster)
- **Tradeoff**: Lower line detection accuracy, especially for thin lines

#### Option C: Hybrid Approach (Best Balance) ⚡

**Combine Option A + Option B**:
1. Downsample to 800x600 (moderate reduction)
2. Increase HOUGH_THRESHOLD to 60 (moderate filtering)
3. Reduce MAX_LINES to 8

**Expected Impact**:
- **Estimated speedup**: 132.8ms → **30-40ms** (4x faster)
- **Tradeoff**: Balanced quality vs performance

### 6.2 Long-term Optimizations

1. **GPU Acceleration**: Use OpenCV CUDA (requires CUDA-capable device)
2. **Native C++ Implementation**: JNI-based GuidelineAnalyzer for reduced overhead
3. **Adaptive Parameters**: Adjust HOUGH_THRESHOLD based on scene complexity
4. **Frame Skipping**: Reduce sampling rate to 5 FPS (200ms intervals)
