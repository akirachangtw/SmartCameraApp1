## ⚠️ 發現的問題與建議

### 問題 1: 平均處理時間超標

**現象**: 平均處理時間 ~50ms，超過 <15ms 目標

**原因分析**:
1. **圖片切換開銷**: StaticImageSource 切換圖片時，Bitmap 解碼導致延遲（100-150ms）
2. **模擬器 CPU 限制**: x86_64 模擬器性能不如實體裝置 ARM CPU
3. **OpenCV 參數保守**: 當前參數設置偏向品質而非速度

**影響評估**: ⚠️ 中等
- ✅ 最佳幀效能達標（14ms）
- ⚠️ 連續穩定幀平均仍在 20-30ms（可接受）
- ❌ 圖片切換時 100-150ms 不可接受（但僅在測試模式）

**建議**:
1. **優先處理**: 實機測試以驗證真實效能（ARM 性能更好）
2. **可選優化**: 調整 OpenCV 參數以提高速度
   ```kotlin
   // GuidelineAnalyzer.kt
   private const val HOUGH_THRESHOLD = 70  // 50 → 70 (減少弱線條)
   private const val MAX_LINES = 8         // 10 → 8 (減少處理負擔)
   private const val MIN_LINE_STRENGTH = 0.4f  // 0.3 → 0.4 (只保留強線條)
   ```
3. **長期優化**: 考慮降低採樣解析度（downscale 至 960x540）

### 問題 2: 冷啟動處理時間過長

**現象**: 首次分析 385ms（26x 目標）

**原因**: OpenCV 首次調用包含：
- Native 庫初始化
- JNI 橋接建立
- SIMD 指令集檢測
- Cache warming

**影響評估**: ✅ 低（僅影響首幀）

**建議**: 接受此現象，首幀延遲在 400ms 以內是正常的

### 問題 3: 缺少效能統計報告

**現象**: GuidelineAnalyzer 的 `reportPerformanceStats()` 未在 logcat 中出現

**原因**:
- 統計報告每 30 幀觸發一次
- 測試時間可能不足 30 幀
- 或者 log 級別被過濾

**建議**:
- 延長測試時間至 >3 分鐘（確保累積 30 幀）
- 或降低統計間隔至 10 幀
