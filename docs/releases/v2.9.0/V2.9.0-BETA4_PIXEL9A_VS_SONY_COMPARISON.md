## Graphics Memory Analysis

### Graphics Memory by Resolution (MB)

```
Sony XQ-BT52 (all at 640x480):
Plan A: 47.5 MB
Plan B: 45.9 MB ⭐ (Best)
Plan C: 46.5 MB

Pixel 9a:
Plan A (640x480): 103.1 MB ⚠️
Plan B (640x480): 134.7 MB ❌ (WORST!)
Plan C (800x600): 121.8 MB ⚠️
Plan D (800x600): 107.2 MB ⚠️
```

### Why is Pixel 9a Graphics Memory So High?

**Hypothesis 1: Display Resolution**
- Pixel 9a: 1080x2424 (Full HD+)
- Sony XQ-BT52: Unknown (likely 1080x1920 or lower)
- Higher display resolution = larger Preview surface = more Graphics memory

**Hypothesis 2: GPU Architecture**
- Pixel 9a: Tensor G4 (Mali-G715)
- Sony: Snapdragon (Adreno)
- Different GPU architectures may allocate memory differently

**Hypothesis 3: CameraX Implementation**
- Pixel 9a may pre-allocate multiple buffers
- Sony may use more aggressive memory optimization

**Hypothesis 4: Android Version**
- Both should be similar (Android 14+)
- Unlikely to be the cause

### Critical Observation: Plan B Anomaly

**Plan B (640x480) on Pixel 9a has the WORST Graphics memory (134.7 MB)**

This is unexpected because:
- Plan A (same 640x480 resolution): 103.1 MB
- Plan C (higher 800x600 resolution): 121.8 MB
- Plan D (same 800x600 resolution): 107.2 MB

**Possible causes**:
1. Buffer pre-allocation based on target resolution
2. CameraX internal buffering strategy
3. Test order effect (Plan B was 2nd test, device was warming up)
4. Memory fragmentation

**Recommendation**: Re-test Plan B in isolation to confirm
