## 4. Root Cause Analysis: Why Limited Improvement?

### Processing Time Breakdown

**Sprint 4 Baseline (132.8ms average)**:
```
1. YUV→Bitmap Conversion (implicit):     ~35ms  (26%)
2. Bitmap.toGrayMat() (RGBA→Gray):       ~25ms  (19%)
3. Camera Buffer Management:             ~20ms  (15%)
------------------------------------------------
   Subtotal (Camera Pipeline):           ~80ms  (60%)

4. Canny Edge Detection:                 ~20ms  (15%)
5. Hough Line Transform:                 ~25ms  (19%)
6. Line Filtering & Sorting:             ~8ms   (6%)
------------------------------------------------
   Subtotal (OpenCV Processing):         ~53ms  (40%)

Total: ~133ms
```

**Sprint 5 Optimized (113.9ms average)**:
```
1. YUV→Bitmap Conversion (implicit):     ~35ms  (31%)
2. Bitmap.toGrayMat() (RGBA→Gray):       ~25ms  (22%)
3. Camera Buffer Management:             ~20ms  (17%)
------------------------------------------------
   Subtotal (Camera Pipeline):           ~80ms  (70%)  ⚠️ UNCHANGED

4. Canny Edge Detection:                 ~15ms  (13%)  ✅ -25%
5. Hough Line Transform:                 ~15ms  (13%)  ✅ -40%
6. Line Filtering & Sorting:             ~4ms   (4%)   ✅ -50%
------------------------------------------------
   Subtotal (OpenCV Processing):         ~34ms  (30%)  ✅ -36%

Total: ~114ms  (14.3% improvement)
```

### Key Insight

**Bottleneck**: Camera pipeline (Steps 1-3) accounts for **70% of total time** and is **completely unaffected** by OpenCV parameter changes.

**Why Improvement is Limited**:
- OpenCV optimization: 53ms → 34ms (**-36%** reduction) ✅
- Camera pipeline unchanged: 80ms → 80ms (**0%** reduction) ❌
- Total improvement: (53-34) / 133 = **14.3%** only

**Conclusion**: **Parameter tuning hit diminishing returns** because non-OpenCV overhead dominates.

## 8. v2.8.0 Optimization Roadmap

### Priority 2: Bypass Bitmap Conversion (Highest Impact) 🚀

**Goal**: Eliminate YUV→Bitmap→Mat double conversion

**Architectural Changes**:
1. Modify `CameraViewModel` to sample `ImageProxy` instead of `previewBitmap`
2. Update `GuidelineAnalyzer.analyze()` to use `ImageProxy` directly
3. Use existing `ImageProxy.toGrayMat()` (direct Y plane extraction)

**Expected Impact**:
- Camera pipeline: 80ms → **~10ms** (8x faster) ✅
- Total time: 113.9ms → **~55-65ms** (2x faster)
- **Result**: **ACCEPTABLE PERFORMANCE** (< 100ms target achieved)

**Code Changes Required**:
```kotlin
// CameraViewModel.kt
// BEFORE (Sprint 5):
previewBitmap
    .sample(100)
    .onEach { bitmap ->
        val result = guidelineAnalyzer.analyzeBitmap(bitmap)
        _guidelineResults.value = result
    }

// AFTER (v2.8.0):
// Sample ImageProxy directly from CameraInputSource
cameraInputSource.imageProxyFlow
    .sample(100)
    .onEach { imageProxy ->
        val result = withContext(Dispatchers.Default) {
            // Use existing ImageProxy.toGrayMat() (no Bitmap conversion!)
            guidelineAnalyzer.analyze(imageProxy)
        }
        _guidelineResults.value = result
    }
```

**Effort**: Medium (1-2 days)
**Risk**: Medium (requires new data flow, testing)
**Timeline**: v2.8.0

### Priority 3: Image Downsampling (If Needed)

**Goal**: Reduce input resolution to 800x600

**Expected Impact**: 55-65ms → **~35-45ms** (additional 1.5x faster)

**Tradeoff**: Lower line detection accuracy for thin/distant lines

**Timeline**: v2.8.0 (only if Priority 2 doesn't achieve < 50ms)
