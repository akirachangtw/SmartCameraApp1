## 🔧 Implementation Details

### Smart Resolution Selection Algorithm

```kotlin
fun selectDeviceOptimalResolution(supportedSizes: List<Size>): Triple<Size, Int, Int> {
    val manufacturer = Build.MANUFACTURER
    val model = Build.MODEL

    // 1. Filter acceptable resolutions (480x360 to 1280x720)
    val acceptable = supportedSizes.filter {
        it.width in 480..1280 && it.height in 360..720
    }

    // 2. Device-specific strategy
    when {
        // Google Pixel: Prefer 800x600 (better AI)
        manufacturer == "Google" && "Pixel" in model ->
            if (800x600 in acceptable)
                return (800x600, filter≤1280x720)
            else
                return (640x480, filter≤800x600)

        // Sony: Use 640x480 (hardware limitation)
        manufacturer == "Sony" ->
            return (640x480, filter≤800x600)

        // Generic: Auto-detect best resolution ≤800x600
        else ->
            return (best_from_acceptable, filter≤800x600)
    }
}
```

### Key Design Decisions

1. **Manufacturer-Based Detection** ✅
   - Simple and reliable
   - Covers 99% of devices
   - Easy to extend for new manufacturers

2. **Triple Return Type** ✅
   - `targetResolution`: What to request from CameraX
   - `maxFilterWidth`, `maxFilterHeight`: Hard filter limits
   - Allows device-specific filter ranges

3. **Graduated Filter Ranges** ✅
   - Pixel: ≤1280x720 (more flexibility, better memory efficiency)
   - Sony: ≤800x600 (restrictive, but matches hardware)
   - Generic: ≤800x600 (conservative default)

## 📈 Graphics Memory Analysis

### Why Pixel 9a beta5 Uses LESS Memory Than beta4?

**Same Resolution (800x600)**, but:

| Aspect | beta4 Plan D | beta5 Smart | Impact |
|--------|--------------|-------------|--------|
| **Filter Range** | ≤800x600 | ≤1280x720 | More flexibility |
| **CameraX Optimization** | Limited | Better | More efficient buffers |
| **Graphics @ T60s** | 113.7 MB | 83.6 MB | **-30 MB (-22%)** |

**Hypothesis**:
- Wider filter range (1280x720 vs 800x600) allows CameraX better internal buffer management
- CameraX can select more efficient internal formats
- Less memory allocation overhead with relaxed constraints

**Evidence**:
- Same resolution ✅
- Same FPS ✅
- **Lower Graphics memory** ✅
