## LOST Events 詳細分析

共 3 個 LOST，均為**單帲極端快速移動**引起，與 Phase 8 的 feedback loop 根本不同：

### LOST-1 (16:46:14.627) — 極端快速摆動
```
dist=52.4px → clamp    (追蹤正常)
dist=48.7px → clamp    (追蹤正常)
dist=38.2px → clamp    (追蹤正常)
dist=29.3px → clamp    (追蹤正常, inliers=7)
dist=22.8px → clamp    (追蹤正常, inliers=5)
dist=9.4px             (追蹤正常, inliers=5)
dist=33.3px → clamp    (inliers=4)
All 4 points lost LK   → LOST  ← 點集從 30 急降至 0
```
根因: 極快摆動導致點集逐幀急減，最終全部失敗。

### LOST-2 (16:46:51.129) — 垂直快速摆動
```
dist=71.9px → clamp    (inliers=20/30)
dist=95.5px → clamp    (inliers=17/17)  ← 垂直快速
dist=82.8px → clamp    (inliers=8/9)
RANSAC: inliers=1/valid=8 < minRequired=3  → LOST
```
根因: 單帲垂直位移 95px，超出 LK pyramid 搜尋能力。

### LOST-3 (16:47:34.708) — 急速移動
```
dist=7.3px             (quality=0.94, 正常)
dist=31.0px → clamp    (quality=0.58, 急速開始)
RANSAC: inliers=0/valid=15 < minRequired=6  → LOST
```
根因: 從靜止突然快速移動，單帲位移倍增導致 LK 無法匹配。

**結論**: 這些 LOST 均為 LK 光流本身的物理限制（單帲位移超出搜尋窗口範圍），非 bug。將在 Phase 9B/9C 透過 winSize 擴大 + Forward-Backward check 進一步改善。
