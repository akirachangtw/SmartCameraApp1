   - Analysis selector 可以維持 4:3 或 16:9 視模型需求（但需注意與 preview 協商影響）
3. **在 bind 完成後記錄實際 resolution**
   - 增加清楚 log：Preview/Analysis/Capture 最終 resolution、crop rect、rotation，作為後續 UI toggle 的驗證基準。
4. **評估是否需要調整 Preview 的 ScaleType**
   - 若要接近原生相機 FOV：通常避免過度 crop。可考慮在「16:9 模式」下改成 FIT_CENTER / FIT_*（或在 UI 上用 letterbox 呈現），但這會改變產品視覺。  
   - 最小差異路徑：**先用正確 aspect 的輸入**，盡量維持既有 scaleType 不動，觀察放大是否已顯著改善。

### Step B — 加入長寬比狀態（內部狀態先行，不上 UI 或先用 debug）
5. **新增 `AspectMode`（4:3 / 16:9 / 1:1）**
   - 在 camera pipeline 層（如 LiveCameraSource 的 config/state）集中管理。
6. **AspectMode → 三個 UseCase 同步套用**
   - Preview、ImageAnalysis、ImageCapture 都吃同一個 aspect 設定（至少 Preview & ImageCapture 必須一致以達 WYSIWYG）。
7. **1:1 的處理策略先定義清楚**
   - CameraX 不一定原生提供「1:1 輸出 size」；常見做法是：
     - Preview：仍用最接近的 sensor aspect（通常 4:3），UI 以 overlay 顯示 1:1 frame（或以 crop 顯示）
     - Capture：拍後 crop 成 1:1（或用 `OutputTransform` / 後處理 pipeline）
   - 最小差異：先做「拍照後 crop」，避免逼 CameraX 協商 1:1 size 造成不可預期。
8. **切換 AspectMode 走 rebind usecases**
   - 封裝成單一入口（例如 `rebindCamera(aspectMode)`），確保原 analyzer 移除、unbindAll、再 bind。

### Step C — 上 Toggle UI（最後才做）
9. **UI 只改 state，不直接動 CameraX 細節**
   - UI → ViewModel/StateFlow → LiveCameraSource 觸發 rebind。
10. **對齊 Pixel 相機交互**
   - 先做 3 段式 toggle（4:3 / 16:9 / 1:1），不做更複雜的手勢與動畫，降低風險。
