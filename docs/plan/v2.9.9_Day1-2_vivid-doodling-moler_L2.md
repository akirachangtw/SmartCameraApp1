## 2. 方案 B 可行性評估

### 2.1 實作方案

**修改檔案**：`OpticalFlowTracker.kt`（單一檔案）

**新增常數**：
```kotlin
companion object {
    // [新增] 速度限制：每幀最大位移（downsampled 座標系）
    private const val MAX_VELOCITY_PER_FRAME = 15f
}
```

**新增方法**：
```kotlin
/**
 * Clamp point velocity to prevent visual jitter
 * Limits maximum displacement per frame while preserving movement direction
 */
private fun clampVelocity(oldPoint: Point, newPoint: Point, distance: Float): Point {
    if (distance <= MAX_VELOCITY_PER_FRAME) {
        return newPoint
    }

    val scale = MAX_VELOCITY_PER_FRAME / distance
    val dx = newPoint.x - oldPoint.x
    val dy = newPoint.y - oldPoint.y

    return Point(
        oldPoint.x + dx * scale,
        oldPoint.y + dy * scale
    )
}
```

**修改 track() 方法**（line 227-229）：
```kotlin
if (isValid) {
    // [新增] 速度限制：限制每幀最大位移
    val clampedPoint = clampVelocity(trackedPoint!!, newPoint, distance)
    trackedPoint = clampedPoint  // 原本是 trackedPoint = newPoint
    ...
}
```

### 2.2 閾值設計

**MAX_VELOCITY_PER_FRAME = 15f 的依據**：

| 條件 | 值 | 說明 |
|------|-----|------|
| Downsample 比例 | ~0.5x | 640 / 1280 |
| 15px (downsampled) | ~30px (原始) | 原始座標系中的位移 |
| 正常手持移動 | 3-9px/frame | from L1 logcat 分析 |
| 異常跳動 | 30-35px/frame | from L1 logcat 分析 |
| 設定閾值 | 15px | 正常值的 1.5-5 倍，異常值的 0.5 倍 |

**效果預估**：
- 正常移動（<9px）：完全不受影響
- 異常跳動（35px → 15px）：位移減少 57%，視覺平滑
