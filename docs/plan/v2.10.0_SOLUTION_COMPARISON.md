## 核心差異對比

### 1. 1:1 模式解析度策略

#### 方案 A (Traycer)：動態正方形選擇

**策略**：優先尋找真正的正方形解析度，若不支援則 fallback

**實作**：
```kotlin
val commonSelector = if (currentAspectRatioMode == AspectRatioMode.RATIO_1_1) {
    ResolutionSelector.Builder()
        .setResolutionFilter { supportedSizes, _ ->
            // Step 1: 尋找正方形解析度
            val squareSizes = supportedSizes.filter { it.width == it.height }

            if (squareSizes.isNotEmpty()) {
                // Step 2: 選擇最接近 1920x1920 的正方形
                squareSizes.minByOrNull {
                    kotlin.math.abs(it.width - 1920)
                } ?: squareSizes.first()
                listOf(it)
            } else {
                // Step 3: Fallback - 選擇最接近 1:1 的解析度
                supportedSizes.minByOrNull { size ->
                    kotlin.math.abs(size.width.toFloat() / size.height - 1.0f)
                }?.let { listOf(it) } ?: supportedSizes
            }
        }
        .build()
}
```

**優點**：
- ✅ 若設備支援正方形，可獲得真正的 1:1 解析度
- ✅ 像素利用率高（不浪費 sensor 像素）
- ✅ 有多層 fallback 機制

**缺點**：
- ❌ ResolutionFilter 邏輯複雜，維護成本高
- ❌ 大多數設備**不支援真正的正方形解析度**（現實中 squareSizes 通常為空）
- ❌ Fallback 到「最接近 1:1」仍可能選到非正方形（如 4:5），WYSIWYG 仍可能破壞

---

#### 方案 B (Gemini)：4:3 Sensor + ViewPort 裁切

**策略**：接受現實（大多數 sensor 不輸出正方形），使用 4:3 + ViewPort 裁切

**實作**：
```kotlin
// 1:1 模式：使用標準 4:3 AspectRatioStrategy
val commonSelector = ResolutionSelector.Builder()
    .setAspectRatioStrategy(
        AspectRatioStrategy(
            AspectRatio.RATIO_4_3,  // 請求 4:3（最接近正方形的標準比例）
            FALLBACK_RULE_AUTO
        )
    )
    .build()

// ViewPort 定義 1:1 裁切區域
val viewPort = ViewPort.Builder(
    Rational(1, 1),  // 目標長寬比：1:1
    currentRotation
)
    .setScaleType(ViewPort.FIT)  // 保留完整 FOV
    .build()

// UseCaseGroup 統一應用 ViewPort
val useCaseGroup = UseCaseGroup.Builder()
    .addUseCase(preview)
    .addUseCase(imageAnalysis)
    .addUseCase(imageCapture)
    .setViewPort(viewPort)  // ✅ WYSIWYG 保證
    .build()
```

**優點**：
- ✅ **簡單可靠**：標準 CameraX 做法，所有設備都支援 4:3
- ✅ **WYSIWYG 絕對保證**：ViewPort 統一裁切 Preview/Capture/Analysis
- ✅ **裝置相容性高**：不依賴特定解析度支援
- ✅ **維護成本低**：邏輯清晰，符合 CameraX 官方建議

**缺點**：
- ⚠️ 實際 sensor 輸出 4:3，裁切到 1:1 會浪費約 25% 像素
- ⚠️ 依賴 CameraX 的 ViewPort 裁切機制（需 CameraX 1.3+）

---

### 2. 16:9 模式 FOV 修正

**兩方案一致**：都使用 `ViewPort.setScaleType(ViewPort.FIT)`

```kotlin
val viewPort = ViewPort.Builder(
    Rational(16, 9),
    currentRotation
)
    .setScaleType(ViewPort.FIT)  // ✅ 避免預設 FILL_CENTER 雙層裁切
    .build()
```

## 技術可行性評估

### 現實裝置支援度

根據 Android 生態系統調查：

| 解析度類型 | 支援度 | 代表設備 |
|-----------|-------|---------|
| **4:3** | ~99% | 幾乎所有設備 |
| **16:9** | ~95% | 大多數設備 |
| **1:1 正方形** | **~5%** | 極少數（主要是某些前鏡頭） |

**結論**：Traycer 方案的 `squareSizes.filter { it.width == it.height }` 在 **95% 設備上會返回空列表**，必定走 fallback 邏輯。

## 實際測試證據

### 當前問題根本原因（交接文檔）

**問題 1：1:1 WYSIWYG 破壞**
- **現象**：Preview 正方形，Capture 輸出 1440 x 1920 (3:4)
- **原因**：`AspectRatioMode.toCameraXAspectRatio` 將 1:1 fallback 到 `RATIO_4_3`
- **關鍵代碼**：`LiveCameraSource.kt:868`
```kotlin
val commonSelector = ResolutionSelector.Builder()
    .setAspectRatioStrategy(
        AspectRatioStrategy(
            currentAspectRatioMode.toCameraXAspectRatio,  // ❌ 1:1 → RATIO_4_3
            FALLBACK_RULE_AUTO
        )
    )
    .build()
```

**問題 2：16:9 FOV 過度裁切**
- **現象**：FOV 比 Sony 內建相機窄 30-40%
- **原因**：`ViewPort.Builder` 未設定 ScaleType，預設 `FILL_CENTER` 雙層裁切
- **關鍵代碼**：`LiveCameraSource.kt:933`
```kotlin
val viewPort = ViewPort.Builder(
    currentAspectRatioMode.toRational(),
    currentRotation
).build()  // ❌ 預設 FILL_CENTER
```

## 方案選擇建議

### 推薦方案：**Gemini 方案（方案 B）**

**理由**：

1. **符合現實**
   - 95% 設備不支援真正的正方形解析度
   - Traycer 方案在大多數設備上會走 fallback，增加不確定性

2. **技術成熟度**
   - Gemini 方案是 **CameraX 官方推薦做法**
   - ViewPort 裁切機制已在專案中驗證（v2.10.0）

3. **WYSIWYG 保證**
   - UseCaseGroup + ViewPort 統一裁切
   - Preview/Capture/Analysis 絕對一致

4. **實作成本**
   - **最小變更**：只需補上 `setScaleType(ViewPort.FIT)`
   - 當前架構已有 80% 完成度

5. **可預測性**
   - 4:3 是標準比例，所有設備支援
   - 效能影響可預測

---

### 混合方案（可選優化）

若希望在支援正方形的設備上獲得最佳像素利用率，可採用混合策略：

**階段 1**（必做）：實作 Gemini 方案
- 保證所有設備都有可靠的 1:1 WYSIWYG

**階段 2**（可選優化）：針對特定設備啟用真正的正方形
- 建立設備白名單（已驗證支援正方形的型號）
- 對白名單設備使用 Traycer 方案的 ResolutionFilter
- 其他設備維持 Gemini 方案

**優點**：
- ✅ 保證基礎可靠性（Gemini）
- ✅ 在支援的設備上優化像素利用率（Traycer）

**缺點**：
- ⚠️ 增加複雜度和測試成本
- ⚠️ 需維護設備白名單

## 實作計劃（基於 Gemini 方案）

### 修改範圍

**檔案 1**：`LiveCameraSource.kt`（2 處修改）

#### 修改 1：移除 1:1 的錯誤 fallback
```kotlin
// 當前（Line 866-873）
val commonSelector = ResolutionSelector.Builder()
    .setAspectRatioStrategy(
        AspectRatioStrategy(
            currentAspectRatioMode.toCameraXAspectRatio,  // ❌ 1:1 → RATIO_4_3
            FALLBACK_RULE_AUTO
        )
    )
    .build()

// 修改為
val commonSelector = ResolutionSelector.Builder()
    .setAspectRatioStrategy(
        AspectRatioStrategy(
            when (currentAspectRatioMode) {
                AspectRatioMode.RATIO_4_3 -> AspectRatio.RATIO_4_3
                AspectRatioMode.RATIO_16_9 -> AspectRatio.RATIO_16_9
                AspectRatioMode.RATIO_1_1 -> AspectRatio.RATIO_4_3  // ✅ 使用 4:3，由 ViewPort 裁切
            },
            FALLBACK_RULE_AUTO
        )
    )
    .build()

Log.i(TAG, "[v2.10.0] ResolutionSelector: ${currentAspectRatioMode.displayName} " +
           "(1:1 uses 4:3 sensor + ViewPort crop)")
```

#### 修改 2：設定 ViewPort.FIT
```kotlin
// 當前（Line 933-936）
val viewPort = ViewPort.Builder(
    currentAspectRatioMode.toRational(),
    currentRotation
).build()

// 修改為
val viewPort = ViewPort.Builder(
    currentAspectRatioMode.toRational(),  // Rational(1,1) for 1:1 mode
    currentRotation
)
    .setScaleType(ViewPort.FIT)  // ✅ 避免 FILL_CENTER 雙層裁切
    .build()

Log.i(TAG, "[v2.10.0] ViewPort: aspect=${currentAspectRatioMode.displayName}, " +
           "rotation=$currentRotation, scaleType=FIT")
```

**檔案 2**：`AspectRatioMode.kt`（可選 - 標註 Deprecated）

```kotlin
/**
 * 轉換為 CameraX AspectRatio 常數
 *
 * @deprecated v2.10.0: 1:1 模式應使用 ViewPort 裁切，而非 AspectRatioStrategy
 * 保留此方法僅供向後相容，請使用 ViewPort.Builder(toRational(), rotation) 替代
 */
@Deprecated(
    message = "Use ViewPort.Builder(toRational(), rotation) for 1:1 mode",
    replaceWith = ReplaceWith("toRational()")
)
val toCameraXAspectRatio: Int
    get() = when (this) {
        RATIO_4_3 -> AspectRatio.RATIO_4_3
        RATIO_16_9 -> AspectRatio.RATIO_16_9
        RATIO_1_1 -> AspectRatio.RATIO_4_3  // ⚠️ Deprecated: 應使用 ViewPort 裁切
    }
```
