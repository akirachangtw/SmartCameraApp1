## 3. 根因分析

### 3.1 直接原因

LK 光學流動追蹤在某些幀產生**低質量結果**（quality=0.80），但系統仍然採用該結果更新座標，導致視覺跳動。

### 3.2 可能觸發因素

1. **前置鏡頭自動曝光變化** — 亮度突變影響灰度圖
2. **人臉表情/角度變化** — 追蹤點外觀變化
3. **低紋理區域** — 皮膚等平滑表面 LK 容易失敗
4. **光線變化** — 環境光影響追蹤穩定性

### 3.3 現有機制不足

- ❌ 沒有基於 quality 的結果過濾
- ❌ 沒有速度/位移限制
- ❌ 單點追蹤容易受局部影響

## 5. 解決方案評估

### 方案 A：異常跳動過濾

**原理**：當 quality < 閾值 且 distance > 閾值 時，拒絕該幀結果

```kotlin
const val MIN_QUALITY_THRESHOLD = 0.85f
const val MAX_DISTANCE_THRESHOLD = 10f

if (quality < MIN_QUALITY_THRESHOLD && distance > MAX_DISTANCE_THRESHOLD) {
    // 忽略該幀，保持上一幀座標
    return lastValidPoint
}
```

| 優點 | 缺點 |
|------|------|
| 實作簡單 | 可能造成追蹤「凍結」感 |
| 直接解決跳動 | 閾值需要調優 |

---

### 方案 B：速度限制（推薦）

**原理**：限制每幀最大位移，超過則按比例縮小

```kotlin
const val MAX_DISTANCE_PER_FRAME = 15f // pixels

fun clampVelocity(oldPoint: PointF, newPoint: PointF): PointF {
    val dx = newPoint.x - oldPoint.x
    val dy = newPoint.y - oldPoint.y
    val distance = sqrt(dx * dx + dy * dy)

    if (distance > MAX_DISTANCE_PER_FRAME) {
        val scale = MAX_DISTANCE_PER_FRAME / distance
        return PointF(
            oldPoint.x + dx * scale,
            oldPoint.y + dy * scale
        )
    }
    return newPoint
}
```

| 優點 | 缺點 |
|------|------|
| 視覺平滑，無凍結感 | 快速移動時可能「跟不上」 |
| 實作簡單 | 需要根據幀率調整閾值 |
| 保持追蹤連續性 | - |

---

### 方案 C：多點 LK 追蹤（長期方案）

**原理**：追蹤多個特徵點，取中位數濾除異常

```kotlin
// 1. 在 tap 點周圍偵測角點
val corners = Imgproc.goodFeaturesToTrack(gray, maxCorners=10, ...)

// 2. 同時追蹤多點
Video.calcOpticalFlowPyrLK(prevGray, gray, prevCorners, nextCorners, status, err)

// 3. 濾除異常點，取中位數
val validPoints = nextCorners.filter { status[i] == 1 && err[i] < threshold }
val medianX = validPoints.map { it.x }.median()
val medianY = validPoints.map { it.y }.median()
```

| 優點 | 缺點 |
|------|------|
| 最穩定的追蹤 | 實作複雜度高 |
| 自然濾除異常 | 效能影響（需監控） |
| 長期方案 | 需要角點偵測調優 |

---

### 方案 D：A+B 組合

同時套用異常過濾 + 速度限制，雙重保護。
