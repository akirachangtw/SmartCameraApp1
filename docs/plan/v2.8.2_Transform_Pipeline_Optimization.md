# Implementation Plan - v2.8.2 Phase D: Transform Pipeline Optimization

## Goal Description
Optimize the camera preview pipeline to achieve 26+ FPS stability.
Currently, the pipeline runs YUV conversion in RenderScript (Phase C), but uses a slow CPU-based Canvas draw for Rotation and Mirroring (`transformBitmap`) in `LiveCameraSource`.
Phase D will move this Rotation and Mirroring logic into RenderScript to eliminate the CPU bottleneck and memory bandwidth overhead.

## User Review Required
> [!IMPORTANT]
> This change introduces a new RenderScript kernel `yuv_rotate.rs`.
> It modifies how `LiveCameraSource` produces the preview bitmap.

## Proposed Changes

### App Module

#### [NEW] [yuv_rotate.rs](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/rs/yuv_rotate.rs)
- Custom RenderScript kernel.
- Inputs: YUV allocation (NV21), Rotation Degrees, Mirror parameters.
- Output: ARGB Bitmap allocation (Rotated/Mirrored).
- Logic:
    - Compute source coordinates based on rotation/mirror.
    - Convert YUV to RGB using standard formula (or reuse intrinsic if possible, but combined is faster).
    - Writes directly to the output coordinate.

#### [MODIFY] [RenderScriptYuvConverter.kt](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/util/RenderScriptYuvConverter.kt)
- Add loading of `ScriptC_yuv_rotate`.
- Add method `convert(image: ImageProxy, outBitmap: Bitmap, rotation: Int, mirror: Boolean)`.
- If rotation == 0 and !mirror, can fallback to Intrinsic (optional, but consistent to use custom for all).
- Handle allocation resizing based on *output* dimensions (swapped W/H for 90/270 rotation).

#### [MODIFY] [LiveCameraSource.kt](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/data/source/camera/LiveCameraSource.kt)
- Remove `transformBitmap` function.
- Update `getPreviewStream` to calculate target width/height based on rotation.
- Acquire `rawBuffer` with the *final* dimensions (rotated).
- Call `renderScriptYuvConverter.convert` with rotation parameters.
- Remove the intermediate `rawBuffer` (unrotated) -> `outputBuffer` (rotated) copy step. This saves one full bitmap allocation/copy per frame!
