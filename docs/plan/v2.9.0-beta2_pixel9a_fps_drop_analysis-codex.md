原因（主因）

這個「跑 4–6 分鐘後開始掉」的型態，跨版本一致，且在 alpha 有明確 Thermal SEVERE 對應，最符合 Pixel 9a（Tensor G4）熱節流導致 CPU/GPU 降頻：每幀處理（YUV→RGB、transform、分析）變慢 → CameraX KEEP_ONLY_LATEST 會丟帧/降低 analyzer 回呼頻率 → 你看到的 FPS（多半是 app 內計算的處理 FPS）下降。
次因會讓熱節流更早出現：解析度被 CameraX 選到偏大（beta2 實際 1080x1080）與/或 Graphics 記憶體偏高，增加 GPU 帶寬與發熱，讓 FPS 更容易在後段掉。
建議怎麼確認是熱節流（把「猜」變成「證據」）

同步記錄 FPS + 溫度/降頻：adb shell cat /sys/class/thermal/thermal_zone*/temp、adb shell cat /sys/devices/system/cpu/cpu*/cpufreq/scaling_cur_freq（對齊你每 2 分鐘的 T0~T5）。
分開量「預覽 FPS」與「分析/處理 FPS」：PreviewView 可能仍 30fps 但 analyzer 掉；用 adb shell dumpsys gfxinfo <package> framestats 看 UI jank，避免把分析 FPS 當成畫面 FPS。
