# 相機問題分析與修復計畫 (v2.9.6)

針對使用者回報的三個關鍵問題進行深入代碼分析與修復方案規劃。

## 1. 問題分析

### 1.1 後置鏡頭橫向拍照方向錯誤
- **現象**: 橫向拍照時，照片方向不正確（可能旋轉了 90 度或未正確標記方向 EXIF）。
- **原因**: 
    1. `LiveCameraSource.kt` 中 `ImageCapture` 被強制設定為 `Surface.ROTATION_0` (Line 664)，未隨裝置實體方向改變。
    2. 目前的拍照流程是 `ImageProxy` -> `Bitmap` -> `再壓縮存檔`。**Bitmap 轉換過程會遺失 EXIF 方向資訊**。
    3. 雖然代碼中有手動旋轉 Bitmap 的邏輯 (Line 466)，但因為它是基於固定的 `ROTATION_0` 加上感測器角度計算，且最終存檔時缺乏 EXIF 標記，導致相簿 App 無法正確識別橫向照片。

### 1.2 APP 預覽畫面解析度很差
- **現象**: 預覽畫面模糊，明顯低於螢幕解析度。
- **原因**: 
    1. `LiveCameraSource.kt` 中存在「智慧解析度選擇」邏輯，但其 Fallback 機制過於保守。
    2. Line 1176 附近的邏輯顯示，如果沒有命中特定快取策略，系統會強制將解析度限制在 **800x600** 以下 (Line 1175: `return Triple(optimal, 800, 600)`).
    3. 對於現代高解析度手機螢幕 (1080p+)，800x600 的預覽被放大顯示時會非常模糊。

### 1.3 照片清晰度低於內建相機
- **現象**: 照片細節流失，不如原生相機清晰。
- **原因**: **二次壓縮 (Double Compression)**
    1. CameraX 拍攝原始 JPEG (ISP 處理後的高畫質影像)。
    2. App 將其解碼為 **Bitmap** (佔用大量記憶體且可能發生降樣)。
    3. App 再度將 Bitmap 壓縮為 JPEG (Quality 95)。
    - 這個過程不僅耗時、耗記憶體，更會導致畫質顯著下降（JPEG 有損壓縮累加）。

## 2. 實施計畫 (Implementation Plan)

### 2.1 [Critical] 重構拍照流程 (解決方向與畫質問題)
**目標**: 移除 Bitmap 中轉流程，直接使用 CameraX 的 `takePicture(OutputFileOptions)` API。

- **修改 `LiveCameraSource.kt`**:
    - 修改 `takePicture` 介面，接受 `File` 或 `OutputStream` 參數。
    - 使用 `imageCapture.takePicture(outputOptions, ...)` 直接存檔。
    - **優勢**: 
        - 自動處理 **EXIF Orientation** (不再需要手動旋轉 Bitmap)。
        - 速度更快 (零記憶體複製)。
        - **原始畫質** (保留 ISP 的優化結果)。

- **新增 `CameraOrientationListener`**:
    - 在 `LiveCameraSource` 中監聽裝置物理方向。
    - 動態更新 `imageCapture.targetRotation`，確保 CameraX 知道當前重力方向。

### 2.2 [Critical] 優化預覽解析度 (解決預覽模糊)
**目標**: 放寬解析度限制，允許 1080p 等級的預覽。

- **修改 `LiveCameraSource.kt`**:
    - `selectDeviceOptimalResolution`: 將過濾上限從 800x600 提升至 **1920x1080** 或更高。
    - 移除不必要的 `maxFilterWidth` 強制限制。
    - 確保在記憶體安全的前提下，優先選擇接近螢幕比例的高解析度 (如 16:9 的 1080p)。

### 2.3 驗證計畫
- **方向測試**: 測試 0° (直向), 90° (橫向左), 270° (橫向右) 拍照，檢查相簿顯示是否正確。
- **畫質測試**: 比較新舊版照片檔案大小與放大細節。
- **預覽測試**: 目測預覽畫面清晰度，並檢查 Log 中的 `Surface` 解析度輸出。

## 3. 風險評估
- **記憶體**: 提高預覽解析度會增加 Graphic Memory 用量。需確認 Pixel 9a 等記憶體敏感機型是否能承受 (可能需保留針對特定機型的限制，但 Sony/Pixel 旗艦機應放寬)。
- **分析效能**: `ImageAnalysis` (ML Kit) 使用的串流解析度應與 `Preview` 分離。建議保持 `ImageAnalysis` 在較低解析度 (如 VGA/720p) 以維持 AI 偵測速度，但讓 `Preview` 使用高解析度供使用者觀看。
