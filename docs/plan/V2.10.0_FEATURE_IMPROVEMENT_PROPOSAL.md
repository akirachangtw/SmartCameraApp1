# v2.10.0 Feature Improvement Proposal

這份提案針對以下三個功能進行整合改進的分析與建議方案：
1.  **長寬比 (Aspect Ratio) 設定移至 Settings**
2.  **GPS EXIF 功能修復與整合**
3.  **EXIF 詳細資訊顯示**

---

## 1. 長寬比設定移至 Settings (Move Aspect Ratio to Settings)

### 現狀分析
目前長寬比切換按鈕位於 `CameraScreen` 的頂部工具列 (`TopBar`)，與閃光燈、HDR 等常用功能並列。這佔用了寶貴的螢幕空間，且長寬比通常不是需要頻繁切換的選項，適合移至設定頁面以簡化主介面。

### 建議方案
*   **Data Layer**: 在 `OverlayPreferences` (DataStore) 中新增 `KEY_ASPECT_RATIO_MODE`，將長寬比狀態持久化儲存。
*   **ViewModel**:
    *   `CameraViewModel` 不再維護 `aspectRatioMode` 的記憶體狀態，改為觀察 `OverlayPreferences` 的 Flow。
    *   `SettingsViewModel` 新增讀寫 `aspectRatioMode` 的接口。
*   **UI Layer**:
    *   **SettingsScreen**: 新增 "Camera Resolution" 或 "Aspect Ratio" 區塊，使用 Radio Button 或 Dropdown Menu 讓使用者選擇 (4:3, 16:9, 1:1)。
    *   **CameraScreen**: 移除頂部的長寬比切換按鈕。

### 風險評估
*   **低風險**: 這是單純的 UI/UX 重構。唯一需注意的是在切換設定後回到相機預覽時，需要觸發 `bindToLifecycle` 或重新設定 `UseCaseGroup` 的 `ViewPort` (這在 `CameraViewModel` 觀察 Flow 時應自動處理)。

## 2. GPS EXIF 功能修復與整合 (Fix GPS EXIF Implementation)

### 現狀分析
*   `AndroidManifest.xml` 已宣告 `ACCESS_FINE_LOCATION` 和 `ACCESS_COARSE_LOCATION`。
*   `CameraRepositoryImpl` 中已有 `getLastLocation()` 與 `writeExifMetadata()` 邏輯，能在拍照後寫入 GPS 資訊。
*   **缺失環節**: `SettingsScreen` 只有一個簡單的 Switch Toggle，**沒有進行權限請求流程**。如果使用者未授權，開啟開關也不會有作用，導致功能失效。

### 建議方案
*   **UI Layer (SettingsScreen)**:
    *   使用 `Accompanist Permissions` 或 `ActivityResultLauncher` 實作權限請求。
    *   當使用者點擊 "GPS 位置標記" 開關時：
        1.  檢查是否已有權限。
        2.  若無權限，彈出系統權限請求對話框。
        3.  若使用者拒絕，顯示解釋性 UI (Rationale) 或導引至系統設定。
        4.  只有在獲得權限後，才允許將 `isGpsTaggingEnabled` 設定為 `true`。
*   **UI Layer (Main Screen)**:
    *   (可選) 在相機預覽介面顯示一個小的定位圖示 (如 `Icons.Default.LocationOn`)，指示目前 GPS 標記已啟用且定位成功。

### 風險評估
*   **中風險**:
    *   **權限拒絕**: 使用者可能永久拒絕權限，需妥善處理 fallback UI。
    *   **定位延遲**: `getLastLocation` 目前設定超時為 2秒。若完全無快取位置，可能會因為等待定位而影響寫入 EXIF 的即時性（目前已改為非同步處理，風險較低）。

## 3. EXIF 資訊顯示 (EXIF Info Display)

### 現狀分析
目前拍照成功後，僅顯示簡單的動畫或 Snackbar，使用者無法確認照片的具體參數（如 ISO, 快門, 是否成功寫入 GPS）。

### 建議方案
*   **新增 `ExifInfoDialog` Composable**:
    *   設計一個對話框，顯示關鍵 EXIF 資訊：
        *   **基本**: 光圈、快門、ISO、焦距。
        *   **檔案**: 解析度、檔案大小、路徑。
        *   **位置**: 經緯度 (若有)、海拔。
*   **觸發機制**:
    *   **選項 A (自動)**: 拍照後若開啟 "Debug Mode" 或 "Info Mode" 自動彈出。
    *   **選項 B (手動 - 推薦)**: 在拍照成功後的 Snackbar 上增加一個 "查看詳情" (Details) 的 Action Button。
    *   **選項 C (預覽區)**: 在畫面角落顯示上一張照片的縮圖，點擊後開啟預覽層，並提供 "Info" 按鈕。
*   **實作**:
    *   使用 `androidx.exifinterface.media.ExifInterface` 讀取剛剛儲存的檔案 URI。

### 風險評估
*   **低風險**: 這是純讀取與顯示功能。需注意 Android 10+ 的 Scoped Storage 存取權限，但因爲是讀取剛寫入的檔案，通常不需要額外權限。

---

## 執行計畫摘要

1.  **Phase 1 (Settings)**:
    *   修改 `OverlayPreferences` 加入長寬比。
    *   重構 `SettingsViewModel` 與 `CameraViewModel` 以同步長寬比設定。
    *   更新 `SettingsScreen` UI (加入長寬比選擇、實作 GPS 權限請求)。
2.  **Phase 2 (Cleanup)**:
    *   移除 `CameraScreen` 頂部的長寬比按鈕。
3.  **Phase 3 (Feature)**:
    *   實作 `ExifInfoDialog`。
    *   修改 `CameraRepository` 或 `ViewModel` 回傳 URI 後的邏輯，在 UI 層加入 "查看詳情" 的入口。
