# v2.9.0-beta4 Multi-Resolution Validation Test Plan

## Executive Summary

**Goal**: Test multiple resolution configurations (480x360, 640x480, 720x540, 800x600) to find optimal balance between AI accuracy and Graphics memory usage.

**Critical Success Criterion**: Maintain AI analysis accuracy (face detection, composition) while keeping Graphics memory < 120 MB @ 10 min.

**Test Device**: Pixel 9a (Tensor G4)

**Estimated Total Time**: 2-3 hours

---

## Test Configurations

### Resolution Options

| Plan | Resolution | Pixel Count | Aspect Ratio | Expected Graphics (T0) | Expected Graphics (T10) |
|------|-----------|-------------|--------------|----------------------|------------------------|
| **A (Baseline)** | 480x360 | 172,800 | 4:3 | ~35-45 MB | ~60-80 MB |
| **B (Current)** | 640x480 | 307,200 | 4:3 | ~45-60 MB | ~80-100 MB |
| **C (Recommended)** | 720x540 | 388,800 | 4:3 | ~55-70 MB | ~90-110 MB |
| **D (Maximum)** | 800x600 | 480,000 | 4:3 | ~65-80 MB | ~100-120 MB |

**Reference Points**:
- v2.8.6 (1080x1080 fallback): Graphics = 63.8 MB → 216 MB
- v2.9.0-beta2 (1080x1080): Graphics = 187 MB → 216 MB
- v2.9.0-beta4 Sony test (640x480): Graphics = 45.2 MB (T0)

## Test Methodology

### Method 1: Quick Switch (Recommended) ⚡

**Total Time**: ~20 minutes per resolution = **1.5 hours total**

**Process**:
1. Modify `LiveCameraSource.kt` Line 552: `val targetResolution = Size(X, Y)`
2. Run: `./gradlew assembleDeviceDebug installDeviceDebug`
3. Test on Pixel 9a for 10 minutes
4. Collect data and switch to next resolution

**Advantages**:
- Fast iteration
- No version number changes
- Easy to compare results side-by-side

**Disadvantages**:
- Cannot A/B test without recompiling
- Logcat may mix different versions

### Method 2: Standalone APKs 📦

**Total Time**: ~1 hour build + 1.5 hours test = **2.5 hours total**

**Process**:
1. Create 4 versions (v2.9.0-beta4a, beta4b, beta4c, beta4d)
2. Each version hardcoded with different resolution
3. Build all 4 APKs
4. Test each independently

**Advantages**:
- Can reinstall anytime for comparison
- Clear version separation in Logcat
- Better for long-term archiving

**Disadvantages**:
- Longer build time
- More disk space

## Test Procedures

### Phase 1: Objective Data Collection (Per Resolution)

**Duration**: 10 minutes

**Steps**:

1. **Install & Launch** (T0: 0 min)
   ```bash
   adb install -r app/build/outputs/apk/device/debug/app-device-debug.apk
   adb shell am start -n com.akirachang.ai.photographer/.MainActivity
   ```

2. **Capture Initial State** (T0: 0 min)
   ```bash
   # Resolution verification
   adb logcat -d | grep "v2.9.0-beta4 Resolution"
   # Expected: "ImageProxy actual size: 640x480, WithinFilter(<= 800px): true"

   # Graphics memory baseline
   adb shell dumpsys meminfo com.akirachang.ai.photographer | grep Graphics
   # Record: Graphics_T0
   ```

3. **Mid-point Check** (T5: 5 min)
   ```bash
   # FPS stability check
   adb logcat -d | grep "Performance: FPS="
   # Expected: 22-28 FPS (before thermal throttling)

   # Graphics memory growth
   adb shell dumpsys meminfo com.akirachang.ai.photographer | grep Graphics
   # Record: Graphics_T5
   ```

4. **Final State** (T10: 10 min)
   ```bash
   # Post-throttle FPS
   adb logcat -d | grep "Performance: FPS="
   # Expected: 15-23 FPS (after thermal throttling at 4-6 min)

   # Graphics memory final
   adb shell dumpsys meminfo com.akirachang.ai.photographer | grep Graphics
   # Record: Graphics_T10

   # BitmapPool health
   adb logcat -d | grep "v2.8.4 Pool"
   # Expected: HitRate > 90%
   ```

5. **Stop App**
   ```bash
   adb shell am force-stop com.akirachang.ai.photographer
   ```

### Phase 2: AI Accuracy Validation (Per Resolution)

**Duration**: 15 minutes (5 min per scenario)

**Test Setup**:
- Subject distance: 1 meter
- Lighting: Normal indoor/outdoor
- Expected: All resolutions should detect face successfully

2. Open app, wait for face detection

4. Check composition guide overlay

**Pass Criteria**:
- ✅ Face detection: < 1 second
- ✅ Face bounding box: Accurate (covers face within 10% margin)
- ✅ Composition guide: Visible and aligned

## Decision Matrix

### Evaluation Criteria

| Criterion | Weight | Target |
|-----------|--------|--------|
| **Graphics Memory (T10)** | 30% | < 120 MB |
| **FPS Stability** | 20% | > 20 FPS (post-throttle) |
| **AI Accuracy (Near 1m)** | 25% | Excellent |
| **AI Accuracy (Medium 2m)** | 20% | Good+ |
| **AI Accuracy (Far 4m)** | 5% | Optional |

### Scoring Rules

**Graphics Memory** (30 points):
- < 80 MB: 30 points (Excellent, matches v2.8.6)
- 80-100 MB: 25 points (Good)
- 100-120 MB: 20 points (Acceptable)
- 120-150 MB: 10 points (Poor)
- > 150 MB: 0 points (Fail)

**FPS Stability** (20 points):
- > 22 FPS: 20 points (Excellent)
- 20-22 FPS: 15 points (Good)
- 17-20 FPS: 10 points (Acceptable)
- < 17 FPS: 0 points (Fail)

**AI Accuracy Near 1m** (25 points):
- Excellent (< 1s, 100% stable, accurate bbox): 25 points
- Good (< 2s, > 90% stable, good bbox): 20 points
- Poor (> 2s or flickering): 10 points
- Fail (no detection): 0 points

**AI Accuracy Medium 2m** (20 points):
- Excellent (< 2s, 100% stable): 20 points
- Good (< 3s, > 80% stable): 15 points
- Poor (< 5s, > 50% stable): 10 points
- Fail (no detection): 0 points

**AI Accuracy Far 4m** (5 points):
- Excellent (< 3s, > 80% stable): 5 points
- Good (< 5s, > 50% stable): 3 points
- Poor (detected but unstable): 1 point
- Fail (no detection): 0 points (acceptable)

| A | 480x360 | 30 | 20 | 25 | 15 | 1 | **91** | #4 |
| B | 640x480 | 25 | 20 | 25 | 20 | 3 | **93** | #2 |

**Note**: Plan B (640x480) likely wins due to excellent AI accuracy at 2m while maintaining low memory.

## Risk Assessment

### Low Risk ✅
- All resolutions use ResolutionSelector (proven on Sony XQ-BT52)
- All resolutions ≤ 800px (filter guarantees)
- BitmapPool stable (v2.8.4 proven)

### Medium Risk ⚠️
- Plan A (480x360): May fail AI accuracy at 2m+
- Plan D (800x600): May exceed 120 MB Graphics on Pixel 9a
- Thermal throttling: Expected, not a bug (hardware limitation)

### High Risk 🔴
- None (all options are within safe bounds)

---

## Rollback Strategy

### If All Plans Fail Graphics Memory Target

**Option 1**: Accept 120-150 MB as new baseline (if AI accuracy critical)
- Document as known Pixel 9a behavior
- Update v2.9.0 release notes

**Option 2**: Revert to v2.8.6 approach
- Remove ResolutionSelector
- Accept 1080x1080 fallback (Graphics ~200 MB)
- Investigate alternative BitmapPool optimizations

### If All Plans Fail AI Accuracy

**Option 3**: Increase resolution to 1280x720 (720p)
- Modify filter: `width <= 1280 && height <= 720`
- Accept higher Graphics memory (~150-180 MB)
- Prioritize AI accuracy over memory
