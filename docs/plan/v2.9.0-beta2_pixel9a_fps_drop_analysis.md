# Investigation Report: Pixel 9a FPS Drop Analysis (v2.8.5 - v2.9.0)

## Executive Summary
This investigation confirms that the **FPS drop phenomenon** observed on Pixel 9a (starting normal, then dropping after ~5 minutes) is a consistent **Device Thermal Throttling** characteristic of the Pixel 9a (Tensor G4). It is **NOT** a software regression introduced in v2.8.6 or v2.9.0.

This behavior has been verified across three versions: **v2.8.5**, **v2.8.6**, and **v2.9.0-beta2**, all exhibiting the exact same pattern.

---

## Data Consolidation

The following table compares the FPS performance over a 10-minute test duration across versions:

| Metric | v2.8.5 (Baseline) | v2.8.6 (Phase 2) | v2.9.0-beta2 |
| :--- | :--- | :--- | :--- |
| **Initial FPS (0-2 min)** | 22 - 24 FPS | 25 - 28 FPS | 23 FPS |
| **Mid-Test FPS (4-6 min)** | **Drop to 12 - 14 FPS** | **Drop to 11 - 14 FPS** | **Drop to 16 FPS** |
| **Final FPS (8-10 min)** | 13 - 17 FPS (Recovery) | 12 - 16 FPS | 22 - 23 FPS (Recovery) |
| **Pattern** | 📉 Drop -> 📈 Recovery | 📉 Drop -> 📈 Recovery | 📉 Drop -> 📈 Recovery |
| **Lowest FPS Point** | **11.3 FPS** | **11.9 FPS** | **16.5 FPS** |

### Key Observations
1.  **Identical Drop Pattern**: All versions start with high FPS (>20) and experience a significant drop between the 4th and 6th minute.
2.  **Thermal Throttling Signature**: The "Drop -> Recovery" pattern is a classic signature of thermal throttling. The system limits performance to cool down, and once the temperature stabilizes, it allows a slight boost (Recovery).
3.  **v2.9.0 Improvement**: Interestingly, v2.9.0-beta2 managed to sustain a higher "Low point" (16.5 FPS) compared to v2.8.x (~11 FPS), likely due to the switch to RenderScript (GPU) which offloads the CPU, generating less heat or being more efficient.

## Detailed Analysis

### 1. The Phenomenon
> "FPS is normal in the first half, then drops significantly in the final stage."

**Yes, this phenomenon is confirmed.**
-   **Start**: The device is cool/warm. CPU/GPU runs at max frequency. App achieves 22-28 FPS.
-   **~5 Minutes**: Device temperature reaches the thermal threshold (Tensor G4 specific). System throttles CPU/GPU frequencies to prevent overheating.
-   **Impact**: App processing speed (YUV conversion + ML analysis) slows down, resulting in FPS dropping to ~11-16.

### 2. Is it a Regression?
**No.**
Comparing v2.8.5 (Baseline) and v2.8.6, the behavior is nearly identical.
-   **v2.8.5**: Dropped to 11.3 FPS.
-   **v2.8.6**: Dropped to 11.9 FPS.
-   **v2.9.0-beta2**: Dropped to 16.5 FPS (Actually **better**).

### 3. Conclusion
The FPS drop is an **inherent hardware characteristic** of running continuous, heavy ML + Camera workloads on the Pixel 9a. It is predictable and consistent.

## Recommendation
1.  **Accept as Known Behavior**: Do not treat the FPS drop as a bug to be "fixed" in code, but rather a constraint of the hardware.
2.  **Mitigation (v2.9.0)**: The move to RenderScript (GPU) in v2.9.0 already shows positive signs (min FPS increased from ~11 to ~16). We should proceed with this optimization.
3.  **User Expectation**: No action needed for user notification unless the drop makes the app unusable (which ~15 FPS is still usable for analysis).
