## 📋 任務概述

### What (任務目標)

**重構解析度選擇機制**,從品牌判斷邏輯改為硬體動態檢測:

1. **移除品牌依賴邏輯**
   - 刪除 Pixel Strategy (品牌字串判斷)
   - 刪除 Sony Strategy (品牌字串判斷)
   - 簡化 Generic Strategy (移除品牌假設)

2. **實作硬體動態檢測**
   - 初次安裝後首次啟動時執行檢測
   - 查詢 Camera2 API 獲取所有支援解析度
   - 檢測是否支援 800x600

3. **建立快取機制**
   - 儲存檢測結果到 SharedPreferences
   - 後續啟動直接讀取快取
   - 提供手動重新檢測功能

4. **保留 Fallback 機制**
   - 快取失效時自動重新檢測
   - 檢測失敗時使用預設 640x480

## 🎯 Why (為何需要)

### 1. 品牌判斷邏輯的問題

**問題案例: OnePlus CPH2381**

```kotlin
// 當前邏輯 (v2.9.0-beta5)
if (manufacturer.equals("Google", ignoreCase = true)) {
    // Pixel Strategy: 假設支援 800x600
    return Triple(Size(800, 600), 1280, 720)
}
// OnePlus 不符合任何品牌判斷,進入 Generic
// Generic 假設不支援 800x600,使用 640x480
```

**實際硬體**:
- OnePlus CPH2381 **支援 800x600** ✅
- 但被 Generic 策略誤判為不支援 ❌
- 結果: 錯過更好的解析度!

**測試數據證據** (7 款裝置):

| 裝置 | 品牌邏輯預測 | 實際硬體支援 | 結果 |
|------|------------|------------|------|
| Pixel 9a | ✅ 800x600 | ✅ 800x600 | 正確 |
| Pixel 10 Pro | ✅ 800x600 | ✅ 800x600 | 正確 |
| **OnePlus CPH2381** | ❌ 640x480 | ✅ 800x600 | **錯誤!** |
| Samsung S23 | ✅ 640x480 | ✅ 640x480 | 正確 |
| OPPO CPH2557 | ✅ 640x480 | ✅ 640x480 | 正確 |
| Sony XQ-BT52 | ✅ 640x480 | ✅ 640x480 | 正確 |

**錯誤率**: 1/7 = 14% (OnePlus 案例)

### 2. 無法適應未來機型

**場景 1: 2027 年 Samsung S25 支援 800x600**
```kotlin
// v2.9.0 邏輯: 假設所有 Samsung 不支援 800x600
// 即使 S25 硬體支援,APP 也無法利用
// 需要: 發布新版 APP,更新品牌邏輯
```

**場景 2: 新品牌 Vivo 支援 800x600**
```kotlin
// v2.9.0 邏輯: Vivo 不在品牌清單中
// 進入 Generic,假設不支援
// 需要: 測試 Vivo → 更新 APP → 重新發布
```

### 3. 維護成本高

**當前維護負擔**:
```kotlin
// 每發現一個新模式,都要更新邏輯
if (manufacturer.equals("Google", ignoreCase = true)) { ... }
else if (manufacturer.equals("Sony", ignoreCase = true)) { ... }
// 未來需要?
else if (manufacturer.equals("Xiaomi", ignoreCase = true)) { ... }
else if (manufacturer.equals("OnePlus", ignoreCase = true)) { ... }
else if (manufacturer.equals("Vivo", ignoreCase = true)) { ... }
// 無止境...
```

**測試負擔**:
- 每個品牌都要測試多款機型
- 每次 Android 版本更新都要重新驗證
- 品牌收購/合併可能改變策略 (如 OnePlus/OPPO)

### 4. 硬體檢測的優勢

**直接問硬體**:
```kotlin
// ✅ 簡單、直接、可靠
val supports800x600 = supportedSizes.any {
    it.width == 800 && it.height == 600
}
```

**自動適應**:
- ✅ 所有品牌通用
- ✅ 所有機型通用
- ✅ 未來機型自動支援
- ✅ 無需維護品牌清單

## ⚠️ 潛在風險

### 1. 權限時機問題 (高風險) 🔴

**問題描述**:
```kotlin
// Camera2 API 需要 CAMERA 權限
val cameraManager = context.getSystemService(Context.CAMERA_SERVICE) as CameraManager
val characteristics = cameraManager.getCameraCharacteristics(cameraId)
// ❌ 如果用戶尚未授予權限,這裡會拋出異常!
```

**風險場景**:
- 首次安裝時,用戶可能尚未授予相機權限
- 如果在權限前執行檢測 → SecurityException

**緩解策略**:
```kotlin
// ✅ 延遲到權限授予後執行
LaunchedEffect(permissionGranted) {
    if (permissionGranted && !capabilityDetector.isCapabilitiesCached()) {
        capabilityDetector.detectAndCacheCapabilities()
    }
}
```

**驗證方式**:
- 全新安裝 APP 測試
- 權限拒絕後重新授予測試
- 權限撤銷後重新啟動測試

### 2. 快取失效場景 (中風險) ⚠️

**場景 1: APP 版本更新**
```kotlin
// v2.9.5 → v2.9.6 升級
// 舊版快取可能不相容
```

**場景 2: 裝置硬體驅動更新**
```kotlin
// Android 系統更新可能改變 Camera HAL
// 支援的解析度可能變化
```

**場景 3: 快取損壞**
```kotlin
// SharedPreferences 檔案損壞
// 讀取時返回異常值
```

**緩解策略**:
```kotlin
fun shouldRecache(): Boolean {
    val cachedVersion = prefs.getString("app_version", "")
    val currentVersion = BuildConfig.VERSION_NAME

    return when {
        cachedVersion != currentVersion -> true  // APP 更新
        !prefs.contains("target_width") -> true  // 從未快取
        else -> false
    }
}
```

**驗證方式**:
- APP 更新測試 (v2.9.5 → v2.9.6)
- 手動刪除快取檔案測試
- 修改快取值為無效值測試

## 🔄 Fallback 機制

### 多層保護

```
Layer 1: 讀取快取
    ↓ (失敗)
Layer 2: Runtime 硬體檢測
    ↓ (失敗)
Layer 3: 預設 640x480
```

### 錯誤處理

```kotlin
fun getOptimalResolution(): Size {
    return try {
        // Layer 1: 快取
        getCachedStrategy()?.targetResolution
            ?: run {
                // Layer 2: Runtime 檢測
                val supports800x600 = detectHardwareSupport()
                if (supports800x600) Size(800, 600)
                else Size(640, 480)
            }
    } catch (e: Exception) {
        // Layer 3: 安全預設值
        Log.e(TAG, "Resolution detection failed, using fallback", e)
        Size(640, 480)
    }
}
```
