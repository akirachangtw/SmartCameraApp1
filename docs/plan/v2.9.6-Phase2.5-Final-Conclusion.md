## 執行摘要

Phase 2.5 成功升級 CameraX 1.4.1 → 1.4.2，將 **6/8 原生函式庫**從 4KB 對齊升級至 16KB 對齊（75% 成功率）。然而，剩餘的 **2 個 ML Kit 函式庫**仍維持 4KB 對齊，導致 **PageSizeMismatchDialog 仍出現**於實體 Pixel 9a 裝置上。

儘管警告對話框持續存在，**App 功能完全正常**，無任何效能或功能退化。此外，透過 `android:pageSizeCompat="enabled"` 屬性，App 已符合 Google Play 的 16KB 相容性要求。

## 🔍 根本原因分析

### 為何 6/8 修復仍不足以消除警告

#### Android 16 APK 檢查機制

```
APK Installation/Launch:
├─ 掃描所有 lib/arm64-v8a/*.so 檔案
├─ 檢查每個 .so 的 ELF LOAD segment alignment
├─ 若任一函式庫對齊 < 16KB
│  └─ 觸發 PageSizeMismatchDialog
└─ 政策：ALL-or-NOTHING（全部對齊或全部視為未對齊）
```

**關鍵發現**：
- ✅ 6/8 函式庫 16KB 對齊 = **75% 完成**
- ❌ 2/8 函式庫仍 4KB 對齊 = **觸發警告**
- ❌ Android 16 不採用「部分對齊」概念
- ❌ 一個未對齊函式庫 = 整個 APK 視為未對齊

### 為何 pageSizeCompat 無法抑制警告

#### pageSizeCompat 工作原理

```xml
<application android:pageSizeCompat="enabled">
```

**預期行為**：
- ✅ 在**真正 16KB 裝置** (PAGE_SIZE=16384) 上啟用向後相容模式
- ✅ 允許 4KB 對齊函式庫在 16KB 裝置上運行
- ✅ 抑制 PageSizeMismatchDialog

**實際限制**：
- ❌ 僅對**真正 16KB 裝置**有效
- ❌ 無法抑制 **4KB 裝置上的前瞻性警告**
- ❌ Pixel 9a 預設運行於 4KB 模式 (PAGE_SIZE=4096)
- ❌ 切換至真正 16KB 需解鎖 Bootloader（清除所有資料）

#### 裝置模式差異

| 裝置 | Architecture | PAGE_SIZE | pageSizeCompat 效果 | 警告狀態 |
|------|-------------|-----------|-------------------|---------|
| **Pixel9a-16KB Emulator** | x86_64 | **16384** | ✅ **有效** | ✅ 無警告 |
| **Pixel 9a Physical** | arm64-v8a | **4096** | ❌ **無效** | ❌ 有警告 |

### ML Kit Issue #987 解讀差異

#### GitHub Issue #987 聲稱

> "ML Kit itself is 16KB-aligned. The issue is with CameraX's transitive dependencies. **Solution: Upgrade CameraX to 1.4.2+**."

#### 實測結果

**CameraX 1.4.2 修復範圍**：
- ✅ CameraX 自身函式庫（libsurface_util_jni, libimage_processing_util_jni）
- ✅ CameraX-MLKit Vision 整合
- ❌ **獨立 ML Kit Face Detection**（我們使用的）
- ❌ **獨立 ML Kit Object Detection**（我們使用的）

**依賴關係差異**：
```
# CameraX-MLKit Vision (Issue #987 涵蓋)
androidx.camera:camera-mlkit-vision:1.4.2
└─ 內部包含 16KB 對齊的 ML Kit 函式庫

# 獨立 ML Kit (我們使用，Issue #987 不涵蓋)
com.google.mlkit:face-detection:16.1.5
com.google.mlkit:object-detection:17.0.1
└─ 獨立 AAR 檔案，仍為 4KB 對齊
```

## 🎓 關鍵學習

### 技術層面

1. **16KB 對齊是二進位層級問題**
   - 必須重新編譯 `.so` 檔案
   - 單純解壓縮或 ZIP 對齊無效

2. **Android 16 檢查機制嚴格**
   - ALL-or-NOTHING 政策
   - 一個未對齊 = 整個 APK 視為未對齊

3. **pageSizeCompat 有限制**
   - 僅對真正 16KB 裝置有效
   - 無法抑制 4KB 裝置前瞻性警告

4. **ML Kit Issue #987 範圍有限**
   - 僅涵蓋 CameraX-MLKit Vision 整合
   - 不涵蓋獨立 ML Kit 函式庫

### 專案管理層面

1. **階段性驗證重要**
   - Phase 2.4 模擬器通過 ≠ 實機通過
   - 必須在實機驗證

2. **依賴上游限制**
   - 閉源函式庫（ML Kit）無法自行修復
   - 需等待上游更新

3. **風險與回報評估**
   - Phase 2.5 已達 75% 修復
   - 剩餘 25% 風險高、回報低

4. **Google Play 政策理解**
   - 「支援 16KB」≠「零警告」
   - 功能正常即符合要求
