# Implementation Plan - v2.9.0 Resolution Fix (ResolutionSelector)

This plan addresses the **Graphics Memory Leak** in v2.9.0-beta2 caused by CameraX falling back to 1080x1080 instead of the requested 480x360.
We will replace the "soft hint" `setTargetResolution` API with the strict `ResolutionSelector` API (CameraX 1.3+).

## Goal Description
Force CameraX to select a resolution close to 480x360 (e.g., 640x480) and strictly prevent selecting 1080p (1920x1080 or 1080x1080), reducing Graphics memory usage.

## User Review Required
> [!IMPORTANT]
> `setTargetResolution` is deprecated/legacy behavior in newer CameraX versions and acts as a suggestion.
> We are migrating to `ResolutionSelector`, which provides a `ResolutionFilter` to explicitly filter out unwanted sizes (like > 1000px).

## Proposed Changes

### CameraX Configuration
#### [MODIFY] [LiveCameraSource.kt](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/data/source/camera/LiveCameraSource.kt)
-   Replace `setTargetResolution(Size(360, 360))` with `ResolutionSelector`.
-   Use `ResolutionStrategy` with `FALLBACK_RULE_CLOSEST_HIGHER_THEN_LOWER`.
-   Add `ResolutionFilter` to **HARD REJECT** any resolution where width or height > 800px.
    -   This guarantees 1080p is never selected.
    -   It will force 640x480 or similar.

```kotlin
val resolutionSelector = ResolutionSelector.Builder()
    .setResolutionStrategy(
        ResolutionStrategy(
            Size(480, 360),
            ResolutionStrategy.FALLBACK_RULE_CLOSEST_HIGHER_THEN_LOWER
        )
    )
    .setResolutionFilter { supportedSizes, _ ->
        supportedSizes.filter { it.width <= 800 && it.height <= 800 }
    }
    .build()

// Apply to ImageAnalysis and Preview
ImageAnalysis.Builder().setResolutionSelector(resolutionSelector)...
Preview.Builder().setResolutionSelector(resolutionSelector)...
```
