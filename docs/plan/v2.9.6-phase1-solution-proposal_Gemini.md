# v2.9.6 Phase 1 - Solution Proposal (Implementation Plan)

本文件針對 v2.9.6 Phase 1 測試報告指出的問題，提出具體可行的修復方案。
**目標**：在不破壞既有相機管線（Live/Static/Analysis）的前提下，修復 EXIF 遺失與預覽旋轉問題。

---

## 1. [BUG] 照片無 EXIF Orientation

### 問題分析
目前 `CameraRepositoryImpl.saveBitmapToMediaStore()` 使用 `bitmap.compress()` 直接寫入 JPEG 串流。Android 的 `Bitmap.compress` 僅處理圖像數據壓縮，**不會保留或寫入 EXIF Metadata**（包含 Orientation）。導致第三方相簿（或跨平台瀏覽）無法識別照片的正確方向。

### 建議方案
**在儲存完成後，補寫 EXIF Orientation Tag。**

由於我們的 `LiveCameraSource` 或 `ImageCapture` 產出的 Bitmap 已經經過旋轉處理（視覺上已是「正向」），因此我們只需要在 EXIF 中標記為 **"Normal" (1)**，告知檢視器「這張照片不需要再旋轉」即可。

### 實作步驟
修改 `CameraRepositoryImpl.kt` -> `saveBitmapToMediaStore()`：

1.  維持現有的 `contentResolver.insert` 和 `bitmap.compress` 流程（確保圖片資料寫入成功）。
2.  在 `outputStream` 關閉後，重新對該 URI 開啟 `ParcelFileDescriptor`：
    ```kotlin
    context.contentResolver.openFileDescriptor(uri, "rw")?.use { pfd ->
        val exif = ExifInterface(pfd.fileDescriptor)
        // 設定為 Normal (1)，因為 bitmap 內容已經是轉正的
        exif.setAttribute(ExifInterface.TAG_ORIENTATION, ExifInterface.ORIENTATION_NORMAL.toString())
        exif.saveAttributes()
    }
    ```
3.  **注意**：需匯入 `androidx.exifinterface.media.ExifInterface` (Jetpack版) 以獲得最佳相容性。

## 2. [BUG] 橫向旋轉時預覽畫面不正確 (Double Rotation)

### 問題分析
- **現狀**：APP 介面被鎖定在 Portrait 模式。
- **原因**：當使用者將手機轉為 Landscape 時，`LiveCameraSource` 的 `OrientationEventListener` 偵測到變化，並呼叫 `updateTargetRotation` 將 `imageAnalysis.targetRotation` 更新為 `ROTATION_90` 或 `ROTATION_270`。
- **後果**：
    - CameraX 的 `ImageAnalysis` 會試圖根據這個 targetRotation 調整輸出（例如交換寬高，或者改變 `rotationDegrees` metadata）。
    - 但我們的 `transformBitmap` 邏輯是自己計算旋轉角度。當 `imageAnalysis` 已經因為 targetRotation 改變了輸出的 `rotationDegrees`，而我們又再次疊加處理，或者因為 UI 鎖定導致座標系認知不一致，最終畫面呈現出「多轉了 90 度」或方向錯誤。
- **結論**：既然 UI 鎖定 Portrait，預覽串流（ImageAnalysis）應該始終認為自己處於 Portrait 環境，不應隨物理裝置旋轉而改變其「目標座標系」。

### 建議方案
**鎖定 ImageAnalysis 的 TargetRotation 為 ROTATION_0 (Portrait)。**

這樣 CameraX 會始終提供相對於 Portrait 的旋轉資訊（`rotationDegrees`），讓我們的 `transformBitmap` 負責單純的視覺旋轉，避免 CameraX 內部混淆。

### 實作步驟
修改 `LiveCameraSource.kt` -> `updateTargetRotation(rotation: Int)`：

1.  **分離 TargetRotation 設定**：
    - `imageCapture.targetRotation` = `rotation` (維持動態更新，確保原生拍照 metadata 正確，雖然我們後來轉 Bitmap，但保持邏輯一致較好)。
    - `imageAnalysis.targetRotation` = **`Surface.ROTATION_0` (固定)**。
    - `preview.targetRotation` = 若使用 PreviewView，可維持動態；若由我們自己畫 Bitmap，建議也隨由 UI 決定（即固定為 0）。

2.  **驗證**：
    - 啟動 App (Portrait)。
    - 手機轉 90 度。
    - 確認 `Log: Orientation changed` 觸發。
    - 確認預覽畫面中的物體依然垂直，沒有突然轉 90 度。

## 3. 驗證計畫

### A. EXIF 驗證
*   **測試案例**：
    *   TC-001: Portrait 拍攝。
    *   TC-002: Landscape Left 拍攝。
    *   TC-003: Landscape Right 拍攝。
*   **預期結果**：所有照片的 EXIF Orientation 均為 `1 (Normal)`。
*   **工具**：使用 `exiftool` 或線上 EXIF 檢視器檢查輸出檔案。

### B. 預覽旋轉驗證
*   **測試操作**：在 Live Preview 模式下，旋轉裝置至四個方向。
*   **預期結果**：預覽畫面始終保持「重力方向正確」（物體不倒），且不會出現畫面突然跳轉 90 度的情況。

*   確認 `switchCamera` (前後鏡頭切換) 功能正常。
*   確認存檔速度沒有明顯變慢（EXIF寫入應極快）。
