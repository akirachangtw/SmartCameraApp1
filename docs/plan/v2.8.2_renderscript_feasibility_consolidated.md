## 1. 執行摘要 (Executive Summary)

### 問題現狀

**Phase B-1 測試結果** (Integer Math 優化):
- YUV 轉換時間：44.4ms → 39.6ms (僅 -10.9%)
- FPS：16.0 → 16.2 (僅 +1.4%)
- **結論**: CPU 優化已達極限，瓶頸在 JNI 邊界與記憶體頻寬

**根本原因**:
```kotlin
// 307,200 像素 × 3 次 ByteBuffer.get() = 921,600 次 JNI 呼叫
for (y in 0 until height) {
    for (x in 0 until width) {
        val yValue = yBuffer.get(yRowOffset + x)  // ← JNI bottleneck
        val uValue = uBuffer.get(uvPixelIndex)    // ← JNI bottleneck
        val vValue = vBuffer.get(uvPixelIndex)    // ← JNI bottleneck
        // ...
    }
}
```

### 解決方案

**v2.8.2 Phase C: RenderScript GPU 加速**

**核心策略**:
1. 使用 Android `ScriptIntrinsicYuvToRGB` 執行 GPU 平行運算
2. 繞過 CPU 迴圈與 JNI 邊界檢查
3. 保留 Integer-based CPU fallback 機制

**預期效益**:
- YUV 轉換時間：39.6ms → **3-8ms** (5-13x 加速)
- FPS：16.2 → **28-30** (75-85% 提升)
- CPU 使用率：High (100% single core) → **Low** (GPU offload)

## 2. 技術可行性評估

### 2.1 為何選擇 RenderScript?

#### ✅ 優勢分析

| 評估維度 | RenderScript | Native C++ NEON | Vulkan Compute | OpenGL ES Shader |
|----------|--------------|-----------------|----------------|------------------|
| **開發複雜度** | 🟢 低 | 🟡 中 | 🔴 高 | 🔴 高 |
| **效能提升** | 🟢 5-10x | 🟡 1.5-2.5x | 🟢 10-20x | 🟢 8-15x |
| **相容性** | 🟡 API 17+ (有 deprecation) | 🟢 所有 ARM 裝置 | 🔴 API 24+, 需驗證 | 🟡 API 18+, 需 EGL |
| **實作時間** | 🟢 4-6 小時 | 🟡 8-12 小時 | 🔴 16-24 小時 | 🔴 12-20 小時 |
| **維護成本** | 🟢 低 | 🟡 中 | 🔴 高 | 🔴 高 |
| **Fallback 需求** | 🟢 需要 (CPU) | ❌ 不需要 | 🟢 需要 (老裝置) | 🟢 需要 (部分廠商) |

#### 為何不選其他方案？

**Native C++ NEON**:
- Phase B-1 已證明：即使用 integer math，記憶體存取仍是瓶頸
- NEON 只能加速運算，無法解決 `ByteBuffer.get()` 的 JNI overhead
- 預期僅 1.5-2.5x 提升，無法達成 30 FPS 目標

**Vulkan Compute / OpenGL ES**:
- 實作複雜度過高，需要 2-3 週開發時間
- 需要處理 EGL context、shader 編譯、同步機制
- 對當前專案 (API 24+) 投資報酬率低

**結論**: RenderScript 是**唯一能在可控成本內達成 30 FPS 目標**的方案。

### 2.2 RenderScript Deprecation 風險評估

#### 🟡 棄用狀態

**官方聲明** (Android 12, API 31):
> "RenderScript APIs are deprecated. They will continue to function, but we expect them to be removed in the future."

**實際情況**:
- ✅ Android 15 (API 35) 仍可使用 `renderscript.support.mode`
- ✅ Google Play 仍接受包含 RenderScript 的應用
- ⚠️ 未來 Android 版本可能移除 (時間未定)

#### 緩解策略

1. **使用 Support Library 模式**
   ```kotlin
   android {
       defaultConfig {
           renderscriptTargetApi = 21
           renderscriptSupportModeEnabled = true  // ← 關鍵設定
       }
   }
   ```
   - Support mode 將 RenderScript 編譯為 CPU fallback
   - 即使未來 Driver 移除，仍能在 CPU 上執行 (性能降低但不會 crash)

2. **保留 CPU Fallback**
   ```kotlin
   class YuvConverterFactory {
       fun create(): YuvConverterInterface {
           return try {
               RenderScriptYuvConverter(context)  // 優先 GPU
           } catch (e: Exception) {
               YuvConverter()  // Fallback to Integer CPU
           }
       }
   }
   ```

3. **長期遷移路徑**
   - v2.8.2 ~ v2.10: 使用 RenderScript (緊急修復)
   - v3.0+: 評估遷移到 Vulkan Compute (依裝置支援度決定)

**風險等級**: 🟡 **中風險** (可接受)
- 短期 (1-2 年): 安全
- 中期 (2-5 年): 需監控 Android 版本更新
- 長期 (5+ 年): 需遷移到 Vulkan

### 2.4 效能預期分析

#### 理論分析

**GPU 平行度**:
- CPU: 單執行緒循序處理 307,200 像素
- GPU: 假設 128 CUDA cores，平行處理 2,400 像素/batch
- 理論加速比：128x (實際約 5-10x，考慮 overhead)

**Memory Bandwidth**:
- CPU 路徑：Java → JNI → ByteBuffer → Pixel Array → Bitmap (4 次傳輸)
- GPU 路徑：Allocation (shared memory) → GPU → Bitmap (1-2 次傳輸)

#### 實際測試參考 (業界數據)

| 裝置 | CPU YUV Time | RenderScript YUV Time | 加速比 |
|------|--------------|----------------------|--------|
| Pixel 4 (SD 855) | 35ms | 4ms | 8.75x |
| Galaxy S10 (Exynos 9820) | 40ms | 6ms | 6.67x |
| OnePlus 7T (SD 855+) | 32ms | 3ms | 10.67x |

**Sony XQ-BT52 預測** (SD 690):
- CPU Integer: 39.6ms (實測)
- RenderScript 預期: **5-8ms** (保守估計 6.5x 加速)
- 預期 FPS: **28-30** (vs 目標 26+) ✅

## 3. 實作計畫評估

### 3.1 架構設計

#### 方案 A: Feasibility 文件提議 (簡化版)

```kotlin
class RenderScriptYuvConverter(context: Context) {
    private val rs = RenderScript.create(context)
    private val script = ScriptIntrinsicYuvToRGB.create(rs, Element.U8_4(rs))

    fun convertToBitmap(image: ImageProxy, reuseBitmap: Bitmap): Bitmap {
        // 1. 建立 Allocation (每幀都要重建！效能不佳)
        val yuvAlloc = Allocation.createFromBitmap(...)
        val outAlloc = Allocation.createFromBitmap(rs, reuseBitmap)

        // 2. 執行轉換
        script.setInput(yuvAlloc)
        script.forEach(outAlloc)

        // 3. 複製結果
        outAlloc.copyTo(reuseBitmap)
        return reuseBitmap
    }
}
```

**問題**:
- ❌ 每幀都重新建立 `Allocation` → 額外 5-10ms overhead
- ❌ 未考慮 YUV 4:2:0 格式的 Plane 分離
- ❌ 未整合 BitmapPool

#### 方案 B: Plan 文件提議 (優化版)

```kotlin
class RenderScriptYuvConverter(context: Context) {
    private val rs = RenderScript.create(context)
    private val script = ScriptIntrinsicYuvToRGB.create(rs, Element.U8_4(rs))

    // 重用 Allocation (關鍵優化！)
    private var yuvAlloc: Allocation? = null
    private var outAlloc: Allocation? = null
    private var lastWidth = 0
    private var lastHeight = 0

    fun convertToBitmapBuffer(image: ImageProxy, buffer: BitmapPool.BitmapBuffer) {
        val width = image.width
        val height = image.height

        // 重建 Allocation 僅在尺寸變化時
        if (width != lastWidth || height != lastHeight) {
            yuvAlloc?.destroy()
            outAlloc?.destroy()

            val yuvType = Type.Builder(rs, Element.U8(rs))
                .setX(width)
                .setY(height)
                .setYuvFormat(android.graphics.ImageFormat.YUV_420_888)
                .create()
            yuvAlloc = Allocation.createTyped(rs, yuvType, Allocation.USAGE_SCRIPT)

            val rgbType = Type.Builder(rs, Element.RGBA_8888(rs))
                .setX(width)
                .setY(height)
                .create()
            outAlloc = Allocation.createTyped(rs, rgbType, Allocation.USAGE_SCRIPT)

            lastWidth = width
            lastHeight = height
        }

        // YUV → Allocation (零拷貝或快速路徑)
        yuvAlloc!!.copyFrom(image.planes[0].buffer)  // Y plane
        // TODO: 處理 U/V planes (需要 interleave)

        // GPU 轉換
        script.setInput(yuvAlloc)
        script.forEach(outAlloc)

        // Allocation → Bitmap
        outAlloc!!.copyTo(buffer.bitmap)
    }

    fun destroy() {
        yuvAlloc?.destroy()
        outAlloc?.destroy()
        script.destroy()
        rs.destroy()
    }
}
```

**優點**:
- ✅ 重用 `Allocation`，避免每幀重建 (節省 5-10ms)
- ✅ 整合 `BitmapPool.BitmapBuffer`
- ✅ 支援尺寸變化 (Live/Static 模式切換)
- ✅ 明確的資源釋放機制

**待解決**:
- ⚠️ YUV 4:2:0 的 U/V plane 需要 interleave 處理
- ⚠️ `copyFrom()` 是否支援 `ImageProxy.planes[0].buffer` 需驗證

#### 推薦方案

**採用方案 B (Plan 文件)，並補充**:
1. YUV Plane 處理邏輯 (參考 Android SDK samples)
2. 異常處理 (初始化失敗時拋出 exception，由 Factory 捕捉)
3. 效能日誌 (與 Phase A/B 一致的 `[v2.8.2]` tag)

#### Step 2: RenderScriptYuvConverter 實作 🟡 **需補充細節**

**Feasibility 文件問題**:
- ❌ 未說明如何處理 YUV 4:2:0 的 Plane 分離
- ❌ 未考慮 Allocation 重用

**Plan 文件優勢**:
- ✅ 明確提到 "Manages Allocation lifecycle"
- ✅ 提到 "Zero GC" (暗示重用機制)

**關鍵技術挑戰**:

**Challenge 1: YUV Plane Interleaving**

`ScriptIntrinsicYuvToRGB` 需要 NV21 格式 (Y + interleaved UV)，但 `ImageProxy` 提供 YUV_420_888 (Y + separate U + V)。

**解決方案**:
```kotlin
// 需要先將 U/V planes interleave 成 NV21 格式
fun imageProxyToNV21(image: ImageProxy): ByteArray {
    val yPlane = image.planes[0]
    val uPlane = image.planes[1]
    val vPlane = image.planes[2]

    val ySize = yPlane.buffer.remaining()
    val uSize = uPlane.buffer.remaining()
    val vSize = vPlane.buffer.remaining()

    val nv21 = ByteArray(ySize + uSize + vSize)

    // Copy Y
    yPlane.buffer.get(nv21, 0, ySize)

    // Interleave U and V into NV21 format (VUVUVU...)
    var pos = ySize
    for (i in 0 until uSize) {
        nv21[pos++] = vPlane.buffer.get(i)  // V first (NV21)
        nv21[pos++] = uPlane.buffer.get(i)  // U second
    }

    return nv21
}
```

**Impact**:
- ⚠️ 額外記憶體分配 (640×480×1.5 = 460KB per frame)
- ⚠️ CPU 時間 ~2-3ms (interleaving loop)
- **總時間預估**: 2-3ms (CPU interleave) + 3-5ms (GPU convert) = **5-8ms** ✅ 仍符合目標

**Challenge 2: Allocation 零拷貝**

Feasibility 文件提到 "USAGE_SHARED 嘗試零拷貝"，但實際上：
- `USAGE_SHARED`: Android 8+ 支援，與 `HardwareBuffer` 共享記憶體
- `ImageProxy`: CameraX 提供的 buffer 可能不支援 direct mapping

**實際策略**:
```kotlin
// 方案 1: 嘗試零拷貝 (僅 Android 8+)
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
    yuvAlloc = Allocation.createTyped(
        rs, yuvType,
        Allocation.USAGE_SHARED or Allocation.USAGE_SCRIPT
    )
    // 嘗試直接對接 ImageProxy buffer (需驗證)
} else {
    // 方案 2: 傳統拷貝
    yuvAlloc = Allocation.createTyped(rs, yuvType, Allocation.USAGE_SCRIPT)
    yuvAlloc.copyFrom(nv21ByteArray)  // 2-3ms overhead
}
```

**結論**: 先實作方案 2 (穩定)，後續優化方案 1 (Android 8+ 加速)。

#### Step 3: Fallback 機制 ✅ **設計合理**

**Feasibility 文件**:
> 保留原有的 YuvConverter (Integer implementation) 作為 Fallback

**Plan 文件**:
> (未明確提及，但隱含在 "Keep HandlerThread" 中)

**建議實作**:
```kotlin
interface YuvConverterInterface {
    fun convertToBitmapBuffer(image: ImageProxy, buffer: BitmapPool.BitmapBuffer)
    fun destroy()
}

class YuvConverterFactory(private val context: Context) {
    fun create(): YuvConverterInterface {
        return if (BuildConfig.ENABLE_RENDERSCRIPT) {
            try {
                Log.i(TAG, "[v2.8.2] Attempting RenderScript GPU converter")
                RenderScriptYuvConverter(context)
            } catch (e: Exception) {
                Log.w(TAG, "[v2.8.2] RenderScript failed, fallback to CPU", e)
                YuvConverter()  // Integer CPU fallback
            }
        } else {
            Log.i(TAG, "[v2.8.2] RenderScript disabled, using CPU converter")
            YuvConverter()
        }
    }
}
```

**優點**:
- ✅ 運行時偵測 RenderScript 可用性
- ✅ 編譯時開關 (BuildConfig flag)
- ✅ 詳細日誌追蹤

## 5. 風險與緩解措施

### 5.1 技術風險

| 風險 | 機率 | 影響 | 緩解措施 | 狀態 |
|------|------|------|----------|------|
| **RenderScript 棄用** | 🟡 中 (5 年內) | 🟡 中 | Support mode + CPU fallback | ✅ 已規劃 |

### 9.1 完整 RenderScriptYuvConverter 架構

```kotlin
package com.akirachang.ai.photographer.util

import android.content.Context
import android.graphics.Bitmap
import android.renderscript.*
import androidx.camera.core.ImageProxy
import android.util.Log

/**
 * v2.8.2 Phase C: GPU-accelerated YUV to RGB converter using RenderScript
 *
 * Performance target:
 * - YUV conversion time: < 8ms (vs 39.6ms CPU Integer)
 * - Expected FPS: 28-30 (vs 16.2 CPU)
 *
 * Fallback: If RenderScript initialization fails, throws exception
 * (Caller should catch and use YuvConverter as CPU fallback)
 */
class RenderScriptYuvConverter(context: Context) : YuvConverterInterface {

    private val TAG = "RenderScriptYuvConverter"

    // RenderScript context and script
    private val rs: RenderScript = RenderScript.create(context)
    private val script: ScriptIntrinsicYuvToRGB = ScriptIntrinsicYuvToRGB.create(
        rs,
        Element.U8_4(rs)
    )

    // Reusable allocations (避免每幀重建)
    private var yuvAlloc: Allocation? = null
    private var outAlloc: Allocation? = null
    private var lastWidth = 0
    private var lastHeight = 0

    // Reusable NV21 buffer for YUV interleaving
    private var nv21Buffer: ByteArray? = null

    init {
        Log.i(TAG, "[v2.8.2] RenderScript YUV converter initialized")
    }

    override fun convertToBitmapBuffer(image: ImageProxy, buffer: BitmapPool.BitmapBuffer) {
        val width = image.width
        val height = image.height

        // Recreate allocations only when size changes
        if (width != lastWidth || height != lastHeight) {
            reallocate(width, height)
        }

        // Step 1: Convert ImageProxy YUV_420_888 to NV21 format
        val startInterleave = System.nanoTime()
        val nv21 = imageProxyToNV21(image)
        val interleaveTime = (System.nanoTime() - startInterleave) / 1_000_000.0

        // Step 2: Copy NV21 to RenderScript Allocation
        val startCopy = System.nanoTime()
        yuvAlloc!!.copyFrom(nv21)
        val copyTime = (System.nanoTime() - startCopy) / 1_000_000.0

        // Step 3: GPU YUV to RGB conversion
        val startConvert = System.nanoTime()
        script.setInput(yuvAlloc)
        script.forEach(outAlloc)
        val convertTime = (System.nanoTime() - startConvert) / 1_000_000.0

        // Step 4: Copy result to Bitmap
        val startOutput = System.nanoTime()
        outAlloc!!.copyTo(buffer.bitmap)
        val outputTime = (System.nanoTime() - startOutput) / 1_000_000.0

        val totalTime = interleaveTime + copyTime + convertTime + outputTime

        // v2.8.2 Performance logging (every 30 frames)
        if (System.currentTimeMillis() % 2000 < 100) {  // Approximate logging
            Log.d(TAG, "[v2.8.2 GPU Timing] Total=${"%.1f".format(totalTime)}ms " +
                      "(Interleave=${"%.1f".format(interleaveTime)}ms, " +
                      "Copy=${"%.1f".format(copyTime)}ms, " +
                      "GPU=${"%.1f".format(convertTime)}ms, " +
                      "Output=${"%.1f".format(outputTime)}ms)")
        }
    }

    /**
     * Convert ImageProxy YUV_420_888 planes to NV21 format
     * NV21 format: [Y plane] + [V U V U V U ...] (interleaved)
     */
    private fun imageProxyToNV21(image: ImageProxy): ByteArray {
        val width = image.width
        val height = image.height
        val yPlane = image.planes[0]
        val uPlane = image.planes[1]
        val vPlane = image.planes[2]

        val ySize = width * height
        val uvSize = ySize / 2  // YUV 4:2:0 subsampling

        // Reuse buffer if size matches
        if (nv21Buffer == null || nv21Buffer!!.size != ySize + uvSize) {
            nv21Buffer = ByteArray(ySize + uvSize)
        }
        val nv21 = nv21Buffer!!

        // Copy Y plane
        yPlane.buffer.rewind()
        if (yPlane.pixelStride == 1) {
            // Contiguous Y plane - fast path
            yPlane.buffer.get(nv21, 0, ySize)
        } else {
            // Padded Y plane - slow path
            for (row in 0 until height) {
                yPlane.buffer.position(row * yPlane.rowStride)
                yPlane.buffer.get(nv21, row * width, width)
            }
        }

        // Interleave U and V planes into NV21 format (VUVUVU...)
        uPlane.buffer.rewind()
        vPlane.buffer.rewind()

        var pos = ySize
        val uvWidth = width / 2
        val uvHeight = height / 2

        for (row in 0 until uvHeight) {
            val uRowOffset = row * uPlane.rowStride
            val vRowOffset = row * vPlane.rowStride

            for (col in 0 until uvWidth) {
                val uvIndex = uRowOffset + col * uPlane.pixelStride
                nv21[pos++] = vPlane.buffer.get(vRowOffset + col * vPlane.pixelStride)  // V
                nv21[pos++] = uPlane.buffer.get(uvIndex)  // U
            }
        }

        return nv21
    }

    /**
     * Reallocate RenderScript buffers when image size changes
     */
    private fun reallocate(width: Int, height: Int) {
        Log.i(TAG, "[v2.8.2] Reallocating allocations for ${width}x${height}")

        // Destroy old allocations
        yuvAlloc?.destroy()
        outAlloc?.destroy()

        // Create YUV input allocation (NV21 format)
        val yuvType = Type.Builder(rs, Element.U8(rs))
            .setX(width)
            .setY(height)
            .setYuvFormat(android.graphics.ImageFormat.NV21)
            .create()
        yuvAlloc = Allocation.createTyped(rs, yuvType, Allocation.USAGE_SCRIPT)

        // Create RGB output allocation
        val rgbType = Type.Builder(rs, Element.RGBA_8888(rs))
            .setX(width)
            .setY(height)
            .create()
        outAlloc = Allocation.createTyped(rs, rgbType, Allocation.USAGE_SCRIPT)

        lastWidth = width
        lastHeight = height
    }

    override fun destroy() {
        Log.i(TAG, "[v2.8.2] Destroying RenderScript resources")
        yuvAlloc?.destroy()
        outAlloc?.destroy()
        script.destroy()
        rs.destroy()
    }
}
```

### 9.2 YuvConverterFactory 實作

```kotlin
package com.akirachang.ai.photographer.util

import android.content.Context
import android.util.Log

interface YuvConverterInterface {
    fun convertToBitmapBuffer(image: androidx.camera.core.ImageProxy, buffer: BitmapPool.BitmapBuffer)
    fun destroy()
}

class YuvConverterFactory(private val context: Context) {

    companion object {
        private const val TAG = "YuvConverterFactory"
    }

    fun create(): YuvConverterInterface {
        // BuildConfig.ENABLE_RENDERSCRIPT is set in build.gradle.kts
        return if (BuildConfig.ENABLE_RENDERSCRIPT) {
            try {
                Log.i(TAG, "[v2.8.2] Attempting to create RenderScript GPU converter")
                RenderScriptYuvConverter(context).also {
                    Log.i(TAG, "[v2.8.2] ✅ RenderScript GPU converter created successfully")
                }
            } catch (e: Exception) {
                Log.w(TAG, "[v2.8.2] ❌ RenderScript initialization failed, falling back to CPU", e)
                YuvConverter().also {
                    Log.i(TAG, "[v2.8.2] ✅ CPU Integer converter created (fallback)")
                }
            }
        } else {
            Log.i(TAG, "[v2.8.2] RenderScript disabled via BuildConfig, using CPU converter")
            YuvConverter()
        }
    }
}
```
