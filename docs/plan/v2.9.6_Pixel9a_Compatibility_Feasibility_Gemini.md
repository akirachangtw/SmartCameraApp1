
# v2.9.6 Pixel 9a Compatibility & Optimization Feasibility Plan

## 1. Executive Summary

Based on the physical device test results (`v2.9.6-Phase2.1`), the SmartCameraApp shows excellent functional compatibility with the Pixel 9a (Android 16), achieving a 100% pass rate in core test cases. However, two key areas for compatibility and user experience improvement were identified:
1.  **16KB Page Size Compatibility**: Android 16 displays a `PageSizeMismatchDialog` warning due to native libraries (OpenCV, ML Kit) lacking 16KB alignment.
2.  **EXIF Metadata**: Photos lack EXIF Orientation tags, causing potential display issues on non-Android platforms (e.g., Windows PC).

This plan outlines the feasibility analysis and proposed solutions for these items.

---

## 2. Issue Analysis & Feasibility

### 2.1 16KB Page Alignment (Android 15+ Requirement)

**Observation**: 
On app startup, the system displays a warning: *"This app uses native libraries that are not aligned to 16KB page boundaries."* (Affected libs: `libopencv_java4.so`, `libface_detector_v2_jni.so`, etc.)

**Root Cause**: 
Use of upstream pre-compiled libraries (OpenCV 4.13.0, ML Kit) which are built with 4KB memory page alignment. Android 15 and 16 (on compatible devices like Pixel 9 series) optionally enforce or warn about 16KB alignment support.

**Feasibility of Solutions**:

| Approach | Description | Feasibility | Pros | Cons |
| :--- | :--- | :--- | :--- | :--- |
| **A. Recompile Libraries** | Rebuild OpenCV/libjni from source with `-z max-page-size=16384` linker flag. | **Medium** | True fix. | ML Kit is closed source (cannot recompile). Significant effort for OpenCV. |
| **B. Native Lib Extraction (Workaround)** | Set `android:extractNativeLibs="true"` (via `useLegacyPackaging = true`). | **High** | Easy config change. Bypasses strict mmap alignment requirements by extracting files. | Increases app install size on device. |
| **C. Wait for Upstream** | Wait for Google ML Kit and OpenCV releases. | **High** | No effort. | Passive; warning persists until update. |

**Recommendation (Phase 2.2)**: 
Adopt **Option B (Native Lib Extraction)** immediately as a temporary workaround to eliminate the user-facing warning. Continue monitoring Option C for the long-term fix.

> **Status Update**: This change has been tentatively added to `build.gradle.kts` in the `v2.9.6-phase2.2` code branch and requires verification in the next test cycle.

### 2.2 EXIF Orientation Tags

**Observation**: 
Photos taken in device-correct orientations display incorrectly on PC (e.g., Portrait shown as Landscape).

**Root Cause**: 
CameraX `ImageCapture` saves raw pixel data matching the sensor readout but does not automatically write the `Exif.TAG_ORIENTATION` metadata when `ImageCapture.OnImageCapturedCallback` is used without file output options handling.

**Feasibility of Solution**:

| Approach | Description | Feasibility | Implementation Details |
| :--- | :--- | :--- | :--- |
| **CameraX Metadata** | Manually construct `Exif` header from `ImageProxy` rotation degrees and inject into JPEG bytes. | **High** | Requires `androidx.exifinterface` (already included). |

**Recommendation (Phase 3)**:
Implement manual EXIF injection in the `ImageSaver` or `PhotoRepository` class. This is a low-risk, high-value fix involving standard Android APIs.

    2. Copy files to Windows PC.
    3. distinct Verify Windows Photo Viewer displays them with correct "Up" orientation.
