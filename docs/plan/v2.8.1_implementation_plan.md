# v2.8.1 FPS & Memory Optimization Plan

## Goal Description
Fix severe FPS drops on Sony devices and Memory Growth on Pixel devices.
Analysis confirmed that `LiveCameraSource` performs heavy YUV-to-Bitmap conversion on the Main Thread, causing UI jank. Additionally, per-frame Bitmap allocation causes high GC pressure.

## User Review Required
> [!IMPORTANT]
> **Thread Change Risk**: Moving the analyzer to a background thread is required to fix FPS. This changes the timing of when `previewBitmap` allows collection. We must ensure `CameraViewModel` collects the flow safely (it currently uses `stateIn` which is safe, but we must verify no other Main-Thread-Only assumptions exist in the flow chain).

> [!WARNING]
> **Bitmap Pooling**: Implementing a Bitmap Pool means the `Bitmap` emitted in the flow will be **mutable and reused**. Observers must **not** hold onto the Bitmap reference across frames without copying it, or they will see corrupted data when the next frame overwrites usage.

## Proposed Changes

### Camera Source Layer
#### [MODIFY] [LiveCameraSource.kt](file:///d:/MyDocuments/DevSources/AndroidStudioProjects/SmartCameraApp1/app/src/main/java/com/akirachang/ai/photographer/data/source/camera/LiveCameraSource.kt)
-   **Threading Fix**: Change `imageAnalysis.setAnalyzer` executor from `ContextCompat.getMainExecutor(context)` to a background executor (e.g., `Executors.newSingleThreadExecutor()` or `Dispatchers.Default` based).
-   **Memory Optimization**: Introduce `BitmapPool` (Simple `ArrayDeque` or optimized pool) to reuse `Bitmap` instances.
-   **YUV Conversion**: Modify `toBitmap()` to write into an existing recycled Bitmap instead of creating a new one.

### Utilities

1.  **Sony FPS Test**:

2.  **Pixel Memory Test**:

    -   Monitor PSS (Profiler or `dumpsys meminfo`).

3.  **Visual Correctness**:
