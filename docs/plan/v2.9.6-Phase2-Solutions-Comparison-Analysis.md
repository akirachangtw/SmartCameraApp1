## 2. Official Android Documentation Analysis

### 2.1 Source

**URL**: https://developer.android.com/guide/practices/page-sizes?hl=zh-tw
**Title**: "支援 16 KB 頁面大小"
**Last Updated**: 2025 (includes Android 16 guidance)

### 2.2 Official Solutions

The official documentation provides **three solutions**:

#### Solution 1: Recompile with NDK 27 (Ideal)

**Recommended for**: Apps that control their native library source code

**Method**:
```bash
-Wl,-z,max-page-size=16384
```

**Pros**:
- Best performance
- Native 16KB support
- No warnings

**Cons**:
- Not applicable for third-party libraries (OpenCV, ML Kit)
- Requires NDK 27+

#### Solution 2: AGP 8.5.1+ Automatic Alignment (Modern)

**Documentation Quote**:
> "Android Gradle plugin (AGP) 8.5.1 and higher versions automatically handle 16 KB ZIP alignment for Android 15 and higher."

**What This Means**:
- **Our project uses AGP 8.10.1** ✅
- AGP automatically aligns APK ZIP structures to 16KB boundaries
- **No manual configuration needed** (useLegacyPackaging not required)
- Libraries can remain 4KB-aligned (ELF), but APK (ZIP) is 16KB-aligned

**Critical Discovery**: This invalidates Gemini's `useLegacyPackaging` recommendation.

#### Solution 3: 16 KB Backward Compatibility Mode (Official Workaround)

**Documentation Quote**:
> "Devices with 16 KB page size support a special backward compatibility mode for apps that bundle unaligned native libraries. Note that apps run less efficiently in this mode."
>
> "To prevent the warning dialog shown to users at app install time, set the `android:pageSizeCompat="enabled"` attribute in the AndroidManifest.xml file."

**Implementation**:
```xml
<application android:pageSizeCompat="enabled">
```

**What This Does**:
1. Explicitly enables backward compatibility mode
2. **Suppresses PageSizeMismatchDialog** at install time
3. Allows app to run with 4KB-aligned libraries
4. Signals to Google Play that app is aware of 16KB requirements

**Performance Impact**:
- "Apps run less efficiently" (documented)
- Acceptable for transition period
- No measurable impact on our app (FPS remains 18-22)

### 2.3 Key Differences from Gemini's Plan

| Aspect | Gemini's Plan | Official Documentation |
|--------|---------------|------------------------|
| **Primary Solution** | `useLegacyPackaging = true` | `android:pageSizeCompat="enabled"` |
| **Configuration Location** | Gradle (build.gradle.kts) | Manifest (AndroidManifest.xml) |
| **Number of Files Modified** | 3 (Manifest + app + opencv gradle) | 1 (Manifest only) |
| **AGP 8.5+ Awareness** | ❌ Not mentioned | ✅ Automatic ZIP alignment |
| **Storage Impact** | +10-15 MB (extraction) | No additional storage |
| **Warning Suppression** | ❌ Indirect (didn't work) | ✅ Direct (official attribute) |
| **Google Play Alignment** | ⚠️ Workaround | ✅ Official solution |

## 3. Why Phase 2.2/2.3 Failed

### 3.1 Phase 2.2 Implementation

**What We Did** (following Gemini's plan):
1. ✅ Added `android:extractNativeLibs="true"` to AndroidManifest.xml
2. ✅ Added `jniLibs { useLegacyPackaging = true }` to app/build.gradle.kts

**Expected Result** (from Gemini):
- Libraries extract to filesystem
- No PageSizeMismatchDialog

**Actual Result**:
- ❌ Libraries **did** extract to filesystem
- ❌ PageSizeMismatchDialog **still appeared**

### 3.2 Phase 2.3 Implementation

**What We Did** (root cause hypothesis):
1. ✅ Added `jniLibs { useLegacyPackaging = true }` to opencv/build.gradle
2. ✅ Ensured **all** modules configured for legacy packaging

**Hypothesis**:
- Phase 2.2 only configured app module
- OpenCV module might need separate configuration
- AGP 8.x doesn't propagate packaging settings to library modules

**Actual Result**:
- ❌ Libraries **still** extracted correctly
- ❌ PageSizeMismatchDialog **still appeared**

### 3.3 Root Cause Analysis

#### Verification Evidence (Phase 2.3)

**Libraries Successfully Extracted**:
```bash
$ adb shell ls -la /data/app/.../lib/arm64/
-rwxr-xr-x 1 system system 23972544 1981-01-01 01:01 libopencv_java4.so
-rwxr-xr-x 1 system system  7610736 1981-01-01 01:01 libface_detector_v2_jni.so
-rwxr-xr-x 1 system system  8857296 1981-01-01 01:01 libmlkitcommonpipeline.so
# ... (8 libraries total)
```

**OpenCV Loaded Successfully**:
```
01-26 23:04:54.643 D nativeloader: Load /data/app/.../lib/arm64/libopencv_java4.so using class loader ns clns-10: ok
01-26 23:04:54.643 D OpenCV/StaticHelper: Library opencv_java4 loaded
```

**But Warning Still Appeared**:
```
01-26 23:04:54.660 W AppWarnings: Showing PageSizeMismatchDialog for package com.akirachang.ai.photographer
```

#### The Real Problem

**Timing of the Check**:
- Android 16 analyzes APK **at installation time**
- System checks library alignment **in the APK file**
- This happens **before** `extractNativeLibs` takes effect
- **After** libraries are extracted, it's too late - warning already triggered

**Why useLegacyPackaging Failed**:
1. `useLegacyPackaging` tells AGP to mark libraries for extraction
2. AGP sets `android:extractNativeLibs="true"` in manifest
3. At **install time**: Android sees 4KB-aligned libs in APK
4. Android triggers PageSizeMismatchDialog (APK analysis)
5. **Later**: Android extracts libraries (runtime preparation)
6. Result: **Warning appears despite successful extraction**

**Visual Timeline**:
```
APK Installation Flow:
├─ 1. APK Analysis (Android checks lib alignment in ZIP)
│  └─ ❌ Finds 4KB-aligned libs → Trigger PageSizeMismatchDialog
├─ 2. Warning Dialog (shown to user)
│  └─ User sees: "This app uses native libraries..."
├─ 3. Library Extraction (extractNativeLibs="true")
│  └─ ✅ Libraries extracted to /data/app/.../lib/
└─ 4. Runtime (app launches)
   └─ ✅ Libraries loaded successfully

Phase 2.2/2.3 Fixed Step 3 and 4, but NOT Step 1 and 2
```

### 3.4 Why Gemini's Analysis Was Incomplete

**Gemini's Assumption**:
> "此設定強制在安裝時將 `.so` 檔解壓縮至儲存空間，而非直接從 APK 進行 `mmap`。"

**What Gemini Missed**:
1. Extraction happens, but **warning triggers first**
2. Android checks APK contents **before** extraction
3. `useLegacyPackaging` doesn't prevent the initial warning
4. **The warning is the problem**, not the runtime behavior

**What Gemini Should Have Recommended**:
- Use `android:pageSizeCompat="enabled"` to suppress the warning
- Let AGP 8.10.1 handle automatic alignment (no useLegacyPackaging needed)

## 6. 16KB Backward Compatibility Mode Deep Dive

### 6.1 What Is Backward Compatibility Mode?

**From Official Documentation**:
> "Devices with 16 KB page size support a special backward compatibility mode for apps that bundle unaligned native libraries. Note that apps run less efficiently in this mode."

**Technical Details**:

#### Memory Page Management
- **Normal Mode (16KB-aligned apps)**:
  - Libraries loaded directly via `mmap()`
  - Memory pages aligned to 16KB boundaries
  - Direct hardware page support
  - **Optimal performance**

- **Compatibility Mode (4KB-aligned apps)**:
  - System creates compatibility layer
  - Translates 4KB pages to 16KB pages
  - Additional memory mapping overhead
  - **Slight performance reduction**

#### How Android Detects Which Mode to Use

```
App Installation Analysis:
├─ Check 1: Native libraries present?
│  ├─ Yes → Continue to Check 2
│  └─ No → Normal mode (no native code)
├─ Check 2: Libraries 16KB-aligned?
│  ├─ Yes → Normal mode (optimal)
│  └─ No → Continue to Check 3
├─ Check 3: pageSizeCompat attribute present?
│  ├─ pageSizeCompat="enabled" → ✅ Compatibility mode (no warning)
│  ├─ pageSizeCompat="disabled" → ❌ Show warning
│  └─ Missing → ❌ Show PageSizeMismatchDialog (default behavior)
```

### 6.2 Performance Impact Analysis

**Official Statement**:
> "Note that apps run less efficiently in this mode."

**What This Means for Our App**:

#### Measured Impact (from Phase 2.1 testing):
- **Camera Preview FPS**: 18-22 (unchanged from Android 15)
- **AI Detection Latency**: ~50ms (within normal range)
- **Memory Usage**: ~150-200 MB (normal for ML Kit)
- **Battery Impact**: No noticeable difference

#### Why Impact Is Minimal:
1. **GPU-bound workload**: Camera preview uses GPU (not affected by CPU page size)
2. **ML Kit optimization**: Google's libraries optimized for various configurations
3. **Small native code surface**: Most app logic is Kotlin (JVM), not native

#### Theoretical Impact Areas:
- ⚠️ **Native library loading**: One-time cost at app startup (+50-100ms)
- ⚠️ **JNI calls**: Slight overhead on OpenCV calls (~1-2% slower)
- ⚠️ **Memory overhead**: Potential +5-10 MB for page alignment padding

**Verdict**: Performance impact is **acceptable** for a transition solution.

### 6.3 Google Play Compliance

**Official Requirement** (from documentation):
> "自 2025 年 11 月 1 日起，提交至 Google Play 的所有新應用程式和現有應用程式更新，如指定搭載 Android 15 (API 級別 35) 以上版本的裝置，都必須支援 16 KB 頁面大小。"
