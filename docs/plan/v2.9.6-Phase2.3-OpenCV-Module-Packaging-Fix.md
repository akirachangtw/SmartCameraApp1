## Problem Background

### Phase 2.2 Failure Analysis

**What Phase 2.2 Did**:
1. ✅ Set `android:extractNativeLibs="true"` in AndroidManifest.xml
2. ✅ Set `useLegacyPackaging = true` in app/build.gradle.kts
3. ❌ **PageSizeMismatchDialog still appeared on Pixel 9a**

**Root Cause Discovered**:
- OpenCV is a **separate library module** with its own native libraries
- AGP 8.10.1 requires **explicit per-module packaging configuration**
- App-level `useLegacyPackaging=true` does **NOT propagate** to library modules
- OpenCV's `libopencv_java4.so` (4KB aligned) triggered the warning

---

## Implementation

### Change 1: opencv/build.gradle

**File**: `opencv/build.gradle`
**Lines Modified**: 138-158

**Before** (Lines 138-151):
```groovy
buildTypes {
    debug {
        packagingOptions {
            doNotStrip '**/*.so'  // controlled by OpenCV CMake scripts
        }
    }
    release {
        packagingOptions {
            doNotStrip '**/*.so'  // controlled by OpenCV CMake scripts
        }
        minifyEnabled false
        proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.txt'
    }
}
```

**After** (Lines 138-158):
```groovy
buildTypes {
    debug {
        // v2.9.6 Phase 2.3: Force legacy packaging for 4KB-aligned OpenCV libs
        packagingOptions {
            jniLibs {
                useLegacyPackaging = true
            }
            doNotStrip '**/*.so'  // controlled by OpenCV CMake scripts
        }
    }
    release {
        // v2.9.6 Phase 2.3: Force legacy packaging for 4KB-aligned OpenCV libs
        packagingOptions {
            jniLibs {
                useLegacyPackaging = true
            }
            doNotStrip '**/*.so'  // controlled by OpenCV CMake scripts
        }
        minifyEnabled false
        proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.txt'
    }
}
```

**What This Does**:
- Forces OpenCV module to use **legacy packaging** (extract libs to filesystem)
- Bypasses 16KB alignment requirement for OpenCV's 4KB-aligned `.so` files
- Applied to **both debug and release** buildTypes

## Why Phase 2.3 Will Succeed

### Packaging Decision Flow

```
Build Time:
├─ app module
│  └─ jniLibs { useLegacyPackaging = true }  (Phase 2.2)
│     → ML Kit, AndroidX libs: ✅ Extracted to /data/app/.../lib/
│
└─ opencv module (library)
   ├─ Phase 2.2: No jniLibs config
   │  → Default = modern packaging
   │  → libopencv_java4.so: ❌ Requires 16KB alignment → Dialog
   │
   └─ Phase 2.3: jniLibs { useLegacyPackaging = true }
      → Explicitly forces legacy packaging
      → libopencv_java4.so: ✅ Extracted to /data/app/.../lib/
      → No 16KB alignment required → No Dialog
```

### Comparison Matrix

| Configuration | Phase 2.1 | Phase 2.2 | Phase 2.3 |
|---------------|-----------|-----------|-----------|
| **App Module** | useLegacyPackaging=false | useLegacyPackaging=true | useLegacyPackaging=true |
| **App extractNativeLibs** | false (default) | true | true |
| **OpenCV Module** | No config | ❌ No config | ✅ useLegacyPackaging=true |
| **Result on Pixel 9a** | ❌ Dialog | ❌ Dialog | ✅ **Should Work** |

**Critical Difference**:
- Phase 2.3 is the **first** to explicitly configure OpenCV module's JNI libs packaging
- This ensures OpenCV's 4KB-aligned libraries are extracted, not mmap'd

## Trade-offs

### Benefits ✅

1. **Eliminates UX Issue**
   - No warning dialog on every app launch
   - Professional user experience

2. **Immediate Fix**
   - No waiting for OpenCV 5.x or ML Kit updates
   - Production-ready today

3. **Low Risk**
   - Only changes packaging method
   - No code logic changes
   - Preserves all functionality

### Costs ⚠️

1. **APK Install Size Increase**
   - **Estimate**: +10-15 MB
   - **Reason**: OpenCV libs extracted to filesystem instead of staying compressed in APK
   - **Impact**: Acceptable for modern devices (Pixel 9a has ample storage)

2. **Install Time Increase**
   - **Estimate**: +1-2 seconds
   - **Reason**: Native libs extraction during installation
   - **Impact**: One-time cost, negligible UX impact

3. **Not Ideal Long-Term**
   - **Better Solution**: Wait for upstream 16KB-aligned libraries
   - **Timeline**: OpenCV 5.x expected 2026 Q2-Q3
   - **Migration Path**: Remove workaround when upstream ready
