# v2.10.0_aspect_ratio_wysiwyg_fix | Level 2 Feasibility & Implementation Plan

## 1. Executive Summary (執行摘要)
We have analyzed the Level 1 plan and the current codebase. The proposal to use **UseCaseGroup + ViewPort** is the correct standard CameraX approach to solve the WYSIWYG and FOV issues.
*   **Feasibility**: High. `UseCaseGroup` is the supported API for consistent cropping across Preview/Capture.
*   **Risk**: Medium. Hardcoding "1920x1920" for 1:1 is risky (device support).
*   **Recommendation**: Adopt **Plan A (UseCaseGroup + ViewPort)** but with a **Flexible Resolution Strategy** for 1:1 (not strict 1920x1920), allowing fallback to 4:3 stream + ViewPort Crop.

## 2. Technical Solution Detail (技術方案詳解)

### A. Core Architecture: `UseCaseGroup` & `ViewPort`
Currently, `LiveCameraSource` binds use cases individually. We will refactor `bindToLifecycle` to use `UseCaseGroup`.

```kotlin
// Concept
val viewPort = ViewPort.Builder(aspectRatioMode.toRational(), rotation)
    .setScaleType(ViewPort.FIT) // KEY: FIT prevents "double crop" (zoom effect)
    .build()

val useCaseGroup = UseCaseGroup.Builder()
    .addUseCase(preview)
    .addUseCase(imageAnalysis)
    .addUseCase(imageCapture)
    .setViewPort(viewPort)
    .build()

cameraProvider.bindToLifecycle(lifecycleOwner, cameraSelector, useCaseGroup)
```

### B. 1:1 Mode Implementation (The "Square" Challenge)
Most sensors do NOT output native 1:1. They output 4:3.
*   **Strategy**: DO NOT force `1920x1920` as a strict rule.
*   **Implementation**:
    1.  **ResolutionSelector**: Ask for `RATIO_4_3` (closest to square sensor input).
    2.  **ViewPort**: Set to `Rational(1, 1)`.
    3.  **Result**: CameraX captures 4:3 image, but applies a 1:1 Crop Rect. `ImageCapture` output will be cropped to square (or carry metadata).
    *   *Refinement*: We can try to `setResolutionFilter` to prefer 1:1 sizes if available, but fallback to 4:3 is mandatory.

### C. 16:9 FOV Fix
*   **Problem**: Previous `FILL_CENTER` display on 16:9 preview caused "Zoom".
*   **Fix**:
    1.  `ViewPort` definition: `Rational(16, 9)`.
    2.  `PreviewView.ScaleType`: `FILL_CENTER` (matches view).
    3.  **Crucially**: Use `ViewPort.FIT` inside the *UseCaseGroup* construction to ensure the pipeline optimizes for fitting the rect, rather than cropping it early.

## 3. Risk Assessment & Mitigation (風險與緩解)

| Risk | Probability | Mitigation |
| :--- | :--- | :--- |
| **Strict 1920x1920 failure** | High | **Do not use strict resolution.** Use `ResolutionStrategy` asking for *closest to* 1920x1920, but compatible with 4:3 aspect. |
| **ViewPort ignored on legacy devices** | Low/Medium | Implement explicit "Software Crop" check in `ImageCapture.OnImageSavedCallback` if necessary (advanced), but standard ViewPort should suffice for modern CameraX. |
| **Performance (Crop overhead)** | Low | ViewPort crop is usually metadata-based or hardware scaler. Minimal impact. |
| **Preview/Capture Mismatch** | Low | `UseCaseGroup` guarantees shared crop rect. |

## 5. Conclusion (結論)
Proceed with **Plan A (Revised)**: Use `UseCaseGroup` + `ViewPort`, but rely on 4:3 sensor input for 1:1 crop rather than forcing a potentially unsupported square resolution. This minimizes compatibility risk while achieving WYSIWYG.
