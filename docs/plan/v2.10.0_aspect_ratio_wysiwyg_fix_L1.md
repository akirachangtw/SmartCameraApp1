# v2.10.0_aspect_ratio_wysiwyg_fix｜Level 1 規劃摘要

## 1. 目標（Goal）
- 修正 v2.10.0 長寬比功能的兩個關鍵問題，確保 **Preview 與 Capture 輸出一致（WYSIWYG）**，並使 **16:9 視角（FOV）不再過度裁切**，接近 OEM（Sony 內建相機）體感。
- 以 **最小差異** 方式調整 CameraX 綁定策略，降低回歸風險，並可清楚驗證與回滾。

---

## 2. 背景與問題（Why / What）
### (1) 1:1 模式 WYSIWYG 破壞
- **現象**：Preview 顯示正方形，但 Capture 輸出為 3:4（或 4:3）比例，造成使用者構圖與成像不一致。
- **已知原因**：`AspectRatioMode.toCameraXAspectRatio` 對 **1:1 無法映射**，目前 fallback 到 **4:3**，導致 Capture（或目標解析度選擇）走到非正方形管線。

### (2) 16:9 模式 FOV 過度裁切（比 Sony 內建相機窄 30–40%）
- **現象**：相同鏡頭下，我方 16:9 的視角明顯更窄（等效裁切更大）。
- **已知原因**：`ViewPort.Builder` 未設定 `ScaleType`，導致預設 `FILL_CENTER`，再疊加上游/下游的裁切策略（可視為「雙層裁切」），造成 FOV 額外縮窄。
- **方向**：指定 `ViewPort.setScaleType(ViewPort.FIT)`，避免 FILL_CENTER 額外裁切。

## 4. 風險清單（Risks）
### 相機管線風險
1. **ResolutionSelector 指定 1920×1920** 可能在部分裝置不支援該精確尺寸（或只支援接近尺寸），導致：
   - fallback 行為不可控（選到較小或非預期解析度）
   - bind 失敗或建立 use case 失敗
2. `ViewPort.FIT` 改動可能改變 Preview 的 letterbox 行為，UI 可能出現黑邊（屬預期但需產品接受）。

### 模式切換風險（Live / Static / Debug 等）
3. 長寬比切換時，use case 重新 bind 可能引發：
   - 瞬斷黑屏、閃爍時間變長
   - 先前 zoom / focus / metering 區域需要重設
4. 若同時存在 ImageAnalysis（AI 即時）：
   - analysis 的裁切/座標系映射（Preview ↔ Analysis ↔ Overlay）可能出現偏移，需要檢查 overlay 對齊。

### 效能回歸風險
5. 正方形 1920×1920 可能提高單幀像素量（相對某些 4:3 解析度選擇策略），造成：
   - CPU/GPU/記憶體壓力（特別是 YUV->RGB、AI model 前處理）
   - FPS 降低、發熱上升
6. `USE_PREVIEWVIEW_DISPLAY=true` 可能改變渲染路徑（Surface/Texture），需防止引入舊有 graphics memory 問題回歸（先前 v2.8.6 migration 相關）。

## 5. 建議方案（Plan A / Plan B：最小差異優先）
### Plan A（建議｜對準已知 root cause、最小且可驗證）
1. **1:1 WYSIWYG 修正**
   - 不再透過 `toCameraXAspectRatio` 逼近 1:1（因 CameraX AspectRatio 常見只支援 4:3/16:9）。
   - 改採 **ResolutionSelector + 固定正方形解析度**：
     - 例：`1920x1920` 作為目標（你方已提出）
     - 若支援性疑慮：允許 fallback（見 Plan B）
   - 目標：Preview 與 Capture 都以同一個正方形輸出/裁切策略工作，避免 Preview 正方形但 Capture 仍走 4:3。

2. **16:9 FOV 過度裁切修正**
   - `ViewPort.Builder` 明確設定：
     - `setScaleType(ViewPort.FIT)`
   - 目標：避免預設 `FILL_CENTER` 的額外裁切，讓 16:9 的 FOV 回到合理範圍（接近 OEM）。

3. **維持變更可控**
   - 優先只改 CameraX 綁定相關設定（ResolutionSelector / ViewPort ScaleType），避免同時大改 UI/手勢/overlay。

### Plan B（相容性/回歸保護版｜當 Plan A 在部分機型不穩）
1. **1:1 的解析度選擇改為「正方形優先」而非「固定單一尺寸」**
   - 使用 ResolutionSelector 的策略：優先挑選最接近 1:1 的支援解析度（或在支援列表中挑選最大正方形）。
   - 若無正方形輸出，則採「以 4:3 輸出 + 後段裁切到 1:1」並確保 Capture 與 Preview 使用一致裁切規則（WYSIWYG）。
2. 加入裝置能力偵測/記錄（log）：
   - 記錄實際選到的 resolution、crop rect、viewPort 設定，便於定位機型差異。
3. Feature flag（若需要快速止血）：
   - 保留可切回舊策略的開關（例如針對 1:1 resolution selector 或 ViewPort FIT）。

## 6. 驗證方式（How to verify：模擬器/實機/效能指標）
### 功能驗證（必做：實機）
1. **1:1 WYSIWYG**
   - 切到 1:1 模式，對準棋盤格/方框參考物構圖。
   - 拍照後比對：輸出圖片是否為 1:1，且內容邊界與 Preview 所見一致（允許 UI padding/黑邊但不得比例錯誤）。
   - 檢查 EXIF/實際像素：是否為預期（如 1920×1920 或替代正方形）。

2. **16:9 FOV**
   - 同一位置、同一焦段（1x）、同一解析度模式下：
     - 與 Sony 內建相機對比畫面可視範圍（目標：裁切差異顯著縮小，不再窄 30–40%）。
   - 檢查 Preview 是否出現預期的 FIT 行為（可能有 letterbox，但 FOV 不應再被額外裁切）。

3. **長寬比切換穩定性**
   - 4:3 ↔ 16:9 ↔ 1:1 連續切換 20 次：
     - 不應 bind 失敗、不應卡死
     - 黑屏時間可量測（主觀< 500ms 或依產品標準）

### 效能驗證（實機為主，模擬器僅輔助）
- 指標：
  - Preview FPS（或 pipeline latency）
  - CPU/GPU 使用率（Android Studio profiler）
  - 記憶體（特別是 graphics / native）
  - 溫度/掉幀（長時間 3–5 分鐘）
- 場景：
  - 開啟 AI 即時分析時（ImageAnalysis on）
  - 1:1（1920×1920）與 16:9 各跑一輪對比

### 日誌/可觀測性（建議）
- log 實際選用的：
  - Preview / ImageCapture / ImageAnalysis resolution
  - ViewPort scaleType
  - cropRect（若可取得）

## 7. 回滾策略（Rollback）

3. 若遇到特定機型不支援 1920×1920：
   - 先回退到 Plan B（正方形優先/後裁切）或暫時停用 1:1 入口。
