## 根本原因：水平引導邏輯倒反

### 問題位置
**檔案**: `app/src/main/java/local/mylab/smartcameraapp1/domain/usecase/AnalyzeCompositionUseCase.kt`
**函數**: `calculateGuideData()`
**問題行**: **810-814**

### 錯誤邏輯
```kotlin
// ❌ 當前錯誤邏輯
val targetCenterX = if (faceCenterX < imageWidth / 2f) {
    leftThird  // 臉部在左半邊，目標是左三分線 ❌ 錯誤！
} else {
    rightThird // 臉部在右半邊，目標是右三分線 ❌ 錯誤！
}
```

### 錯誤影響
| 人臉位置 | 錯誤引導目標 | 結果 | 正確應該是 |
|---------|-------------|------|-----------|
| 左半邊 | 左三分線 | 框框更靠左，遠離中心 ❌ | 右三分線，引導向中心 ✅ |
| 右半邊 | 右三分線 | 框框更靠右，可能在空白處 ❌ | 左三分線，引導向中心 ✅ |

### 為什麼會有這個錯誤？
攝影美學的核心原則：
- **偏離中心的人臉應引導回構圖平衡點**
- 人臉在左側 → 應該向右移動到右三分線
- 人臉在右側 → 應該向左移動到左三分線

當前邏輯是「強化偏離」而非「修正偏離」。

## 第二個問題：眼睛在框內但顏色仍為灰色

### 兩個問題的關聯性

**這兩個問題是同一根源的不同表現**：

1. **問題1（框框位置錯誤）**：
   - 水平邏輯倒反 → 框框出現在錯誤位置
   - 表現：人臉左側，框框卻在右邊/對面

2. **問題2（眼睛在框內仍是灰色）**：
   - 容差設定過嚴 → 即使視覺上「接近」，數值上仍「未達成」
   - 表現：眼睛看起來在框內，但進度仍 < 0.4（灰色）

**根本原因**：
- 引導框的**定位邏輯**錯誤（問題1）
- 引導框的**判定標準**過嚴（問題2）
- 兩者結合導致：框框在錯誤位置 + 永遠無法變綠

**用戶體驗影響**：
- 用戶看到框框在奇怪的位置（問題1）
- 即使努力對齊，框框仍不變綠（問題2）
- 完全無法達成「構圖良好」狀態

**修復後的協同效果**：
- 修正位置邏輯 → 框框出現在正確位置
- 放寬容差標準 → 框框能夠變綠色
- 兩者結合 → 用戶能看到正確的視覺引導並達成目標

### 問題確認
用戶回報：另外兩張截圖中，眼睛已經對焦在引導框內，但框框顏色仍是灰色（應該變綠色）

**影響截圖**：
- `前置鏡頭_20251213-112649.png` - 眼睛在灰框內，但顏色仍是灰色
- `後置鏡頭_20251213-112722.png` - 眼睛在灰框內，但顏色仍是灰色

### 問題分析（從logcat數據）

**前置鏡頭 11:26:49**：
```
eyeY: 223-226 px (眼睛實際位置)
upperThird: 801.67 px (上三分線目標)
offset: 575-578 px (偏差 - 超過容差3倍！)
tolerance: 192.4 px

vProgress = 0.0 ❌ (垂直進度為0)
hProgress = 0.36-0.39 (水平進度36-39%)
overall = 0.18 (整體進度18% < 0.4)
→ 顏色 = 灰色 (#9E9E9E)
```

### 根本原因

**視覺誤解 vs 實際判定**：

1. **用戶看到的**：眼睛在灰框內 → 應該算對齊
2. **程式判定的**：眼睛Y座標(223px) 距離上三分線(801px) 太遠 → 未對齊

**問題根源**：
- 引導框的**目標位置**是根據「理想上三分線位置」計算的
- 但用戶的**眼睛實際位置**遠低於上三分線（眼睛在畫面上方1/4處，應該在1/3處）
- 框框顯示在**應該移動到的位置**（目標），而非**眼睛當前位置**
- 因此看起來「眼睛在框內」，實際上是「眼睛距離目標框框太遠」

### 設計問題

當前的引導框設計有兩個可能的理解：

**理解A（當前實作）**：
- 框框 = 目標位置（人臉應該移動到這裡）
- 用戶需要移動人臉讓眼睛對準這個框框

**理解B（用戶期待）**：
- 框框 = 當前人臉位置的追蹤框
- 框框變綠色 = 當前位置已經構圖良好

**當前問題**：用戶誤以為是理解B，但實際是理解A

### 解決方案選項

#### 選項1：調整容差（快速修復）
放寬垂直容差，讓更多情況能達成「對齊」狀態：
- 當前：192.4px (8% × 2405px)
- 建議：350-400px (15-17%)

**優點**：快速實施
**缺點**：降低構圖標準

#### 選項2：改進UI設計（推薦）
明確區分「當前位置」和「目標位置」：
- 添加「當前臉部框」（實線綠框）
- 保留「目標引導框」（虛線灰/綠框）
- 讓用戶清楚看到應該如何移動

**優點**：清晰的視覺引導
**缺點**：需要UI重構

#### 選項3：改變框框計算邏輯
讓框框圍繞當前眼睛位置，而非目標位置：
- 框框中心 = 當前眼睛Y座標
- 顏色 = 根據距離目標的偏差

**優點**：符合用戶直覺
**缺點**：失去「引導到目標」的功能

### 建議方案（v2.4.6）

**優先實施選項1**（與水平邏輯修復一起）：
1. 調整垂直容差到 300-350px
2. 修改眼睛分數計算曲線（更寬鬆）
3. 降低眼睛位置權重（25% → 18%）

**未來考慮選項2**（v2.5.0）：
- 雙框設計：當前框 + 目標框
- 更清晰的視覺引導

## 視覺回饋機制（已正確運作）

### 引導框顏色變化
**檔案**: `CompositionGuideOverlay.kt` 第 75-80 行

引導框顏色根據對齊進度 (`alignmentProgress`) 變化：

| 進度範圍 | 顏色 | 色碼 | 意義 |
|---------|------|------|------|
| `isAligned = true` | **綠色** | `#4CAF50` | ✅ 完美對齊！ |
| `progress > 0.7` | **淡綠色** | `#81C784` | 接近完美 |
| `progress > 0.4` | **黃綠色** | `#AED581` | 越來越接近 |
| `else` | **灰色** | `#9E9E9E` | 需要調整 |

### 進度計算邏輯
**檔案**: `AnalyzeCompositionUseCase.kt` 第 841-851 行

```kotlin
// 水平和垂直進度的加權平均
val horizontalProgress = 1f - (abs(horizontalOffset) / horizontalTolerance).coerceIn(0f, 1f)
val verticalProgress = 1f - (abs(eyeOffsetY) / tolerance).coerceIn(0f, 1f)
val overallProgress = (horizontalProgress + verticalProgress) / 2f
```

### 對齊判定
當**垂直和水平都在容差內**時觸發完美對齊：
```kotlin
if (verticalAligned && horizontalAligned) {
    return null  // 觸發「構圖良好」
}
```

### 用戶觀察到的顏色變化流程
1. **灰色框** (progress < 0.4) → 距離目標較遠，需要大幅調整
2. **黃綠色框** (progress 0.4-0.7) → 正在接近目標位置
3. **淡綠色框** (progress > 0.7) → 非常接近完美構圖 ✅
4. **綠色框** (完全對齊) → 構圖完美，可以拍照！

**此機制已正確運作**，修復水平邏輯後，用戶將能正確看到框框從灰色→淡綠色的進度變化。
