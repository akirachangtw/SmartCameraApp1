## 🎯 設計決策記錄 (Design Decisions)

### 決策 1: 視覺風格方向
**選定**: **選項 B - 科幻風 + Glassmorphism** ✅

**色彩系統**:
- **Primary (主色)**: 極光藍 `#00F2FF` (Aurora Blue)
- **Tertiary (三次色)**: 電子紫 `#7000FF` (Electric Purple)
- **動態色彩**: 開啟高對比度選項 (Material 3 Dynamic Color)

**視覺語言**:
- Glassmorphism (玻璃擬態) - Opacity 20%-40%, Blur 16dp+
- Neural Ring (智能快門環) - 金黃色聚焦動畫
- Motion Shield (動態模糊警示) - 紅色半透明 Overlay
- Magnetic Composition (磁吸感構圖) - AR 引導線 + Snap-to-guide

**理由**:
- 符合 [ui_ux_design_proposals.md](./ui_ux_design_proposals.md) 的「未來感 AI 攝影師」定位
- 提供獨特視覺體驗,區別於標準相機 APP
- 與 Stitch with Google 設計工具整合良好

**權衡**:
- ⚠️ 需要實機 FPS 測試 (backdrop blur 耗 GPU)
- ⚠️ 實施複雜度高於 Material 3 標準風格
- ✅ 可透過 Feature Flag 分階段啟用,降低風險

---

### 決策 2: 實施時機
**選定**: **選項 A - v2.7.0 完成後 → v3.0.0 整合時** ✅

**時間軸**:
```
v2.7.0 (當前)           v2.8.0              v3.0.0              v3.1.0+
├─ OpenCV 整合      ├─ 核心功能       ├─ 基礎 UI/UX    ├─ 進階視覺
│  (Sprint 3+4)      │  穩定化          │  設計系統       │  增強評估
│                    │                 │  實施           │  (Glassmorphism)
└─────────────────┴─────────────────┴─────────────────┴──────────────→
                                        ↑ UI/UX 主要實施階段
```

**理由**:
- 先完成 OpenCV 引導線檢測核心功能 (v2.7.0 優先級最高)
- 避免 UI/UX 改動與相機管線開發衝突
- v3.0.0 時技術債務較少,可專注視覺優化

---

### 決策 3: Glassmorphism 評估時機
**選定**: **延後至 v3.1.0 或更後執行** ✅

**評估項目** (v3.1.0 前完成):
- [ ] 實機 FPS 測試 (backdrop blur 對 GPU 影響)
- [ ] 不同裝置效能驗證 (高/中/低階)
- [ ] Overlay 更新頻率優化 (目標 10Hz)
- [ ] 記憶體占用分析 (目標 < 300MB 高階 / < 200MB 中階)

**決策閘門**:
- ✅ 若 FPS 保持 > 30 FPS (中階) / > 60 FPS (高階) → 正式啟用
- ❌ 若 FPS < 20 FPS 或記憶體 > 400MB → 回退至簡化風格

---

### 決策 4: DirectionalIndicator 視覺設計
**選定**: **Option 1 - 目標圓圈 (Target Circle)** ✅

**設計規格**:
- 中心: 半透明圓形 (極光藍, alpha 0.3)
- 外環: 金黃色動畫環 (聚焦時啟用)
- 尺寸: 48dp (符合 Material 3 可點區域)

**理由**:
- 符合科幻風格 (Neural Ring 概念)
- 性能最優 (簡單幾何,無複雜 path)
- 符合 Material 3 簡潔原則

**備選**:
- Option 2 (箭頭指向): v4.0 進階功能時考慮
- Option 3 (磁力線效果): 效能開銷較高,延後評估

## 🚧 風險識別與緩解策略

### 高風險區域 (來自 L2 可行性分析)

#### 風險 1: CameraX Preview + Overlay 疊圖
**問題**: GPU overdraw, 座標映射錯誤 (6 層 Canvas 疊加)

**緩解措施**:
- ✅ 使用 Android Studio Layout Inspector 檢查 overdraw
- ✅ 座標轉換統一使用 [FrameToViewTransform.kt](../app/src/main/java/com/akirachang/ai/photographer/presentation/camera/components/overlay/FrameToViewTransform.kt)
- ✅ Overlay 更新限制為 **10Hz** (每 100ms) - 已在 [LiveCameraSource.kt:250](../app/src/main/java/com/akirachang/ai/photographer/data/source/camera/LiveCameraSource.kt) 實現
- ⚠️ Glassmorphism blur 需實機 FPS 測試

**驗證方式**:
```bash
# GPU overdraw 檢查
adb shell setprop debug.hwui.overdraw show
# FPS 監控
adb shell dumpsys gfxinfo com.akirachang.ai.photographer framestats
```

---

#### 風險 2: ImageAnalysis 與 UI Thread 邊界
**問題**: 高頻分析結果更新導致 Compose recomposition 掉幀

**緩解措施**:
- ✅ 維持現有 Flow-based 機制 ([CameraViewModel.kt](../app/src/main/java/com/akirachang/ai/photographer/presentation/camera/CameraViewModel.kt))
- ✅ 使用 `distinctUntilChanged()` 避免重複更新
- ✅ StateFlow 只在數值變化 > 閾值時更新

**實施範例**:
```kotlin
// CameraViewModel.kt (建議增強)
val compositionSuggestion = analysisResults
    .map { it.compositionScore }
    .distinctUntilChanged { old, new -> abs(old - new) < 0.05 } // 5% 變化才更新
    .stateIn(viewModelScope, SharingStarted.Lazily, null)
```

---

#### 風險 3: 模式切換 (Live / Static) UI State 不一致
**問題**: 切換時控制項狀態殘留、黑屏、CameraControl not available

**緩解措施**:
- ✅ UI state 在 ViewModel 中集中管理 (已實現)
- ✅ 切換時加入 `loading` state (避免誤觸)
- ✅ 測試用例: 連續切換 20 次不 crash

**測試腳本** (建議新增):
```kotlin
// CameraViewModelTest.kt
@Test
fun `switch Live-Static 20 times should not crash`() {
    repeat(20) {
        viewModel.switchToLive()
        delay(500)
        viewModel.switchToStatic()
        delay(500)
    }
    assertThat(viewModel.uiState.value).isNotInstanceOf(Error::class.java)
}
```

---

#### 風險 4: 權限流程與錯誤狀態 UX
**問題**: 權限拒絕、僅允許一次、背景回前景等狀態未完整覆蓋

**緩解措施** (v3.0 實施):
- [ ] 建立完整權限狀態機:
  ```kotlin
  sealed class PermissionState {
      object Granted : PermissionState()
      object Denied : PermissionState()
      object PermanentlyDenied : PermissionState()
      object OnceOnly : PermissionState()
  }
  ```
- [ ] 每個狀態對應明確 UI 引導
- [ ] 測試場景: 所有排列組合

---

#### 風險 5: Thread / Coroutine Scope 管理
**問題**: ViewModel / StateFlow 與 camera pipeline scope 混用造成 leak

**緩解措施**:
- ✅ 統一使用 `viewModelScope` (ViewModel 層)
- ✅ Camera pipeline 使用 `ProcessLifecycleOwner` scope
- ⚠️ 需驗證無 leak (LeakCanary)

**驗證**:
```gradle
// app/build.gradle.kts
debugImplementation("com.squareup.leakcanary:leakcanary-android:2.12")
```

---

#### 風險 6: 裝置差異 (長寬比 / Notch / 旋轉)
**問題**: 不同螢幕比例、瀏海、挖孔、安全區處理不一致

**緩解措施** (v3.0 實施):
- [ ] 使用 `WindowInsets` 正確處理 safe area
- [ ] 測試裝置:
  - 18:9 (Pixel 5)
  - 20:9 (Samsung S21)
  - 21:9 (Sony Xperia)
  - Foldable (Galaxy Fold)
- [ ] 旋轉測試: Portrait / Landscape / Reverse

## 🔄 回滾策略 (Rollback Strategy)

### Feature Flag 分層啟用

**v3.0.0 階段回滾層級**:
```kotlin
// Level 1: Theme/色彩 (最低風險)
enableNeuralLensColors = false  // 回退至 Material Green

// Level 2: DirectionalIndicator (中風險)
enableDirectionalIndicator = false  // 移除方向指示器

// Level 3: 控制列元件 (中風險)
// 手動回退相關 Composable

// 回滾順序: Level 3 → Level 2 → Level 1
```

**v3.1.0 階段回滾層級**:
```kotlin
// Level 4: Glassmorphism (高風險)
enableGlassmorphism = false

// Level 5: Neural Ring (高風險)
enableNeuralRing = false

// Level 6: Motion Shield (中風險)
enableMotionShield = false

// 總開關 (一鍵回退所有進階視覺)
enableAdvancedUiUx = false
```

### 回滾標準

**立即回滾** (關閉對應 Feature Flag):
- ❌ 黑屏 (相機預覽無畫面)
- ❌ 相機無法恢復 (CameraControl not available 持續)
- ❌ FPS 明顯下降 (< 20 FPS 中階 / < 40 FPS 高階)
- ❌ 實機專屬 bug (模擬器正常但實機 crash)
- ❌ 記憶體 leak (10 分鐘增長 > 50%)

**延後評估** (記錄 issue,下版本修復):
- ⚠️ 特定裝置相容性問題 (< 5% 裝置)
- ⚠️ 邊緣情境 bug (非主流使用場景)
- ⚠️ 視覺瑕疵 (不影響功能)

**允許範圍** (可接受):
- ✅ FPS 輕微下降 (28-30 FPS 中階)
- ✅ 記憶體增加 < 20%
- ✅ UI 動畫偶爾卡頓 (< 5% 時間)

### 回滾流程

1. **檢測異常** (自動或手動)
   ```kotlin
   // 自動 FPS 監控 (建議新增)
   if (currentFps < 20 && deviceTier == Mid) {
       Log.e("UiUx", "FPS below threshold, disabling advanced features")
       featureFlags.enableAdvancedUiUx = false
   }
   ```

2. **關閉 Feature Flag**
   ```kotlin
   // 開發環境: 即時調整
   adb shell setprop debug.smartcamera.enableGlassmorphism false

   // 正式環境: 遠端配置 (Firebase Remote Config)
   ```

3. **驗證回滾效果**
   - 重新測試 FPS / 記憶體
   - 確認功能正常 (V2.0 核心 Overlay 仍可用)

4. **記錄 Issue**
   ```markdown
   ## Issue: Glassmorphism 導致中階裝置 FPS < 20
   - 裝置: Pixel 7a
   - 場景: 複雜街景 + 6 層 Overlay
   - 回滾: enableGlassmorphism = false
   - 後續: v3.2.0 優化 blur 演算法
   ```
