## Sonnet 4.6 的 Effort 等級解析

Claude Code 中 Sonnet 有一個 `--effort` 參數（或等效的思考深度控制），影響模型在回答前的內部推理投入量。概念上分三級：

| Effort 等級 | 內部推理量 | Token 消耗 | 回應速度 | 適合什麼 |
|-------------|-----------|-----------|---------|---------|
| **Low** | 極少推理，直覺回答 | 最低 | 最快 | 簡單明確的執行指令 |
| **Medium (預設)** | 適度推理 | 中等 | 中等 | 大多數程式碼任務 |
| **High** | 深度推理，多步驟內部推演 | 最高 | 最慢 | 複雜邏輯、架構級重構 |

## 程式實作角色的最佳 Effort 配置

程式實作不是一種工作——它是一連串不同複雜度的子任務。每個子任務的最佳 effort 不同：

| 子任務 | Effort | 理由 |
|--------|--------|------|
| 新增一個 data class | **Low** | 純結構定義，沒有邏輯。照規格打字就好。 |
| 實作一個純函數（如評分公式） | **Medium** | 有數學邏輯但邊界明確，Medium 足夠。 |
| 寫 Compose UI 元件 | **Medium** | Canvas 繪圖邏輯需要座標計算，但不涉及架構決策。 |
| 整合多模組（如 IMU + ML Kit + 規則引擎串接） | **High** | 涉及生命週期、執行緒切換、錯誤處理的交叉考量。想不清楚就寫，改三次更貴。 |
| 修一個編譯錯誤 | **Low** | 錯誤訊息已經告訴你問題在哪，直接修。 |
| 修一個邏輯 Bug（如評分公式結果不如預期） | **High** | 需要追蹤數據流、理解多規則互動、推演邊界條件。 |
| 重構 / 拆分 God Object | **High** | 需要理解全局依賴關係，決定新邊界在哪裡。 |
| 加一個新的 Rule（如 GazeRule） | **Medium** | 模式已建立（RuleResult 介面），只需填入新邏輯。 |

**最精確的模型**：不是「程式實作永遠用 Medium」，而是按子任務動態切換。
