定位校正(精準性)
「0.10→0.18」不是對焦成功透明度 —— Focus Ring focused 是 rgba(80,200,100,0.6)、locked 是 amber 1.0,均無此問題。0.10→0.18 是 Traction 對齊呼吸帶(breathe-halo-aligned L281 / breathe-ambient L299),D-3 鎖定、R-T4 於 0630 剛確認。故本審查的修正建議構成 D-3/R-T4 翻案,須 CSO 裁決,附翻盤條件。

🔴 U-1|對齊呼吸 0.10→0.18 低於實景可辨識閾值 核心 · D-3 翻案

視覺物理學論證:原型在黑底 demo 檢視(對比極高,0.10 也可辨);實機取景器是動態中亮度背景(實景平均 40–60% 亮度、持續運動),疊加層偵測閾值比靜態暗背景高 2–3×。綠 #50C864 在 alpha 0.10–0.18 下對實景 Weber 對比僅約 5–12%,戶外強環境光(面板有效對比被壓縮)下落在辨識閾值之下。

殺手證據:專案自己的實機閉環
R-T2 把未對齊 alpha 從 0.25 拉到 0.8 的理由,就是 0.25 在實機「淡到看不見/壞掉」(GAP-06 因果鏈)。對齊呼吸峰值 0.18 比那個已被判死的 0.25 還低 28%。同一塊螢幕、同一顆眼球,不可能 0.25 隱形而 0.18 可見。0.10→0.18 必然重演同型失效,只是換到對齊態。

辯證平衡:Ambient 哲學的「對齊後退場」意圖正確,且全域確認由快門呼吸(0.6→1.0 + 綠影)承擔 —— 但「安靜」≠「不可見」。使用者在對齊瞬間需要通道級的低調確認,否則會誤以為引導失效而繼續調整(IFTR 直接受損)。

/* 建議修正(FULL 裝置)— 保留呼吸韻律與 scale,抬升 alpha 包絡 */ - @keyframes breathe-halo-aligned { 0% { opacity: 0.10; ... scale(0.98); } 100% { opacity: 0.18; ... scale(1.02); } } + @keyframes breathe-halo-aligned { 0% { opacity: 0.25; ... scale(0.98); } 100% { opacity: 0.40; ... scale(1.02); } } - @keyframes breathe-ambient { 0%, 100% { opacity: 0.10; } 50% { opacity: 0.18; } } + @keyframes breathe-ambient { 0%, 100% { opacity: 0.25; } 50% { opacity: 0.40; } }

0.25 谷值 = R-T2 判死線的下緣(呼吸態可短暫觸底,不可常駐);0.40 峰值 ≈ 未對齊 0.8 的一半,維持「對齊比未對齊安靜一級」的層級語彙。翻盤條件:夜景/室內暗場 A/B 若 0.40 過亮干擾,降至 0.22→0.35;scene-adaptive alpha 屬 Phase 1.5,MVP 不做(TTV:改值數小時 vs 自適應 3–5 天)。

🔴 U-2|Pitch 對齊態雙重衰減 — 有效 alpha 僅 0.04–0.11 比 Halo 低 2.5×

Pitch 的對齊色自帶 rgba alpha,又被 breathe-ambient 的 element opacity(0.10–0.18)再打折:

Halo 對齊環(border 全 alpha × 呼吸)
有效 0.10–0.18
Pitch 對齊 ring(rgba 0.6 × 呼吸)
有效 0.06–0.108
Pitch 對齊 line(rgba 0.4 × 呼吸)
有效 0.04–0.072
Pitch 對齊 dot(rgba 0.4 × 呼吸)
有效 0.04–0.072
/* 修正原則:對齊色一律全 alpha,alpha 包絡由呼吸 keyframe 單獨承載 */ - .pitch-traction.aligned .pitch-traction-line { background-color: rgba(80, 200, 100, 0.4); animation: breathe-ambient ...; } + .pitch-traction.aligned .pitch-traction-line { background-color: var(--align-green); animation: breathe-ambient ...; } （ring 的 0.6、dot 的 0.4 同理改 var(--align-green)）

🟠 A-1|alpha 組合語義無主 — 歧義根源 SSOT 缺條款

SSOT D-3 寫「0.10→0.18」時從未定義:這是總感知 alpha(色彩 alpha × 元素 opacity 的乘積上限)還是元素 opacity(可再被色彩 alpha 打折)?Halo 選了前者的實作形態(border 全 alpha)、Pitch 選了後者(rgba 疊乘)——U-2 的雙重衰減正是這條歧義孵出來的。另 breathe-ambient 與 breathe-halo-aligned 兩組 keyframe 值相同僅差 scale,屬可合併的重複來源。修正:SSOT §2.0 增列一句裁定 ——「所有呼吸/漸變 alpha 均指總感知值;承載動畫的元素,其色彩一律全 alpha」。

🟠 A-2|對齊態圓點語義分裂 違反 R-T6 圓點統一基元

通道對齊態圓點表現有效 alpha
Halo歸心 + 0.85 強存在(JS L941)+ breathe-dot~0.6–0.85
Pitch歸位但 rgba 0.4 × 呼吸 0.10–0.18 → 近隱形~0.04–0.07

R-T6 剛裁定「圓點是三通道統一視覺基元」,對齊態卻兩套語彙:Halo 的圓點以強存在確認「已歸心」,Pitch 的圓點直接消失。使用者學到的隱喻(「圓點歸位=成功」)在 Pitch 上失效。修正:統一採 Halo 式 —— 圓點對齊後保持可見歸心(0.85 級),退場呼吸只作用於環/線。此與 U-2 修正天然合併。

🟠 U-3|V 曲線谷底 0.1 過深 — 「圓點失蹤帶」決策邊界回饋消失

三條 V 曲線都在 dist=50(琥珀↔綠交越點)把圓點 opacity 壓到 0.1。交越淡出的意圖正確(避免色彩硬跳),但代價是 dist 37–63 區間 opacity <0.3 —— 引導在使用者修正到一半、最需要回饋的瞬間近乎消失。實景上這是一段圓點失蹤帶。

- opacity = 0.1 + (漸變項) × 增益 /* 谷底 0.1 */ + opacity = 0.35 + (漸變項) × 增益 /* 谷底 0.35:交越淡出感保留,失蹤帶消除 */

翻盤條件:若實機色彩切換顯突兀,谷底最低容許回調至 0.25(不回 0.1)。
